How this guide is organised

This guide covers website design from foundations to advanced practice. Each chapter follows the same rhythm: a topic description, prose explanation, two code samples, and a callout flagging the most common mistake.

Structure of every section

Every h3 section is self-contained: an intro, prose walkthrough, two CSS examples, and a callout. Chapters 1–3 cover foundations: hierarchy, contrast, and the design process. Chapters 4–7 are the hands-on toolkit: information architecture, grids, typography, and colour. The remaining chapters cover imagery, responsive, interaction, accessibility, design systems, prototyping, performance, and handoff.

The mindset: form serves function

Good design is invisible. It lets the user accomplish their goal without noticing the interface. Every visual choice should support that goal.

Principles over trends

Trends change. Principles do not. A design that follows enduring principles — clear hierarchy, sufficient contrast, consistent spacing — ages well. One that chases the latest font gradient becomes dated in months. This guide teaches the principles; the trends will follow.

A typical design workflow

Research → define → ideate → prototype → test → refine. Every chapter in this guide maps to one step in that loop. If you are starting a new site, read the chapters in order. If you are fixing a specific problem, jump to the chapter that covers that step.

Tools you will use throughout

You can design a professional website with free tools. Figma has a free tier. Penpot is open-source and free. GIMP is a free image editor. Even a basic text editor handles layout with CSS Grid or Flexbox.

A free design stack

Figma (free) or Penpot for wireframes and UI. A colour contrast checker like WebAIM Contrast Checker. Google Fonts for typography. Unsplash for stock images. A browser with DevTools for live inspection. All free, all sufficient for most projects.Pair the tool with the section it supports: wireframes in Figma, colours with the checker, typography from Google Fonts, images from Unsplash, and live CSS in the browser.

Export assets in your final format — SVG for icons, WebP for photos, CSS or JSON for tokens. Never ship a raw Figma file or a PSD in the browser.

1.1 Visual hierarchy & Gestalt

Visual hierarchy is the order in which a reader notices elements. Gestalt principles explain why the brain groups some elements together and treats others as separate.

Proximity and similarity

Elements that are close together are seen as related. Elements that share shape, size, or colour are seen as a group. Use generous whitespace between unrelated sections, and consistent spacing inside sections.

/* Good hierarchy with grouped elements */
.card {
  padding: 16px;
  border: 1px solid var(--border);
  border-radius: var(--radius);
  margin-bottom: 24px; /* space between unrelated cards */
}
.card .title {
  font-size: 18px;
  font-weight: 700;
  margin-bottom: 8px; /* space between related title and body */
}

1.2 Contrast, alignment & scale

Contrast makes the important things stand out. Alignment creates order. Scale makes some elements larger or smaller to show relative importance.

WCAG contrast requirements

/* Accessible contrast: 4.5:1 for body text */
body {
  color: #212529;      /* dark text */
  background: #ffffff; /* light background */
}

/* Too low: white text on light grey */
.bad {
  color: #cccccc;
  background: #ffffff;
}

1.3 The four principles of design

The four principles are contrast, repetition, alignment, and proximity (CRAP). Every good layout applies all four.

A CRAP layout

/* Repetition: same card style everywhere */
.card {
  border-radius: var(--radius);
  padding: 16px;
  background: var(--panel);
}

/* Alignment: everything lines up to a left edge */
.card {
  text-align: left;
  margin-left: 0;
}

/* Proximity: related items are close together */
.card .meta {
  margin-top: 8px;
}

/* Contrast: the title stands out from the body */
.card .title {
  font-weight: 700;
  color: var(--text);
}

2.1 Research, personas & journeys

User research is the cheapest way to avoid building the wrong thing. Talk to five people in your target audience before you design.

A simple persona

Name: Sam K.
Age: 34
Job: Freelance designer
Goal: Find a quiet café with reliable wifi to work from.
Pain: Most listings lack wifi speed or seat availability.

# How this informs design:
# - Show wifi speed prominently on listing pages
# - Add a "seat availability" filter
# - Include quiet hours in the summary

2.2 Wireframes & low-fi

A wireframe is a low-fidelity sketch of a page. It defines structure, not colour or typography. Wireframes are cheap to change; high-fidelity mockups are expensive.

A basic wireframe in HTML/CSS

<section class="hero">
  <h1>Find Your Quiet Café</h1>
  <input type="search" placeholder="Search by neighbourhood...">
  <button>Search</button>
</section>
<section class="cards">
  <div class="card">...</div>
  <div class="card">...</div>
</section>

2.3 Jobs-to-be-done frameworks

Jobs-to-be-done says that people "hire" products to accomplish a job. Your site should make the hire obvious and the job easy to finish.

Mapping jobs to pages

# Job: "I need to find a quiet café to work from this afternoon."
#
# The page that serves this job must:
# 1. Be searchable by location or neighbourhood
# 2. Show wifi speed, power outlets, and noise level
# 3. Offer a map view with filters
# 4. Load fast on a mobile device
# 5. Have a clear call to action: "Book a seat"
