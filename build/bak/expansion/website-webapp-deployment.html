How this guide is organised

Deployment is the final step that turns code into a live website or web app. This guide covers static hosting, server hosting, CDNs, HTTPS, and CI/CD.

Structure of every section

Each h3 section is a self-contained unit with an intro, prose, two examples, and a callout. Chapters 1–2 cover build and packaging. Chapters 3–6 cover hosting, CDN, CI/CD, and monitoring. The remaining chapters go deep on rollbacks, scaling, and disaster recovery.

The mindset: deploy early, deploy often

Deploying to production on the last day is risky. Deploy frequently, even with small changes. A working site on a subdomain beats a polished draft on localhost.

Tools you will use throughout

GitHub Actions, Netlify, Vercel, Docker, and a DNS provider. All free for personal projects. No paid service is required for any chapter.

1.1 Build scripts & output

A build script turns source into a deployable artifact. For static sites, it copies files to a dist folder. For dynamic apps, it bundles JS, compiles CSS, and may prerender HTML.

{
  "scripts": {
    "build": "vite build",
    "preview": "vite preview"
  }
}

1.2 Docker & static assets

Docker wraps your app in a container with a fixed Node version, OS, and file structure. It guarantees the same result on your laptop and in production.

FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
CMD ["npm", "run", "preview"]

1.3 Environment config

Never hardcode API keys or database URLs. Use environment variables: a.env file locally, injected secrets in production.

2.1 Static vs server hosting

Static hosting serves pre-built files directly. Server hosting runs your app code on every request. Choose static for speed and cost; choose server for dynamic data.

2.2 CDNs, caching & HTTPS

A CDN caches your assets at edge locations worldwide. HTTPS encrypts traffic and is required for HTTP/2. Always force HTTPS in production.

2.3 CI/CD pipeline

A CI pipeline runs tests, builds artifacts, and deploys when the main branch changes. GitHub Actions is the simplest option.
