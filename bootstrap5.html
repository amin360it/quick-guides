Welcome — How to Use This Bootstrap 5 Guide

This opening chapter explains how to work through the guide, from the starter template to custom Sass builds, entirely offline. Read the chapters in sequence, typing out every snippet by hand to build real muscle memory. Each chapter builds on the previous one, so resist skipping around until you have finished the grid chapters.

This is a complete, self-paced path through Bootstrap 5.3, the most popular CSS framework on the web. Everything runs from static HTML files — no internet connection and no build step required until the customization chapter — and every snippet is copy-ready.

This section maps the four-part structure of the guide across eleven chapters and exercises, showing how each part moves from layout to components to behaviour. Everything builds upward from the grid, exactly like real projects do. Use it to see where you are in the overall journey and what each chapter expects you to know already.

The right mindset

The right mindset - Bootstrap philosophy

This section introduces Bootstrap’s philosophy of utility-first layout sitting on top of a finished component system. Think of the two layers separately: utility classes such as d-flex and p-3 shape layout, while components like cards and navbars supply complete ready-made widgets. Master the two layers and every page composes itself from existing building blocks.

Bootstrap is really two systems in one. The utilities (spacing, display, flex) lay out and fine-tune a page; the components (cards, navbars, alerts) drop in finished, accessible widgets. Roughly: build the skeleton with utilities, then slot components into it. Nearly every "how do I…" question maps onto one of those two layers.

Keep getbootstrap.com/docs/5.3 open beside this guide. Here you learn the why and the order; the official docs are the exhaustive reference for every class name.

1 · Getting Started

1.1 What Bootstrap 5 changed1.2 Installing via CDN or npm1.3 The starter template1.4 The JS bundle and icons

This chapter gets Bootstrap 5 into a project through either the CDN or npm and explains what version 5 changed from its predecessor. You will build the canonical starter template that every Bootstrap page descends from and meet the JavaScript bundle that powers its interactive components. Both installation routes are covered so you can pick the right one for practice or production.

Bootstrap 5 dropped jQuery, adopted CSS variables and RTL support, and made the grid more flexible than ever. This chapter gets a working page up within two minutes and lays the foundation every later chapter builds on.

1.1 What Bootstrap 5 changed

1.1.1 Migration from BS4

This section summarises the headline changes in version 5, from dropping jQuery to adopting CSS variables throughout. Knowing these changes explains most of the differences you will meet in older tutorials. It gives you the mental model needed to read Bootstrap 5 code and to adapt advice written for earlier versions.

  • No jQuery — the JavaScript is plain ES modules; the bundle works with any framework or none.
  • CSS custom properties — every component exposes design tokens you can override in plain CSS.
  • RTL support — flip the whole framework with one attribute (dir="rtl").
  • Custom color modes — dark mode ships as a first-class feature in 5.3.
  • Utilities API — generate your own utility classes in Sass.
  • No support for Internet Explorer; modern browsers only.

1.2 Installing via CDN or npm

1.2.1 Package Manager Installation

This section shows the two installation routes: the CDN for instant use and npm for compiled styling. The CDN involves pasting the bootstrap css link and the bundle script tag into your page head. The npm route adds bootstrap as a dependency so you can version it and later customize it during compilation.

<!-- Quick start: these two tags are all a prototype needs -->
<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>

# Or install into a project with npm, then import the source in your own Sass
npm install bootstrap@5.3.3
@import "bootstrap/scss/bootstrap";

The two CDN tags drop Bootstrap’s CSS and JavaScript into any page instantly, while npm install fetches the source files so you can customize and compile them yourself.

With npm you typically let a bundler (Vite or webpack) resolve the stylesheet for you; the CDN remains the fastest way to experiment or prototype.

1.3 The starter template

1.3.1 Basic Template Structure

This section builds the canonical starter template every Bootstrap page descends from. The viewport meta tag makes responsive design work on mobile, and the lang attribute plus proper doctype keep accessibility and validation correct. Copy this skeleton and it becomes the base of every page you write.

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Hello, world!</title>
    <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">
  </head>
  <body>
    <h1>Hello, world!</h1>
    <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>
  </body>
</html>

This is the minimum Bootstrapped page: the stylesheet in the head, the bundle script just before the closing body tag, and the viewport meta that enables responsive scaling on phones.

Keep that width=device-width, initial-scale=1 viewport meta in every page. Without it the breakpoints still trigger but phones render the page zoomed out.

1.4 The JS bundle and icons

1.4.1 Icon Fonts and JS

This section explains the two JavaScript files shipped with Bootstrap and how to add the icon set. The full bundle includes every plugin, while the separate file is for pages that need only toasts and popovers. Icons come from the separate bootstrap-icons library added as a stylesheet link.

<!-- Bundle: every plugin plus Popper, one file, no extra dependencies -->
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>

<!-- Or the slim split: only tooltips and popovers depend on Popper -->
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.min.js"></script>

<!-- Icons: an optional SVG font by the Bootstrap team -->
<link href="https://cdn.jsdelivr.net/npm/bootstrap-icons@1.11.3/font/bootstrap-icons.min.css" rel="stylesheet">
<i class="bi bi-github"></i>

The bundle ships every plugin plus Popper for positioning, the slim file drops Popper, and the icons stylesheet turns a simple i tag into an SVG icon.

2 · The Grid System

2.1 Containers, rows and columns2.2 The 12-column model and breakpoints2.3 Responsive column classes and auto-layout2.4 Gutters, offsets and ordering2.5 Nesting

This chapter covers the flexbox grid made of containers, rows, columns, breakpoints and auto-layout classes. You place a container, put a row inside it, and fill the row with column classes such as col-md-6. The grid is the backbone of every Bootstrap layout you will ever build, so it deserves careful study.

Bootstrap’s grid is a mobile-first, flexbox-based system of containers > rows > columns. Learn the three layers, the twelve-column model and the breakpoint prefixes, and you can describe any layout on the web in a handful of classes.

2.1 Containers, rows and columns

2.1.1 Containers Detail

This section introduces the three layers of the grid: the container, the row and the column. Every column must sit inside a row, and every row inside a container, so the hierarchy is strict. The container class also centers content and applies horizontal padding, giving the whole layout its width behaviour.

<div class="container">                <!-- centers content, max-width per breakpoint -->
  <div class="row">
    <div class="col">Half width</div>     <!-- two cols share the row 50/50 -->
    <div class="col">Half width</div>
  </div>
</div>

The container sets the page width, the row creates a flex line, and bare col columns divide the available space equally among themselves.

.container is the fixed-width wrapper that centers content: full width until each breakpoint, then a fixed max width. .row is a flex container whose direct children — the columns — are the flex items.

2.2 The 12-column model and breakpoints

2.2.1 Breakpoints Detail

This section explains the twelve-column model and the five breakpoint prefixes from sm to xxl. Each column class carries a number that says how many of the twelve slots it spans, so col-4 takes one third of the row. Combining prefix and number lets the same class behave differently at different screen widths.

<div class="row">
  <div class="col-4">span 4</div>     <!-- 4 of the 12 slots -->
  <div class="col-4">span 4</div>
  <div class="col-4">span 4</div>
  <div class="col-8">8 of 12</div>    <!-- fills the row with the 4 below -->
  <div class="col-4">4 of 12</div>
</div>

Numbered columns always take exactly that many of the twelve slots, so three col-4 columns fill one row and col-8 plus col-4 fill the next.

Twelve is just the default — and it divides nicely into 2, 3, 4 and 6 equal columns. Change the total in Sass if your design needs a different rhythm.

2.3 Responsive column classes and auto-layout

2.3.1 Responsive Classes

This section shows how breakpoint suffixes change column spans at each viewport width. A class like col-md-6 means half width from the md breakpoint up, while un-prefixed col utilities give equal-width auto layout. These prefixed classes are the heart of responsive layout in Bootstrap.

<div class="row">
  <div class="col-sm-6 col-lg-3">half on small, quarter on large</div>
  <div class="col-sm-6 col-lg-3">same</div>
  <div class="col-sm-6 col-lg-3">two per row on tablets</div>
  <div class="col-sm-6 col-lg-3">four across on desktops</div>
</div>

<!-- equally many columns: drop the numbers entirely -->
<div class="row">
  <div class="col-md">auto, equal width</div>
  <div class="col-md">auto, equal width</div>
  <div class="col-md">auto, equal width</div>
</div>

Breakpoint suffixes apply rules from that width upward, so col-sm-6 col-lg-3 means half-width from small and quarter-width from large; the bare col-md classes share equally.

The auto-layout classes let ratios and flexible leftovers coexist: combine col-8 with a bare col and the latter absorbs the space the former leaves free.

2.4 Gutters, offsets and ordering

2.4.1 Gutters and Offsets

This section covers the spacing between columns, column offsets and the order utilities. Gutter classes such as g-3 control the padding between columns, offset classes like offset-md-3 shift a column right, and order classes reflow columns on small screens. These refine the grid without resorting to margin hacks.

<div class="row g-4">                       <!-- gutter: 1.5rem between columns -->
  <div class="col-md-5 offset-md-1">left, pushed in one slot</div>
  <div class="col-md-5 offset-md-1">right, pushed in one slot</div>
  <div class="col order-last">shown last, first in markup</div>
  <div class="col">middle in markup and view</div>
  <div class="col order-first">shown first, last in markup</div>
</div>

The g-4 class pads the gutters between columns, offsets push a column right by whole slots, and order classes reorder columns visually without touching the source.

order-* reorders visually only. Keyboard and screen-reader order still follow the source markup, so keep meaningful content in a sensible order in the HTML.

2.5 Nesting

2.5.1 Nesting Details

This section shows how columns can host their own inner row to create sub-layouts. Inside a column you add a new row div whose children follow the same twelve-slot rhythm. Nesting keeps sub-layouts aligned to the grid and is the standard way to build complex, multi-level sections.

<div class="row">
  <div class="col-md-6">
    <div class="row">                    <!-- nested grid inside the column -->
      <div class="col-6">sub-half</div>
      <div class="col-6">sub-half</div>
    </div>
  </div>
  <div class="col-md-6">right column</div>
</div>

A row placed directly inside a column recreates the full twelve-slot grid within that column’s space, keeping all nested content on the same rhythm.

3 · Layout & Breakpoints

3.1 Fluid and fixed containers3.2 Display utilities3.3 Flex utilities3.4 The spacing scale3.5 Breakpoints in Sass mixins

This chapter goes beyond the grid to the wider layout system: containers, display, flex, spacing and breakpoints. You combine the d-* visibility classes, flex utilities and the spacing scale to shape how content behaves at every screen size. These utilities finish the layout layer that the grid begins.

The grid gives you structure; the layout utilities give you control. Containers, display and flex classes are how you create the arrangement, alignment and breathing room that make a page feel designed.

3.1 Fluid and fixed containers

3.1.1 Container Types

This section compares the fixed container class with the fluid container and the per-breakpoint variants. Container sets a centered, max-width wrapper that changes width at each breakpoint, while container-fluid spans the full viewport width. Choosing the right wrapper sets the whole page’s width behaviour.

<div class="container"> ... </div>       <!-- centered, max-width changes per breakpoint -->
<div class="container-fluid"> ... </div>    <!-- always 100% of the parent width -->
<div class="container-md"> ... </div>       <!-- fluid below md, fixed from md up -->

container centers a fixed-width block that steps up at each breakpoint, container-fluid always fills the width, and container-md behaves fluid below md and fixed from md onward.

/* The five container widths, from the Sass variables — override and rebuild */
$container-max-widths: (
  sm: 540px,
  md: 720px,
  lg: 960px,
  xl: 1140px,
  xxl: 1320px
);

These Sass values are the exact widths each container locks onto at its breakpoint; overriding them and recompiling changes the rhythm of every fixed container.

3.2 Display utilities

3.2.1 Hidden Utilities

This section shows how the d-* classes control visibility and layout mode per breakpoint. Classes like d-none and d-md-block can hide or show elements at different viewport widths. They replace conditional markup for show-and-hide needs, keeping responsive behaviour in CSS rather than in duplicated HTML.

<div class="d-none d-md-block">    <!-- hidden on phones, block from md up -->
  This copy appears from the md breakpoint.
</div>
<span class="d-inline-flex align-items-center">inline, laid out with flex</span>
<div class="d-grid gap-2">          <!-- display: grid with a 0.5rem gap -->
  <button class="btn btn-primary">child 1</button>
  <button class="btn btn-outline-primary">child 2</button>
</div>

Display classes set display per breakpoint: d-none hides below md, d-inline-flex makes an inline flexbox, and d-grid turns a wrapper into a CSS grid.

Every value has a responsive form — d-block, d-md-block, d-lg-none — plus print helpers such as d-print-block.

3.3 Flex utilities

3.3.1 Flex Direction

This section introduces the flex utility pack for alignment, direction and wrapping. Classes such as d-flex, justify-content-between and align-items-center do in markup what flexbox CSS does in a stylesheet. Gap and order utilities complete the set, so most layouts need no custom CSS.

<div class="d-flex justify-content-between align-items-center">
  <span>left</span>
  <span class="ms-auto">pushed right by margin</span>
  <span>right</span>
</div>
<div class="flex-column flex-lg-row">  <!-- stack on phones, row on lg -->
  <div class="flex-grow-1">fills extra space</div>
  <div class="flex-shrink-0">never shrinks</div>
</div>

justify-content and align-items position children along the main and cross axes, ms-auto absorbs leftover space, and flex-grow-1 makes one item fill the remainder.

UtilityEffect
justify-content-*Main-axis alignment: start, center, between, around, evenly
align-items-*Cross-axis alignment: start, center, end, stretch, baseline
flex-wrapAllow items to wrap onto new lines
flex-grow-1Let one item absorb all leftover space
ms-auto / me-autoAuto margins push items apart

3.4 The spacing scale

3.4.1 The Spacing Scale

This section explains the spacing scale behind the margin and padding utilities. Classes like mt-3 or px-4 combine a prefix for property, a breakpoint where allowed, and a number from zero to five. The numbered scale keeps spacing consistent across the whole design instead of relying on arbitrary values.

<div class="p-4">padding on all sides</div>      <!-- 1.5rem -->
<div class="mx-auto">horizontally centered</div>   <!-- auto margins -->
<div class="mt-5 mb-2">top and bottom margins</div>
<div class="ps-3 pe-3">padding start and end only</div>
<div class="py-2">vertical padding</div>
<div class="ms-auto">margin-left: auto (pushes right)</div>

Spacing utilities combine a property (m or p), a side (t, b, s, e, x, y) and a scale step from 0 to 5 that multiplies the base 0.25rem.

Step 0 is zero spacing and each step adds 0.25rem (step 5 is 3rem). Add your own steps to the $spacers map when the built-in scale is too coarse.

3.5 Breakpoints in Sass mixins

This section shows the Sass breakpoint mixins for writing responsive rules alongside the framework. You use mixins such as media-breakpoint-up inside custom Sass to apply rules from a given breakpoint upward. This is the customization path that utility classes alone cannot reach, so it matters for real projects.

@use "bootstrap/scss/mixins/breakpoints" as *;

.custom-panel { padding: 1rem; }

@include media-breakpoint-up(lg) {     // lg and above
  .custom-panel { padding: 2rem; }
}

@include media-breakpoint-down(md) {   // strictly below md
  .custom-panel { border-top: 2px solid; }
}

The media-breakpoint-up and media-breakpoint-down mixins wrap your rules in the same min-width and max-width queries the grid uses, so custom CSS stays in sync.

4 · Content & Typography

4.1 Headings, display headings and lead4.2 Inline text utilities and blockquotes4.3 Lists and images4.4 Figures and tables

This chapter covers the base content styling: headings, text utilities, quotes, lists, images and tables. You pair structural HTML elements with classes such as display-4, lead, text-muted and the table variants. Getting typography right is what separates a prototype from a finished product.

Bootstrap resets most native HTML to a clean baseline, then adds utilities to adjust weight, alignment and emphasis. This chapter styles the words and media that live inside the layout.

4.1 Headings, display headings and lead

4.1.1 Semantic Headings

This section shows heading styling, the display variants and the lead paragraph class. Native h1 through h6 get consistent styles, while display-1 through display-6 give oversized marketing headings. Adding class lead to a paragraph increases its size and weight for introductory text. These are the first classes you reach for on any page.

<h1 class="display-1">Oversized headline</h1>   <!-- lightweight, magazine-style heading -->
<h2>Regular Bootstrap heading</h2>

<p class="lead">This intro paragraph is larger and lighter than body copy.</p>

<h3 class="h1">H3 tag styled as an H1</h3>         <!-- keep the tag, swap the look -->
<div class="display-5 fw-semibold">any element can look like a display heading</div>

display-1 through display-6 give oversized headings, lead enlarges intro paragraphs, and the h1 class restyles a heading without changing its tag.

4.2 Inline text utilities and blockquotes

4.2.1 Whitespace Handling

This section covers the inline text helpers, alignment classes and blockquote styling. Utilities set weight, emphasis and color in one-word classes such as fw-bold, font-italic and text-uppercase. Blockquote markup gets the blockquote class and optional blockquote-footer for attribution, and text alignment classes mirror the CSS alignment properties.

<p><mark>highlighted</mark>, <del>deleted</del>, <s>struck</s>, <ins>inserted</ins></p>
<p class="fw-bold">bold by utility</p>
<p class="fst-italic text-muted">italic, muted copy</p>
<p class="text-uppercase small text-secondary">eyebrow-style label</p>

<blockquote class="blockquote">
  <p>A well-known quote, only a guide.</p>
  <footer class="blockquote-footer">Someone in <cite title="Source Title">Source Title</cite></footer>
</blockquote>

Inline semantic elements get Bootstrap’s default styling, fw- and fst- set weight and style, and the blockquote classes render a quoted passage with a muted attribution footer.

<p class="text-start text-md-center text-lg-end">alignment changes with the breakpoint</p>
<p class="text-break">this long unbroken value will wrap instead of overflowing the card</p>
<p class="text-truncate">one line, ending with an ellipsis when the text runs long</p>

Text alignment is breakpoint-aware, text-break forces long words to wrap, and text-truncate collapses overflowing text onto one line with an ellipsis.

4.3 Lists and images

4.3.1 Styled Lists

This section shows the list styling utilities and the image helpers. Class list-unstyled removes the default bullet styling, while list-inline turns items into a horizontal row. The img-fluid class makes images scale with their container and img-thumbnail adds a bordered frame. Together they cover most common content needs.

<ul class="list-unstyled"><li>no bullets, no padding</li></ul>

<ul class="list-inline">                  <!-- items on one line instead of stacked -->
  <li class="list-inline-item">Link A</li>
  <li class="list-inline-item">Link B</li>
  <li class="list-inline-item">Link C</li>
</ul>

<img src="photo.jpg" class="img-fluid" alt="A sample photo">   <!-- max-width 100%, height auto -->
<img src="avatar.png" class="img-thumbnail" alt="Portrait">     <!-- 1px border frame -->

list-unstyled strips bullets, list-inline lays the items on one line, img-fluid never overflows its parent, and img-thumbnail adds a picture frame.

Always set the alt attribute on meaningful images and leave it empty (alt="") on decorative ones — that is the accessibility contract images hold.

4.4 Figures and tables

4.4.1 Responsive Tables

This section covers figure captions and the full table styling toolkit. The figure and figure-caption classes pair images with captions, while table, table-striped, table-hover and table-bordered style data tables. Wrapping a table in the table-responsive class lets it scroll horizontally on small screens.

<figure class="figure">
  <img src="chart.png" class="figure-img img-fluid rounded" alt="Quarterly chart">
  <figcaption class="figure-caption">Q1 figures at a glance.</figcaption>
</figure>

<div class="table-responsive">                  <!-- horizontal scroll on small screens -->
  <table class="table table-striped table-hover">
    <thead><tr><th>Name</th><th>Role</th></tr></thead>
    <tbody>
      <tr><td>Ada</td><td>Engineer</td></tr>
      <tr class="table-primary"><td>Lin</td><td>Lead</td></tr>
    </tbody>
  </table>
</div>

figure pairs an image with a muted caption, table classes add borders, striping and hover states, and the table-responsive wrapper adds a scrollbar when space runs out.

Rows and cells accept contextual classes such as table-primary, tables can be table-sm, and the responsive wrapper takes breakpoint variants like table-responsive-md.

Exercises 4

  1. Style a headline with display-3 and an intro paragraph with lead.
  2. Compose a blockquote with a blockquote-footer citation.
  3. Wrap a striped, hoverable table in table-responsive and test it on a phone.

5 · Forms & Validation

5.1 Form controls5.2 Input groups and floating labels5.3 Selects, checks, switches and range5.4 Form layout on the grid5.5 Validation styles

This chapter covers the form controls, input groups, layout helpers and validation styling. Bootstrap forms look and behave the same in every browser with one class per control, and form-check components style checkboxes and switches. Grid helpers then lay fields out responsively, and validation classes tint controls for feedback.

Forms are where Bootstrap’s polish shows: every native input is normalised with form-control, every label gets its companion class, and validation turns red or green automatically.

5.1 Form controls

5.1.1 Control Types

This section shows the form-control class that styles inputs and textareas across every browser. Adding class form-control to an input, select or textarea normalises its size, font and border. Form-select is the sibling class for selects, and form-label plus form-text handle captions and helper text.

<form>                                  <!-- every control needs a label; helper text is tied on -->
  <div class="mb-3">
    <label for="email" class="form-label">Email address</label>
    <input type="email" class="form-control" id="email" placeholder="name@example.com">
    <div class="form-text">We never share your email.</div>
  </div>
  <div class="mb-3">
    <label for="notes" class="form-label">Notes</label>
    <textarea class="form-control" id="notes" rows="3"></textarea>
  </div>
  <button type="submit" class="btn btn-primary">Submit</button>
</form>

The form-label, form-control and form-text trio styles labels, inputs and helper text coherently, and a wrapping mb-3 div spaces each control apart.

5.2.1 Floating Labels

This section shows input groups, which attach affixes and buttons to a control, plus floating labels that animate in place. The input-group wraps a control with input-group-text or buttons on either side. Floating labels swap the label for a placeholder and use the form-floating wrapper. Both patterns save layout work.

<div class="input-group mb-3">

</div>
<div class="input-group mb-3">

  <span class="input-group-text">.00</span>

  <input type="email" class="form-control" id="floating" placeholder="name@example.com">

5.3.1 Form Controls Options

This section covers the remaining control types: custom selects, checkboxes, radios, switches and the range slider. Form-select styles dropdowns, while form-check, form-check-input and form-check-label build checkboxes and radios, and form-switch turns them into switches. The form-range class styles the range slider, and all share the same label and feedback system.

<select class="form-select" aria-label="Choose a region">

5.4.1 Grid Layout

This section shows how to lay forms out with the grid using rows and columns. You place form controls inside col classes so fields receive gutters and responsive widths like any other grid content. Row g-3 gaps the fields, and unprefixed col classes make them equal width automatically.

<form>
  <div class="row g-3">

5.5 Validation styles

5.5.1 Validation States

This section explains the validation classes that tint controls green or red and reveal feedback text. Adding is-valid or is-invalid to a control colours its border, and the sibling valid-feedback or invalid-feedback elements show messages. Using novalidate on the form lets Bootstrap’s visual states take over from the browser defaults.

<form class="row g-3 needs-validation" novalidate>
  <div class="col-md-4">
    <label for="city" class="form-label">City</label>
    <input type="text" class="form-control" id="city" required>
    <div class="invalid-feedback">Please choose a city.</div>
  </div>
  <div class="col-12">
    <button class="btn btn-primary" type="submit">Submit form</button>
  </div>
</form>

<script>
(() => {
  'use strict';
  const forms = document.querySelectorAll('.needs-validation');
  Array.from(forms).forEach(form => {
    form.addEventListener('submit', event => {
      if (!form.checkValidity()) {        // ask the browser which fields fail
        event.preventDefault();
        event.stopPropagation();
      }
      form.classList.add('was-validated'); // then paint the invalid-feedback blocks
    });
  });
})();
</script>

Controls grow .is-valid or .is-invalid styling when their wrapping form gains .was-validated, and this script adds that class after the browser’s own constraint checks run.

You can also force states directly with is-valid and is-invalid on controls, plus the accompanying valid-feedback or invalid-feedback block.

<button type="button" class="btn btn-primary" data-bs-toggle="modal" data-bs-target="#exampleModal">
  Launch demo modal
</button>

9 · JavaScript Behaviour

9.1 data-bs-* attributes9.2 The programmatic API9.3 Events and lifecycle9.4 Tooltip and popover opt-in plus accessibility

This chapter covers how Bootstrap’s JavaScript activates from data attributes and through objects and events. You will wire plugins with declarative data-bs-* attributes, then learn the programmatic constructor API to take control when needed. Every plugin follows the same lifecycle of creation, events and disposal.

Bootstrap’s JavaScript powers the collapses, dropdowns, modals and toasts of Chapters 6–7. It works two ways: declaratively through data-bs-* attributes, and programmatically through JavaScript objects.

9.1 data-bs-* attributes

This section explains the declarative API that boots plugins from markup alone. Attributes such as data-bs-toggle, data-bs-target and data-bs-dismiss activate components like modals and dropdowns with no JavaScript of your own. Wrapping components in a data-bs-toggle context means most projects never need anything more than these attributes.

<!-- data-bs-toggle names the plugin, data-bs-target points at its subject -->
<button type="button" data-bs-toggle="collapse" data-bs-target="#panel" aria-expanded="false" aria-controls="panel">
  Open the panel
</button>
<div id="panel" class="collapse">...</div>

<!-- plugin options arrive as further data-bs-* attributes -->
<ul class="dropdown-menu" data-bs-offset="10,20">...</ul>

<!-- disable attribute auto-initialisation to drive every plugin from JS -->
<script src="assets/bootstrap.bundle.min.js" data-bs-no-conflict="true"></script>

Every plugin reads its settings from data-bs-* attributes, and data-bs-no-conflict on the script tag opts out of auto-initialisation for manual control.

9.2 The programmatic API

This section shows how to instantiate and control plugins from JavaScript. Every plugin exposes a constructor, so you write new bootstrap.Modal with an element and an options object. Methods such as show, hide and toggle then control it, and dispose cleans up cleanly.

<div id="toastBox" class="toast">Body message</div>

const toastEl = document.getElementById('toastBox');
const toast = new bootstrap.Toast(toastEl, { delay: 3000 });   // options, not attributes
toast.show();              // opens, autohides after the delay
toast.dispose();           // removes the instance and its listeners

// plugins are reachable per element once created
const modal = bootstrap.Modal.getOrCreateInstance('#modalExample');
modal.show();

new bootstrap.Toast creates an instance with host-object options, show() opens it, dispose() tears it down, and getOrCreateInstance returns an existing instance without duplicating it.

9.3 Events and lifecycle

This section explains the plugin events that fire around every transition. Bootstrap emits events such as show, shown, hide and hidden before and after a component changes state. Listening with element.addEventListener lets you hook into moments like just before a modal opens so you can run your own logic.

const modalEl = document.getElementById('modalExample');

modalEl.addEventListener('show.bs.modal', () => {
  console.log('opening — load content or reset state');
});

modalEl.addEventListener('shown.bs.modal', () => {
  firstInput.focus();                            // safe to focus once fully visible
});

modalEl.addEventListener('hide.bs.modal', (event) => {
  if (!saved) event.preventDefault();            // veto the close entirely
});

Every plugin fires matching pairs of events (show/shown, hide/hidden), and calling preventDefault() on a hide event stops the transition from happening.

9.4 Tooltip and popover opt-in plus accessibility

This section shows why tooltips and popovers need manual initialisation and the accessibility hooks they rely on. They defer because Popper must calculate their position, so you instantiate them with the JavaScript API instead of data attributes. Ensure the reference element has a tabindex when needed and rely on their built-in ARIA wiring to keep keyboard and screen-reader users in sync.

// tooltips and popovers are NOT attribute-autoloaded: construct them in JS
const triggers = document.querySelectorAll('[data-bs-toggle="tooltip"]');
const tooltipList = [...triggers].map(el => new bootstrap.Tooltip(el));

// popovers use their own constructor with the same options object
const popover = new bootstrap.Popover(document.querySelector('#popoverBtn'), {
  container: 'body',   // avoid clipping by overflow-hidden ancestors
  html: false          // keep HTML out of the title by default
});

// keep tooltips hover-free for keyboard users: focus triggers them too
new bootstrap.Tooltip(el, { trigger: 'hover focus' });

Tooltips and popovers are built in JavaScript because Popper must position them; adding focus to the trigger keeps them reachable by keyboard users.

For accessible overlays: never nest interactive controls inside a tooltip, prefer real buttons over tooltips on span elements, and let the plugin’s built-in ARIA (role="tooltip" plus describedby) do the wiring.

10 · Customization

10.1 CSS variables10.2 Sass variables and maps10.3 Customizing with npm and compiling10.4 Color modes, RTL and reducing the bundle

This chapter covers the three customization levels: CSS variables, Sass overrides and full compilation. You will theme Bootstrap by overriding custom properties, by editing Sass variables and maps, and by compiling a trimmed output. The chapter also covers dark mode, right-to-left support and reducing the final bundle size.

Out of the box Bootstrap is a finished system — but it is built to be reshaped. CSS variables handle runtime theming, Sass handles compile-time changes, and both feed into how you ship the result.

10.1 CSS variables

This section shows how to override the CSS custom properties that every component reads. Root variables like the color scale and component-specific ones like btn-border-radius are overriden on a selector. Because these are runtime CSS variables, theming happens with no rebuild.

/* root overrides in your own stylesheet — no rebuild needed */
:root {
  --bs-primary: #7c3aed;              /* every component reads these tokens */
  --bs-body-bg: #faf7ff;
  --bs-border-radius: 0.75rem;
}

/* variables are scoped, so a single component can restyle itself */
.card-accent {
  --bs-card-border-width: 0;
  --bs-card-bg: #fff7ed;
}

Overriding the :root tokens recolors the whole framework at runtime, and overriding them on a scoped class restyles just that component.

Every component exposes a documented block of variables like --bs-card-*; the inspector in devtools shows the full cascade on any element.

10.2 Sass variables and maps

This section shows how to override variables and maps before compiling. You import custom Sass that sets variables, such as the theme colors or spacing scale, before importing Bootstrap’s source files. Sass decisions are baked into the generated CSS, so they suit deep, build-time changes.

// scss/custom.scss — order matters
@import "bootstrap/scss/functions";
$primary: #7c3aed;                     // step 2: override variables
@import "bootstrap/scss/variables";
@import "bootstrap/scss/maps";
$theme-colors: map-merge($theme-colors, (   // step 4: extend the maps
  "brand": #0d9488
));
@import "bootstrap/scss/bootstrap";    // step 5: everything else

Overrides sit between the functions import and the variables import, map changes come after variables, and compiling bakes the new palette into the CSS.

New theme colors generate whole families automatically — .text-brand, .bg-brand and .btn-brand all appear once the map grows.

10.3 Customizing with npm and compiling

This section shows the npm install and the compile step that turns your overrides into a production stylesheet. You install bootstrap as a dependency and compile your Sass entry file that imports the framework’s source. This is the fork in the road from CDN use to keeping project files in your own build.

npm init -y
npm install bootstrap     # pulls the compiled assets and the Sass source

# compile the custom stylesheet twice: expanded for development, minified for production
npx sass scss/custom.scss dist/bootstrap.css
npx sass scss/custom.scss dist/bootstrap.min.css --style=compressed

# sanity check: confirm the custom primary color made it into the output
select-string -Pattern "#7c3aed" dist/bootstrap.css

npm install fetches Bootstrap’s source, and two sass runs produce expanded CSS for development and minified CSS for production, verified with a search for the custom color.

10.4 Color modes, RTL and reducing the bundle

This section covers dark mode, right-to-left support and slimming the final files. Dark mode is enabled by adding the data-bs-theme attribute or class to the html element, RTL works by loading the RTL build, and unused plugins can be dropped from the JavaScript bundle. All three are structural choices you make once and benefit from forever.

<html lang="en" data-bs-theme="dark">    <!-- dark mode: flip every component -->

// flip at runtime with one line and persist the choice
document.documentElement.setAttribute('data-bs-theme',
  localStorage.getItem('theme') || 'light');

<html lang="ar" dir="rtl">                 <!-- RTL mirrors the entire layout -->

data-bs-theme switches light and dark across all components, dir="rtl" mirrors the whole layout without markup changes, and a little local storage persists user choice.

For smaller builds, compile selective Sass instead of the full bootstrap.scss, turn off unused $enable-* flags, and import only the components you actually use.

11 · Accessibility & Best Practices

11.1 Semantic markup11.2 Focus states and keyboard support11.3 ARIA in components11.4 Contrast and common misuse

This chapter covers the accessibility contract Bootstrap components promise and the common ways projects break it. Components ship with keyboard support, focus rings and ARIA attributes, but only when you keep the required markup and attributes intact. Accessible markup is a habit, not a deadline checklist.

Bootstrap’s components ship with reasonable ARIA and keyboard behaviour for free — but only if you keep the right attributes in place. This chapter is about not breaking the defaults and knowing when to reach for more.

11.1 Semantic markup

This section shows how real elements and landmarks scaffold every component. Choose the right tag first, such as button for a button or nav for navigation, and classes then only change appearance. Semantic HTML keeps structure meaningful for screen readers and search engines alike.

<!-- semantic: an anchor, because it navigates -->
<a class="btn btn-primary" href="/account">Go to account</a>

<!-- semantic: a button, because it does something in-page -->
<button type="button" class="btn btn-outline-secondary">Save draft</button>

<!-- anti-pattern: a div staging as a button must rebuild keyboard and focus -->
<div onclick="..." role="button" tabindex="0">bad idea</div>

An anchor navigates, a button triggers in-page behaviour, and a div turned into a button must re-implement keyboard handling and focus that a native button gives you free.

11.2 Focus states and keyboard support

This section explains how Bootstrap’s focus rings surface every tab stop. Focused elements show a visible outline supplied by focus ring styles, and the CSS variables behind them make restyling easy. Do not remove outlines, because keyboard users need them, restyle them instead.

/* replace, never remove, the focus ring */
.form-control:focus {
  border-color: var(--bs-primary);
  box-shadow: 0 0 0 0.25rem rgba(124, 58, 237, 0.25);
}

/* keyboard-visible focus for any custom widget, using the modern hook */
.focusable:focus-visible {
  outline: 2px solid var(--bs-primary);
  outline-offset: 2px;
}

Focus rings are accessibility progress indicators: restyle them with box-shadow or outline rather than hiding them, and use :focus-visible so only keyboard users see them.

Anything interactive must be reachable: any element with a click role needs tabindex="0" plus Enter and Space handling — again, a native button gives you all of that for free.

11.3 ARIA in components

This section maps the ARIA attributes Bootstrap wires for you and the ones you must supply. Components like modals and toggles add attributes such as role or aria-expanded automatically, while you must provide aria-label on icon-only buttons or alt text on images. Getting these right keeps screen-reader users in sync with the visible state.

<div id="status" role="status" aria-live="polite" class="visually-hidden"></div>

function announce(msg) {
  const region = document.getElementById('status');
  region.textContent = msg;   // region stays visually hidden but is read aloud
}

announce('Your changes were saved.');

role="status" plus aria-live="polite" makes a visually-hidden region announce updates to assistive technology without interrupting the task.

11.4 Contrast and common misuse

This section finishes with color contrast and the recurring misuse patterns to avoid. Text and background color choices must keep enough contrast for readability, and common errors include overriding colors with the text- or bg- utilities without checking their ratio. These errors are the usual reason an accessible Bootstrap site fails an audit.

  • Muted gray on white — text-muted often fails WCAG AA for small text; prefer text-secondary or a custom darker value.
  • Tooltip-only information — tooltips vanish for hover and some keyboard users; keep critical content in the page text.
  • Carousels that autoplay — respect prefers-reduced-motion or drop data-bs-ride; moving content is a distraction for many users.
  • Color alone as the signal — pair every color with an icon, a checkmark or text.
  • Buttons that look like links — keep affordances honest so assistive users can predict what will happen.

A.4 Glossary

This section defines the terms used throughout the guide, from breakpoint and gutter to utility and customization. Each entry gives a plain-language definition so a class or word in the chapters never feels fuzzy. Skim it whenever you hit a term you have not seen before.

  • Breakpoint — the viewport widths (sm…xxl) that switch layout via min-width media queries.
  • Container — the horizontal wrapper that centers rows and caps the page width.
  • Gutter — the padding inside each column that becomes the space between columns.
  • Responsive class — any utility with a breakpoint suffix, active from that width upward.
  • Component — a finished, accessible widget (card, navbar, modal) you drop into markup.
  • Plugin — the JavaScript behaviour engines behind toggles, collapses and toasts.
  • Popper — the positioning library that places tooltips, popovers and dropdowns.
  • Spacer — one step of the spacing scale; 0.25rem base values from 0 to 5.
  • CSS variable — a --bs-* design token overrideable at runtime.
  • Sass map — the compile-time collection of values (colors, spacers, gutters) that generates utilities.
