How this guide is organised

This guide covers website development from zero to full-stack. Every chapter follows the same rhythm: a topic description, prose explanation, two code samples, and a callout flagging the most common mistake.

Structure of every section

Each h3 section is a self-contained unit: intro, prose walkthrough, two code examples, and a callout. Chapters 1–3 build the foundation: how the web works, core HTML/CSS/JS, and tooling. Chapters 4–8 cover the interactive layer: DOM, APIs, SPAs, forms, and PWAs. The remaining chapters go deep on backend, databases, auth, security, performance, testing, deployment, and scaling.

The mindset: users first, then code

Fast, accessible, and maintainable. Those three goals never conflict when you follow the right order: user needs first, architecture second, micro-optimisations last.

Follow the delivery sequence

Do not build the backend before the API contract is clear. Do not write CSS before the HTML structure is semantic. Do not optimise images before the page loads. This guide follows the real delivery sequence: structure first, behaviour second, polish third.

Verify before you deploy

Every chapter ends with a check: does this work on a phone, with a slow network, with a screen reader? If the answer is yes, it is done. If not, fix it before moving on.

Tools you will use throughout

You can build a production website with free tools. VS Code is free. Node.js is free. A local server like Live Server or Python’s http.server is free. Git is free. No paid tooling is required for any chapter in this guide.

A typical workflow

Write HTML in VS Code → preview with Live Server → version with Git → run Lighthouse on every deploy → push to a static host. This loop is the same whether the site is a portfolio or a SaaS dashboard.

Start with plain HTML, CSS, and JS. Add a framework only after you have hit a real problem that the framework would solve.

1.1 HTTP, DNS, TLS & hosting

The web is a request-response system. A browser requests a page by URL; a server responds with HTML, CSS, and JS. DNS translates a domain name to an IP. TLS encrypts the connection.

Anatomy of a URL

https://www.example.com:443/page?id=123#section

https:  protocol
www.:   subdomain
example.com: domain
:443:   port (443 for HTTPS, 80 for HTTP)
/page:  path
?id=123: query string
#section: fragment (client-side only)

1.2 The request lifecycle

From the moment you type a URL to the moment the page renders, several steps occur.

A typical lifecycle

1. DNS lookup: example.com → 93.184.216.34
2. TCP connection to 93.184.216.34:443
3. TLS handshake
4. HTTP GET /page
5. Server processes request → returns HTML + CSS + JS
6. Browser parses HTML → requests CSS and JS
7. CSS parsed → render tree built
8. JS downloaded and executed → page interactive

1.3 Static vs dynamic rendering

Static sites are pre-built HTML files. Dynamic sites generate HTML on the server per request. Each model has trade-offs.

Static vs dynamic

// Static — one HTML file, no server needed
File: index.html
Response: direct from CDN

// Dynamic — server generates HTML per request
Request: GET /news/article/123
Server: render_template('article.html', data=query(123))
Response: HTML built just for this request

Static is faster, cheaper, and more secure. Choose dynamic only when you need real-time data or server-side logic that cannot be replicated at build time.

2.1 Semantic HTML structure

Semantic HTML uses elements for their meaning, not their appearance. A <header> means "page header", not "a div styled like a header".

A skeleton

<!DOCTYPE html>
<html lang="en">
<head>...</head>
<body>
  <header>...</header>
  <main>
    <article>...</article>
    <aside>...</aside>
  </main>
  <footer>...</footer>
</body>
</html>

2.2 CSS layout: box model & flex/grid

Every element is a rectangle (the box model). Padding is inside the border, margin is outside. Flexbox aligns in one dimension; Grid places in two.

A flex header

header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  padding: 16px 24px;
}
header .logo {
  margin-right: auto;
}
header nav a {
  margin-left: 16px;
}

2.3 JS: DOM, events, and state

The DOM is a tree of HTML elements. JS reads, changes, or adds nodes. Events tell JS when something happens: a click, a key press, a form submit.

A simple event handler

const button = document.querySelector('#submit');
button.addEventListener('click', (e) => {
  const input = document.querySelector('#search');
  console.log('Searching for:', input.value);
});
