Orientation — Scope, Versions and Tooling

Scope and target versionSupported branches and end-of-life datesThe open tag, templates and the command lineThe toolchainReading type declarationsConventions used in this guide

This guide documents the PHP 8.5 language as it is actually used in production: its type system, its function and error models, and its object-oriented facilities. It is written as a reference, not a course. Sections state facts about the language and cite the release that introduced each feature; they are designed to be read out of order and consulted while code is being written.

Three constraints shape everything below. First, PHP is a gradually typed language: a declaration is checked at the boundary it appears on, and the boundary that matters most is the calling file, not the declaring file. Second, the language is a moving target with a one-year feature cadence, so every version claim is pinned to a release. Third, the language is only half of PHP — the extension surface is the other half — so this guide covers the core language and cites extension functions where they intersect with it.

Scope and target version

0.1 Visibility and Scope

The version this guide describes, and the specific releases that introduced the syntax it uses.

The target is PHP 8.5, stable since 20 November 2025. The most recent patch at the time of writing is 8.5.11, and the branch receives security fixes until 31 December 2029. Two neighbouring branches matter for deployment decisions: 8.4, which is the conservative production target most hosting platforms and shared packages still default to, and 8.6, which is at release candidate and is due in November 2026.

8.5-specific syntax — the pipe operator above all — is a parse error on 8.4 and earlier. A file that uses |> will not fail gracefully on an older runtime; it will not parse at all, and the error surfaces at include time rather than at the point of use. Pin the runtime before you write the syntax, not after.

Because the language gained most of its modern surface in a short burst, code written against PHP 7.0-era idioms is easily recognised. The table below is the version index used throughout this guide: when a construct is discussed, the release that introduced it is named.

Feature detection at runtime is the correct way to branch on a language version, because the version is a property of the process rather than of the codebase. PHP_VERSION_ID is a monotonically increasing integer; comparing it is cheaper and less error-prone than parsing PHP_VERSION with a regular expression.

// version-gate.php — run with: php version-gate.php
<?php

declare(strict_types=1);

const 8_5_0 = 80500; // 8.5.0
const 8_4_0 = 80400; // 8.4.0

printf("Running on PHP %s (id %d, SAPI %s)", PHP_VERSION, PHP_VERSION_ID, PHP_SAPI, 8_5_0);

if (PHP_VERSION_ID >= 8_5_0) {
    echo "Pipe operator and the URI extension are available.";
} elseif (PHP_VERSION_ID >= 8_4_0) {
    echo "Property hooks and asymmetric visibility are available.";
} else {
    echo "Pre-8.4 runtime: no property hooks.";
}

// The URI extension is always available in 8.5; it is not a PECL package.
if (PHP_VERSION_ID >= 8_5_0 && !class_exists(Uri\Rfc3986\Uri::class)) {
    throw new RuntimeException('URI extension missing from an 8.5 build');
}

The first argument to printf is a format string; %s is replaced by one argument, %d by an integer. A complete treatment of sprintf and printf placeholders is in 1.5.

Prefer PHP_VERSION_ID comparisons over version_compare(PHP_VERSION, '8.5.0', '>=') in hot paths, and prefer feature probes such as defined('Uri\Rfc3986\Uri::class') over version comparisons entirely. A distribution can patch a feature back into an older branch, and a feature probe tells you what the process can actually do.

Supported branches and end-of-life dates

0.2 EOL Support

The release policy, the branches that are still receiving fixes, and what to do about 8.6.

PHP publishes one minor release per year, in November. Each minor branch receives approximately two years of active support — bug fixes and security patches — followed by a further year of security-only support. At end of life, patches stop and the branch is removed from the build matrices of most CI providers, package managers and hosting platforms.

8.1 reached end of life on 31 December 2025. It remains a common ceiling for shared library support because a large body of published packages still declare "php": "^8.1", but nothing in this guide requires it, and no new production deployment should be planned on it.

8.6 is at release candidate at the time of writing. Release candidates are for compatibility testing, not for production. Two practices separate the two uses: pin production images to a stable patch, and run the release candidate in a non-blocking CI job that reports differences without failing the build. The 8.6 feature set is not documented here; where 8.6 is relevant to a decision in this guide it appears only as an upcoming milestone.

Applies to: the CI policy above. A matrix should include 8.4 even when production runs 8.5, because a library consumed by 8.4-only consumers must not ship 8.5-only syntax. Keep the release candidate in a separate job and mark it non-blocking: a candidate that gates a merge blocks every subsequent commit until it is fixed, and its only purpose before release is to report differences. Pin exact patch versions rather than minor branches, so two builds of the same commit are byte-identical. CI configuration itself is covered in CI/CD.

The open tag, templates and the command line

0.3 CLI and Templates

How a file becomes output, which tag to use, and the commands used throughout this guide.

A PHP file is a stream of literal text with executable regions delimited by <?php and ?>. Anything outside the tags is copied verbatim to the output buffer, which is what makes PHP a template language as well as a scripting language. The short echo tag <?= is shorthand for <?php echo and is the correct construct in templates; the short open tag <? exists for compatibility with ancient configurations and is disabled by default.

As of PHP 5.5 the closing tag ?> is optional, and short_open_tag defaults to Off. A pure-PHP file therefore ends at end-of-file with no terminator. This is not merely permitted, it is the conventional style: a trailing ?> immediately followed by a newline emits that newline, which breaks HTTP headers, corrupts binary output and produces "headers already sent" warnings.

// greeting.php — a script: no closing tag, and no trailing whitespace.
<?php

declare(strict_types=1);

$name = $_GET['name'] ?? 'world';

header('Content-Type: text/plain; charset=utf-8');
echo sprintf('Hello, %s!', htmlspecialchars((string) $name, ENT_QUOTES, 'UTF-8'));

Run it with php greeting.php. The declare call must be the first statement in the file; anything before it is a parse error.

Templates invert the pattern. Because PHP has no compile step, a .phtml template is simply a file with mixed text and code, and the same file is both the markup and the program.

<?php declare(strict_types=1); ?>
<!DOCTYPE html>
<html lang="en">
<head><meta charset="utf-8"><title><?= $title ??>Dashboard</title></head>
<body>
<ul>
<?php foreach ($items ?? [] as $item): ?>
  <li><?= htmlspecialchars((string) $item, ENT_QUOTES, 'UTF-8') ?></li>
<?php endforeach; ?>
</ul>
</body>
</html>

The alternative block syntax — if: / endif;, foreach: / endforeach; — exists for templates and is covered in 1.1. Escape every interpolated value with htmlspecialchars(); there is no automatic escaping in PHP templates, and an unescaped interpolation is a stored cross-site scripting defect.

Reading type declarations

0.5 Type Declarations

A notation reference for every type form PHP 8.5 accepts, and what each one actually guarantees.

PHP’s type system has three tiers, and conflating them is the most common source of misunderstanding. The runtime tier is enforced by the engine at the point where a value enters or leaves a typed boundary. The static tier is a docblock contract that no runtime check enforces; PHPStan and Psalm evaluate it, and the engine ignores it entirely. The library tier is the informal use of array to mean a shaped structure, again a docblock contract.

Two consequences follow, and they govern the rest of this guide. A type declaration is only as strong as the weakest boundary it crosses — an untyped parameter converts a typed caller into an untyped callee. And a docblock generic such as list<User> constrains nothing at runtime; it is a promise the analyser holds you to, and a promise nothing holds you to when the analyser is not running.

<?php

declare(strict_types=1);

/** The only tier the engine enforces: runtime types. */
function process(
    int $id,
    string $name,
    ?array $tags = null,
    callable| null $transform = null,
): never {
    throw new InvalidArgumentException('process() is a placeholder');
}

/** The static tier: a contract the analyser enforces and the engine ignores. */
/**
 * @param list<string>                        $tags
 * @param (callable(string): string)|null      $transform
 * @return non-empty-string
 */
function label(int $id, array $tags = [], ?callable $transform = null): string
{
    $base = $transform !== null ? $transform('record') : 'record';

    return $base . '#' . $id;
}

// Static tier violations are reported by the analyser, not by the engine:
// label(1, ['a', 'b']);                 // fine
// label(1, ['a' => 'b']);              // not a list: reported at level 6+
// label(1, 'not-an-array');           // TypeError at runtime as well

A list<T> is an array with consecutive integer keys starting at zero. array<int, string> is weaker: it admits [3 => 'c'], which is a common source of Undefined array key failures when a value is iterated by position. Where order matters, declare list<T>.

declare(strict_types=1) is not retroactive and not contagious. It applies to every call made from the file it appears in, and to the file’s own return type. A file without the declaration will silently coerce an int argument to a string parameter even when the callee declares string. See 1.4.

Conventions used in this guide

0.6 Naming Conventions

The three note forms used throughout, and the reading conventions applied to code samples.

Three callout types recur in every chapter, each carrying a different kind of information that does not belong in a code comment.

Note states a fact about behaviour that a reader is likely to get wrong, or a cross-reference to where the behaviour is described in full. It is commentary, not advice.

Tip states a practice that improves the code without changing what it does. It is optional.

Caveat states a failure mode, a performance characteristic, or a restriction imposed by the language. Ignoring it produces a defect rather than a stylistic disagreement.

Three labels appear inside notes and carry the same meaning throughout:

  • Applies to — the exact PHP version, extension or SAPI a statement depends on.
  • Requirements — what must be true of the environment for a sample to run: an extension, an ini directive, a minimum version.
  • Caveats — the edge cases, the silently wrong results, and the costs associated with a construct.

Code samples follow four reading rules. Comments carry the explanation, so the code can be pasted into a file and run without modification. Line numbers are never shown, because they desynchronise on the first edit. PHP keywords, string literals, numbers and comments are colourised in the sample, but the colour is added by the page and carries no meaning. Every sample that is not a complete file says so in its code-note.

Run every sample before trusting it. php -l file.php checks syntax in milliseconds without executing anything, and php file.php executes it. A language with this many implicit conversions punishes reading over running, and the failure modes are exactly the ones documented in 1.4.

The lexical and semantic rules that govern every line of PHP that follows. Two features distinguish PHP from most languages in the same generation and account for most of its reputation for unexpected behaviour. The open tag, statements and conditionals

1.1 Output and echo

How a file is structured, what terminates a statement, and the four forms a conditional takes.

A PHP file is literal output interleaved with executable regions. The <?php tag opens a region and ?> closes it; outside those markers the bytes are emitted verbatim. Inside a region, statements are terminated by a semicolon or by a closing brace. A semicolon before a closing brace is permitted and does nothing. The <?= tag is the short form of <?php echo and is the correct choice in templates.

PHP is case-insensitive for keywords, function names and class names, but case-sensitive for variables. $name and $Name are different variables; ECHO and echo are the same keyword. Function and class names follow the same rule, which is why the ecosystem enforces PSR naming by tooling rather than by the language.

A conditional has four forms. The braced form is the default and the only one to use in logic code.

<?php

declare(strict_types=1);

$score = 87;

// Braced form. Prefer this everywhere outside templates.
if ($score >= 90) {
    $grade = 'A';
} elseif ($score >= 80) {
    $grade = 'B';
} else {
    $grade = 'C';
}

// Alternative syntax. Only for templates: it ends with ; rather than a brace,
// which is legal but unreadable in procedural code.
if ($score > 0): echo 'positive'; else: echo 'non-positive'; endif;

// Ternary is an expression, so it can produce a value.
$label = $score > 0 ? 'positive' : 'non-positive';

// Loops: all four forms. do-while runs its body at least once.
for ($i = 0; $i < 3; $i++) {
    echo $i;
}

$n = 3;
while ($n-- > 0) { echo $n; }

do {
    $n++;
} while ($n < 3);

// foreach copies by default. Passing the key or value by reference is
// covered in 1.6, and is a source of lasting aliasing bugs.
foreach (['a', 'b'] as $letter) {
    echo $letter;
}

foreach (['a', 'b'] as $index => $letter) {
    echo $index . $letter;
}

// break accepts a level; continue accepts a level. Both are integers, not keywords.
foreach ([1, 2, 3] as $n) {
    if ($n === 2) { continue; }
    echo $n;   // 13
}

Operators are assigned by a fixed precedence table, not left to right. Arithmetic binds tighter than comparison, which binds tighter than assignment. When a compound condition is not obvious, parenthesise it; a reader should not have to hold the precedence table in their head.

Applies to: the alternative syntax has existed since PHP 4 and is unchanged in 8.5. Caveats: every conditional in PHP requires the condition to evaluate to a boolean-ish value. A string "0" and an empty string are falsey; the string "0.0" is truthy because it is not "0" and not empty. Truthiness in PHP is the single most common source of silent logic errors, and the safe practice is to write the comparison explicitly.

== performs type juggling. "0" == "false" is true because both convert to false; "abc" == 0 is true in PHP 8 because the numeric string is converted to 0 and compared. In PHP 7 that comparison returned false. Always use === unless the coercion is the intent.

switch versus match

1.2 Type Switching

Two constructs that look interchangeable and differ in type handling, fall-through and return value.

switch is a loose-equality dispatcher with fall-through. match, added in 8.0, is a strict-equality expression that never falls through and always produces a value. They are not interchangeable, and migrating between them changes behaviour rather than merely style.

Propertyswitchmatch
Comparison operator== (loose)=== (strict)
Falls through without breakYes, by designNo, structurally impossible

<?php

declare(strict_types=1);

function legacy_dispatch(mixed $status): string
{
    // switch: loose comparison, no default action if nothing matches,
    // and fall-through between adjacent cases.
    switch ($status) {
        case 200:
        case 201:          // deliberate fall-through
            return 'success';
        case 404:
            return 'missing';
        default:
            return 'unknown';
    }
}

function strict_dispatch(mixed $status): string
{
    // match: strict comparison, exhaustive or it throws, and an expression.
    return match (true) {
        $status === 200, $status === 201 => 'success',
        $status === 404                        => 'missing',
        default                                       => 'unknown',
    };
}

// match (true) is the idiom that reproduces switch's loose-ish dispatch
// while keeping strict comparison on each arm. Without it, the subject is
// compared strictly, so the int 200 would not match the string '200'.

echo legacy_dispatch(200),   legacy_dispatch(0);   // 'success' 'unknown'
echo strict_dispatch('200'), strict_dispatch(200);    // 'unknown' 'success'

// Without a default arm, a non-matching subject is a fatal condition,
// not a null return:
// match ($status) { 200 => 'success' };  // UnhandledMatchError

The engine compares match arms for exhaustiveness only when the subject type is known to be an enum or a bool; for every other subject, omitting default is a guaranteed UnhandledMatchError on any value not listed. Enums are the exception — an enum subject with all cases covered is statically exhaustive.

Applies to: match requires PHP 8.0 or later. Caveats: match evaluates its subject exactly once, whereas switch re-evaluates the subject on every case comparison, so switch ($obj->next()) advances the iterator once per case. A switch over an enum must be exhaustive by hand, and there is no compile-time check that it is.

Prefer match for value mapping and switch for statement dispatch. The signal is whether the construct’s job is to compute something or to run something. A switch that only returns is almost always better written as a match, because the return makes the fall-through impossible anyway and match states that.

Variables, existence checks and references

1.3 References

How names are bound to values, how existence and nullability are tested, and what a reference actually is.

A PHP variable is a name bound to a value in a symbol table. The prefix sigil $ is part of the name, and there is no declaration step. An undefined variable reads as null and emits a warning; writing to it creates it. This is the origin of PHP’s most common runtime failure, and the reason isset() and ?? exist.

Because names are strings, they can be computed. A variable whose name is itself held in a variable is a variable variable, written with a second $. The construct is legal, occasionally necessary when interfacing with extract() or $-style legacy APIs, and a poor default choice: it defeats every static analyser and makes a typo a silent runtime no-op rather than a compile error.

<?php

declare(strict_types=1);

// Existence, emptiness and removal.
$config = ['debug' => false, 'name' => '', 'items' => []];

var_dump(isset($config['debug']));   // true: the value is false, not null
var_dump(empty($config['debug']));   // true: false is empty
var_dump(isset($config['absent'])); // false
var_dump(empty($config['name']));    // true: '' is empty

unset($config['name']);
var_dump($config);                  // the key is gone entirely

// Null coalescing: reads without warning, and never triggers __isset.
$retries = $config['absent'] ?? 3;            // 3
$config['retries'] ??= 3;               // assign only if absent or null

// Nullsafe operator: short-circuits on null instead of throwing.
function find_user(int $id): ?stdClass { return $id === 1 ? (object)['id' => 1] : null; }

$name = find_user(2)?->id;              // null, no warning
$id   = find_user(1)?->id;              // 1

// Variable variables. Legal, discouraged, opaque to analysers.
$name  = 'total';
$total = 42;
echo $name;                          // 42
// echo ${'to' . 'tal'};                    // same value, and just as opaque

?? suppresses the undefined-index warning that a bare read would emit, and applies to the whole left-hand chain: $a['b']['c'] ?? $default yields $default if $a is missing, null, or has no 'b' key, without evaluating any of the intermediate reads.

Caveats: isset() returns false for any key whose value is null, which is why it cannot distinguish "absent" from "present and null". Use array_key_exists() for that, and note that it throws on objects — pass an object and you get a TypeError, not a boolean. empty() is a test for a falsey value, not for the absence of a value; empty($x) never emits a warning, for any state of $x including undefined.

Arguments are passed by value by default. A copy-on-write mechanism makes that cheap: the copy is deferred until one of the two variables is written to. The & operator in a parameter declaration turns the parameter into a reference to the caller’s variable, at which point writing to the parameter writes to the caller’s variable.

<?php

declare(strict_types=1);

function by_value(int $n): void { $n += 10; }
function by_reference(int &$n): void { $n += 10; }

$x = 1;
by_value($x);        echo $x;   // 1: the caller is unaffected
by_reference($x);    echo $x;   // 11: the caller is modified

// A reference parameter cannot be given a literal or a temporary.
// by_reference(5);            // Fatal error: argument must be a variable

// An expression is a temporary, so this is also illegal:
// by_reference($x + 1);

// Returning by reference is a separate, rarely needed mechanism:
// by &reference requires the function to declare & on the return type.
function &pick(array &$data, string $key): mixed {
    return $data[$key] ?? null;
}

References are aliases, not pointers to a location that is checked. Once $x and $n name the same reference set, rebinding either one is a runtime error, and the alias survives into any closure that captured it. In idiomatic code, references are needed in exactly two places: the &$param of a mutator, and foreach by reference. Everywhere else, return a new value.

PHP 8.1 added first-class callable syntax, which removes the reason to pass 'strlen' as a string. $f = strlen(...); captures a validated callable and is checked by the engine at the point of capture. See 2.2.

The type system and strict_types

1.4 strict_types

What is checked, when it is checked, and why the same call can succeed in one file and fail in another.

PHP has no compile-time type system. A scalar type declaration is a runtime assertion evaluated at the moment the value crosses the boundary, and the engine decides whether to accept the value or convert it. The declaration on the function says what is acceptable; the strict_types setting of the calling file says whether conversion is attempted.

This is the single most important rule in the chapter: strict mode is a property of the call site, not of the declaration. A function declared function f(int $n) accepts "12" when called from a non-strict file and throws a TypeError when called from a strict one. The same function, unchanged, behaves differently for two callers.

<?php

declare(strict_types=1);

// The declared parameter types. This function is identical in both modes.
function show(int $i, string $s, bool $b): void
{
    var_dump($i, $s, $b);
}

show(42, 'text', true);   // int(42) string("text") bool(true)

// Under strict_types=1, each of the following is a TypeError:
// show('42', 'text', true);        // int given, string supplied
// show(42, 123, true);           // string given, int supplied
// show(42, 'text', 1);           // bool given, int supplied

// The return type is checked against the value actually returned,
// and a declared return type with no return statement is a TypeError.
function broken(): string { }        // TypeError, not a silent null

// Union types accept the first member that matches. Intersection types
// (8.1) require every member. DNF types (8.2) combine both.
function handle(int|string $id, (Countable&ArrayAccess)|null $bag = null): string
{
    return 'ok';
}

Adding declare(strict_types=1) to an existing codebase is a behaviour change, not a refactor. It converts a population of silently coerced values into TypeError failures. The safe order is: add the declaration, run the full test suite with error_reporting(E_ALL), fix the sites that now throw, and only then rely on the coercion table below.

Strings, interpolation and multibyte text

1.5 Encoding

The four string literal forms, the interpolation grammar, formatting, and the difference between bytes and characters.

PHP strings are byte sequences. There is no character type; "abc" is three bytes, and a UTF-8 accented character is two or more of them. Length, indexing and case conversion are therefore all byte operations unless the multibyte extension is used, and this is the cause of the classic off-by-one in string slicing.

Four literal forms exist: single-quoted, double-quoted, heredoc and nowdoc. Single-quoted strings are literal except for \\ and \'. Double-quoted strings interpolate variables and array offsets. Heredoc behaves like a double-quoted string; nowdoc behaves like a single-quoted one. Both heredoc and nowdoc are terminated by an identifier that must begin in the first column, which is what allows a body containing any indentation.

<?php

declare(strict_types=1);

$name = 'Ada';
$cart = ['sku' => 'A-1', 'qty' => 2];

$single = 'No interpolation: $name stays literal.';
$double = "Value: $name and $cart[sku] and {$cart['qty']}";

$heredoc = <<<TEXT
    Indented heredoc. The closing identifier must start in column 1.
    Interpolates $name, and \n is a real newline.
    TEXT;

$nowdoc = <<<'TEXT'
    Indented nowdoc. $name is literal here.
    TEXT;

echo $double, PHP_EOL, $heredoc, $nowdoc;

// sprintf with positional and named placeholders (named: PHP 8.0).
$line = sprintf(
    '%-10s %8.2f %5d%%',
    $name,
    1234.5678,
    42,
);
echo $line, PHP_EOL;

$line = sprintf('%1$s scored %2$d', $name, 42);
$line = sprintf('{name} scored {score}', name: $name, score: 42);

// Bytes versus characters. strlen counts bytes; mb_strlen counts characters.
$text = 'cafe' . chr(0xC3) . chr(0xA9);   // "cafe" + e-acute
echo strlen($text);                 // 5 bytes
echo mb_strlen($text, 'UTF-8');   // 4 characters
echo mb_substr($text, 0, 4, 'UTF-8'); // the first four characters, not bytes
echo substr($text, 0, 4);        // the first four BYTES: invalid UTF-8

// Case conversion and sorting are locale- and multibyte-sensitive.
echo mb_strtoupper('cafe' . chr(0xC3) . chr(0xA9), 'UTF-8');
echo strtoupper('STRASSE');          // ASCII only; never use for user data

Requirements: ext-mbstring for mb_strlen, mb_substr and the other mb_* functions. The extension is compiled in by default on most distributions but is not part of the language; declare it in composer.json as "ext-mbstring": "*" so a missing extension fails at install time rather than in production.

Complex interpolation syntax ${expr} was deprecated in 8.2 and removed in 9. Use {$expr} for a variable that needs delimiting, or a printf call, or concatenation. Separately: htmlspecialchars() with an explicit ENT_QUOTES and 'UTF-8' is the only safe way to interpolate a value into HTML, and its omission is the most common PHP security defect.

Applies to: the interpolation grammar is unchanged since 5.0 apart from the ${} removal. Note that "$arr[key]" works but "$arr['key']" does not inside a double-quoted string, because the quotes terminate the string; the unambiguous form is {$arr['key']}. A bare $name interpolates greedily, so "$name_suffix" reads the variable $name_suffix.

Arrays

1.6 Array Functions

The single data structure that serves as list, dictionary, stack and set, its value semantics, and its failure modes.

A PHP array is a single type declared as array that is simultaneously an ordered map and a list. An array is a hash table with insertion order preserved; integer keys starting at zero make it a list, and any other key makes it a dictionary. There is no []-only or {}-only syntax — both literals construct the same type, and an array may legitimately hold some integer keys and some string keys.

Arrays have value semantics: assignment copies, made cheap by copy-on-write. The copy is deferred until either side is modified, so $b = $a is close to free, and $b[] = 1 is what actually duplicates the table. This is the correct default and one of PHP’s better design decisions; it also means that a function receiving an array cannot mutate the caller’s array unless it takes a reference or returns a modified copy.

<?php

declare(strict_types=1);

// One type, three shapes.
$list    = ['a', 'b', 'c'];                       // keys 0, 1, 2
$map     = ['name' => 'Ada', 'role' => 'admin'];   // string keys
$mixed   = [10, 'name' => 'Ada'];                 // both, legally

// Existence: isset() cannot see a key whose value is null.
$rows = [1 => 'Ada', 2 => null];

var_dump(isset($rows[2]));                       // false: the value IS null
var_dump(array_key_exists(2, $rows));              // true: the key IS present

// in_array() is loose by default. The third argument makes it strict.
var_dump(in_array('1', [1, 2]));              // true: '1' == 1
var_dump(in_array('1', [1, 2], true));      // false: different types
var_dump(in_array('abc', [0]));               // true in PHP 8: 'abc' converts to 0

// Composition: array_merge appends and renumbers; array_replace overwrites
// in place and preserves the original key order and string keys.
$a = ['x' => 1, 'y' => 2];
$b = ['y' => 9, 'z' => 3];

print_r(array_merge($a, $b));    // x=>1, y=>9, z=>3 (string keys: last wins)
print_r(array_replace($a, $b)); // x=>1, y=>9, z=>3 (same here)

// With integer keys they diverge sharply. array_merge renumbers,
// array_replace keeps the positions and overwrites by key.
$n1 = [3 => 'c'];  $n2 = [7 => 'g'];
print_r(array_merge($n1, $n2));    // [0 => 'c', 1 => 'g']
print_r(array_replace($n1, $n2)); // [3 => 'c', 7 => 'g']

// Spread unpacks a string-keyed array into an argument list or a literal.
$options = ['retries' => 3, 'timeout' => 1.5];
$merged  = [...$options, 'retries' => 5];        // spread: 7.4; later keys win
print_r($merged);                                // retries=>5, timeout=>1.5

// Sorting. usort is not stable before PHP 8.0; since 8.0 it is.
$people = [
    ['name' => 'Ada',   'age' => 36],
    ['name' => 'Grace', 'age' => 45],
    ['name' => 'Alan',  'age' => 41],
];
usort($people, static fn(array $a, array $b): int => $a['age'] <=> $b['age']);
print_r(array_column($people, 'name'));   // Ada, Alan, Grace

// THE array gotcha: foreach by reference aliases the elements, and the
// alias outlives the loop. $last is a reference to element 2 forever.
$values = [1, 2, 3];
foreach ($values as &$v) { $v *= 2; }
unset($v);   // mandatory: breaks the alias

// Without unset(), this loop is O(n^2) and changes $v[0] on pass two.
foreach ($values as &$v) {
    if ($v === 8) { $values[0] = 0; }
}

The trailing unset($v) after a by-reference foreach is not a style preference. Without it, the loop variable remains a live reference into the array, so a second by-reference loop over the same array writes into the wrong elements. This is the mechanism behind the well-known "the array changed itself" defect, and it is invisible until the code is refactored so the two loops sit in the same function.

Array functions differ in how they treat keys, and reading only the top-level summary is how key-preservation bugs are introduced. array_merge renumbers integer keys and overwrites string keys; array_replace preserves both; array_merge_recursive concatenates duplicate string keys into arrays instead of overwriting; + keeps the left operand’s value for duplicate keys and is not commutative. For anything beyond trivial use, state the key policy in a comment at the call site.

Applies to: usort, uasort and uksort have been stable since PHP 8.0. Before 8.0 an unstable sort could reorder equal elements between runs, which produced non-reproducible output and intermittent test failures. ksort has always sorted by key using PHP’s comparison rules, so mixed-type keys are compared by type first, which is rarely the intent. asort, arsort, ksort, krsort preserve key association; sort, rsort discard it.

Declare shapes in docblocks and let the analyser do the work: @param array<string, User> $usersById and @return list<int>. Runtime PHP cannot enforce either, but PHPStan at level 6 will reject a list<int> returned from a function that can produce a gap in the integer keys, which is the failure that for ($i = 0; $i < count($a); $i++) turns into an undefined-index warning. Prefer foreach over index arithmetic for that reason alone.

Declarations, parameter and return types

2.1 Type Declarations

The full signature grammar, the semantics of void and never, and the rules the engine applies at each boundary.

Every parameter may declare a type, a default value, and whether it is passed by reference or promoted to a variadic. Every function declares at most one return type. A parameter with a default need not be optional at the call site unless it is followed only by other optional parameters — and since PHP 8.0 that "deprecated optional before required" signature is an error rather than a notice.

<?php

declare(strict_types=1);

// void: the function must not return a value. Returning one is a compile
// error; a bare `return;` is legal.
function log_line(string $line): void
{
    file_put_contents('php://stderr', $line . PHP_EOL, FILE_APPEND);
}

// never (8.1): the function cannot return normally. The engine verifies this
// for direct calls, and a return type of never accepts no return at all.
function fail(string $why): never
{
    throw new DomainException($why);
}

// never is the honest return type for a function whose body always
// aborts, and it removes the "missing return" class of TypeError.
function require_user(?int $userId): int
{
    return $userId ?? fail('authentication required');
}

// Nullable return: ?T is T|null, and is not the same as T with a null default.
function find_row(int $id): ?array { return null; }

// Union and intersection return types. Order in a union is irrelevant.
function first_of(array $rows): array|stdClass|null { return null; }

// Intersections describe a value that is several types at once (8.1).
function as_bag(Countable&Traversable $bag): int { return count($bag); }

// The class-relative types. `static` is late-bound: it means "the runtime
// class of the object", so a covariant override is permitted.
class Repo
{
    public function self(): self { return $this; }        // exactly Repo
    public function sibling(): static { return $this; }    // the actual subclass
}

// A default value must be a constant expression. Anything computed at run time
// is rejected, with the exception of `new` in initialisers (8.1) and
// of enum cases.
class Config
{
    public function __construct(
        public array $items = [],           // constant: fine
        public ?DateTimeImmutable $at = new DateTimeImmutable(),  // 8.1: fine
        public string $tz = date_default_timezone_get(),     // not constant: error
    ) {}
}

new in an initialiser creates one object at compile time and shares that instance across every invocation that uses the default. It is legal for immutable value objects such as a DateTimeImmutable; it is a live shared-mutable-state bug for anything else. Pass a nullable parameter and initialise it in the constructor body when the default must be per-call.

Applies to: scalar type declarations on parameters and returns are 7.0; void is 7.1; never is 8.1; pure intersection types are 8.1; DNF types are 8.2. Requirements: none — all of this is core language, with no extension dependency. Caveats: a union type may not include void, never, mixed or null as a standalone member, and callable may not be a property type or a union member, because a property holding a callable has no equivalent runtime representation.

Declare the return type even when you are certain of it. A declared array on a function that returns null on one path converts a silent downstream failure — a foreach over null — into a TypeError at the point the function is defined, which is a far cheaper place to find it.

References, variadics, named arguments and callables

2.2 Callable Type

The five mechanisms for controlling how arguments reach a function, and when each one is the right tool.

A parameter can be positional or named, variadic or fixed, by value or by reference, typed or untyped, and defaulted or required. These are independent axes. Named arguments (8.0) and first-class callables (8.1) are the two that most change how a codebase reads.

<?php

declare(strict_types=1);

// Variadics: the last parameter collects the remaining arguments.
// A variadic has no type declaration; its type lives in the docblock.
function total(string $currency, int ...$amounts): int
{
    /** @var list<int> $amounts */
    return array_sum($amounts);
}

echo total('EUR', 100, 250);   // 350: two arguments reached $amounts
echo total('EUR');                 // 0:   $amounts is []

// Named arguments (8.0): the argument name is the parameter name.
function connect(
    string $dsn,
    string $username = 'root',
    ?string $password = null,
    bool $persistent = false,
): bool { return true; }

connect(dsn: 'pgsql:host=db', password: null, persistent: true);

// Argument unpacking: a string-keyed array becomes named arguments.
$options = [dsn: 'pgsql:host=db', persistent: false];
connect(...$options);

// A positional argument after a named one is a compile error. An unpacking
// after a positional one is also an error. Both are rejected at compile time,
// so a refactor that changes argument order is caught, not silently applied.
// connect('pgsql:host=db', password: null);  // Compile error
// connect('pgsql:host=db', ...$options);     // Compile error

// First-class callable syntax (8.1) creates a validated Closure from any
// callable expression, without invoking it.
$fn     = strlen(...);              // Closure, not int
$method = ArrayObject::count(...);      // static method
$bound  = strlen(...);              // re-usable; no rebinding needed

$obj    = new ArrayObject([1, 2]);
$inst   = $obj->count(...);                // already bound to $obj
$full   = Closure::fromCallable([$obj, 'count']);

// FCCs carry the type signature of their target, so an analyser knows the
// parameter and return types of a value it was given as a string.
// The pipe operator in 8.5 relies on exactly this: see 2.4.

var_dump($fn('abc'));         // int(3)
var_dump($inst());              // int(2)
var_dump($full());              // int(2)

Named arguments couple the call site to the parameter names. Renaming a parameter is therefore a breaking change for every caller that used it by name, and a library that exposes named arguments in its public API is committing to those names. Many widely used libraries suppress this by adding an underscore prefix — function connect(string $dsn, ...) exposed as connect(dsn: ...) is fine, but the name is part of the contract either way.

Because named arguments match on name, a typo is a compile error rather than a silently misrouted value — but only if the call is written literally. When arguments arrive through unpacking, the array keys are checked at run time and an unknown key raises a Error. If a configuration array is splatted into a function, validate the keys first.

Prefer first-class callable syntax over string callable names. $f = 'strtoupper' is only checked when it is called, and a renamed or misspelled function produces a fatal error far from the assignment. $f = strtoupper(...) is validated at the point of assignment and carries the parameter and return types into the analyser.

Scope, static variables, closures and arrow functions

2.3 Closures and Scope

Function-local name resolution, the persistence of static locals, and the two closure forms.

PHP has function scope, not block scope. A variable declared in a if, a loop body or a foreach is available for the remainder of the function. A variable declared inside a closure or a method belongs to that function. Names not preceded by $ — constants, class names, function names — resolve in a global namespace unless the file declares namespace or the code uses a leading \.

Three constructs escape a function’s local scope. global $x imports a global variable into the local scope as an alias. The static keyword on a local variable gives it function-static lifetime rather than call-local lifetime: the value survives between calls of the same function, per function, not per global. A use clause on a closure imports variables by value or by reference at the moment the closure is created.

<?php

declare(strict_types=1);

$counter = 0;

// function-static: the initialiser runs once; the value persists per call site.
function next_id(): int
{
    static $id = 1000;
    return ++$id;
}

echo next_id();   // 1001
echo next_id();   // 1002: the previous value survived

// The persistence is per-function, not per-variable-name and not global.
function other_id(): int
{
    static $id = 1000;
    return ++$id;                // 1001: a separate static
}

// global imports a name as an alias. It does not create a copy.
function bump_counter(): void
{
    global $counter;
    $counter++;
}

bump_counter();
echo $counter;                  // 1

// A closure captures nothing by default; `use` is the capture list,
// evaluated when the closure is created.
$factor = 3;
$double = function (int $n) use ($factor): int {
    return $n * $factor;              // captures a copy of 3
};
$factor = 10;                           // too late: the closure kept 3
echo $double(5);                        // 15

$accumulate = function (int $n) use (&$total): void { $total += $n; };
$total = 0;
$accumulate(5);
$accumulate(7);
echo $total;                       // 12: captured by reference

// Arrow functions (7.4) capture by value automatically, from the
// defining scope, and the body is a single expression evaluated
// lazily. There is no `use` and no `return`.
$factor = 2;
$twice  = fn (int $n): int => $n * $factor;
echo $twice(5);                        // 10

// Auto-capture is by value, so an arrow function cannot mutate its scope:
$count = 0;
$incr  = fn () => $count++;           // $count is captured by value
$incr();
echo $count;                       // 0

// `static fn` makes every captured variable a shared reference rather
// than a per-closure copy: the right choice for memoised closures.
$memo = static fn (string $k): mixed => $cache[$k] ?? '-';

A static arrow function’s implicit captures are by-reference-with-shared-binding rather than by value, which is the correct semantic for a memoising closure. A non-static arrow function that appears in a loop captures a separate copy per iteration, so a collection of fn values built in a loop each keep their own snapshot of every variable.

The persistence of static locals is the single most surprising feature in this section. It makes a function impure in a way that no type declaration reveals, it survives request boundaries in long-running runtimes such as RoadRunner, Swoole or FrankenPHP workers, and it is shared between all callers of the function. A static local that caches an expensive computation and never invalidates it is a correctness bug in any long-lived process. Prefer an injected object with an explicit lifetime.

Use an arrow function when the body is one expression and no capture control is needed; use a closure with use when it is not. The performance difference is negligible and irrelevant next to readability, but the semantic difference is not: a closure with no use clause can see globals only, while an arrow function sees the defining scope automatically.

The callable type and the cost of dynamic dispatch

2.4 Dynamic Dispatch

What callable accepts, what it costs at run time, and the pipe operator that composes callables left to right.

callable is a runtime-checked type that accepts a function name string, an array of [object|class, method], a Closure, any object with an __invoke method, and a first-class callable. It is checked on assignment to a variable and on assignment to a parameter typed callable, but it cannot be a property type, and it carries no type information about the target’s signature.

Direct calls are compiled to a dedicated opcode. Dynamic calls through a variable holding a function name, and calls through call_user_func() and call_user_func_array(), are resolved at run time and are measurably slower. The gap is small in absolute terms for a single call and material in a loop executed millions of times, which is why the pipe operator’s design is specifically to avoid it.

<?php

declare(strict_types=1);

// The four callable forms, all interchangeable at the type level.
$a = 'strtoupper';                        // function name
$b = [ArrayObject::class, 'count'];     // [class, method]
$c = fn (string $s): string => '...';   // closure
$d = strtoupper(...);                      // first-class callable (8.1)

var_dump(is_callable($a), is_callable($b), is_callable($c), is_callable($d));

// Dynamic dispatch by name. Resolved at run time on every call.
function run_dynamic(string $name, string $input): string
{
    return $name($input);                 // slower than $name(...) with a Closure
}

// call_user_func() adds a second layer: it validates the callable, then
// dispatches dynamically. Prefer the direct call, or a Closure.
// $x = call_user_func('strtoupper', $s);
// $x = call_user_func_array('printf', ['%s', $s]);

// PHP 8.5: the pipe operator. `$value |> $callable` is exactly
// `$callable($value)`, compiled to a direct call for function, method and
// static-method first-class callables.
$result = '  Ada Lovelace  '
    |> trim(...)
    |> strtolower(...)
    |> (fn (string $s): string => str_replace(' ', '-', $s))
    |> ucfirst(...);

echo $result;                          // Ada-lovelace

// The right side must be a single-parameter callable. An arrow function
// must be parenthesised so the chain does not get captured by its body.
$names = ['ada', 'grace', 'alan'];
$sizes = $names |> array_map(strlen(...)) |> array_sum(...);
echo $sizes;                           // 11

// Restrictions, all of them real:
// explode('-', 'a-b-c') |> array_pop(...);   // Error: cannot pass by reference
// 1 |> strlen(...);                         // TypeError under strict_types
// $x |> 'strtoupper' |> trim(...);        // fine: a name string is a callable

Applies to: the pipe operator requires PHP 8.5 and is a parse error on 8.4 and earlier. It is left-associative, binds looser than arithmetic and tighter than comparison, and a chain is an expression, so it may appear inside a match arm, a property hook, or a function argument. A void callable mid-chain yields null for the rest of the chain; place it last.

Caveats: pass-by-reference parameters are rejected on the right of a pipe, because the piped value is not a nameable variable. The two exceptions are the core @prefer-ref functions array_multisort() and extract(), which accept a value and branch on whether it was passed by reference. An inline arrow function on the right of a pipe cannot be optimised away, so it costs one closure invocation per step; a first-class callable is compiled to a direct call and costs nothing.

Prefer the pipe operator to a chain of intermediate variables when the steps are single-parameter transforms, and to a wrapper class when they are not. It is composition syntax, not a replacement for method design: it reads left to right, which is the order data flows, and it removes the need to name a temporary for each intermediate result.

Error, Exception, Throwable and throw as an expression

The two exception hierarchies, the control-flow guarantees each gives, and the constructs added to the error model between 7.0 and 8.5.

Every abort in PHP is an instance of Throwable. The interface has two direct implementations: Error, for conditions the programmer cannot reasonably be expected to guard against, and Exception, for conditions that are part of the problem domain. Both are unchecked — PHP has no checked exceptions, and a throws clause is documentation, not enforcement.

class PaymentDeclined extends RuntimeException

Promoted constructor properties are declared with the same syntax as class promotion, so the promoted properties are public readonly string in the example above. A readonly promoted property cannot be written from inside the class after the constructor assigns it; that is the guarantee that makes it safe to cache.

<?php

declare(strict_types=1);

function render(array $rows): string
{
    try {
        foreach ($rows as $row) {
            if (!isset($row['id'])) {
                throw new UnexpectedValueException('row has no id');
            }
        }

        return count($rows) . ' rows';
    } catch (UnexpectedValueException|TypeError $e) {   // union type: 8.0
        // Catching Error here is almost always wrong: a TypeError is a bug,
        // and swallowing it converts a defect into wrong data.
        return 'invalid input: ' . $e->getMessage();
    } finally {
        // finally runs on the normal path, on the exception path, and on a
        // return inside try. It does not run after exit() or a fatal error.
        unset($row);
    }
}

// catch without a variable (8.0) skips the automatic assignment:
// try { risky(); } catch (RuntimeException) { report(); }

// Catching Throwable is the boundary pattern: it converts a fatal into a
// reportable outcome. Catching it in application code defeats the type system.
try {
    charge('A-9', false);
} catch (PaymentDeclined $e) {
    echo $e->getCode();                // 402
    echo $e->getReference();           // A-9: the promoted property
} catch (Throwable $unexpected) {
    // The only legitimate catch-all: the outermost boundary of the request.
    error_log($unexpected::class . ': ' . $unexpected->getMessage());
    http_response_code(500);
}

An exception unwinds the stack until it finds a matching catch; a finally block runs on the way out, and an uncaught exception ends the request with a fatal error. A finally containing return, break or continue discards the in-flight exception silently. A catch with no matching type is not a fallback — it propagates — so catch (Exception $e) does not catch a TypeError, and this is the change that broke most PHP 7 code during the 7.0 migration.

Throw the most specific exception that describes the failure and include the data needed to act on it as promoted properties, as in PaymentDeclined. A caller that can only produce a log line should not have to parse a message string. Reserve RuntimeException for failures with nothing to add.

Attributes versus docblock annotations

2.6 Annotations

The two metadata mechanisms, why both exist, and which one each tool reads.

Docblock annotations predate attributes and are understood by every analyser in the ecosystem. Attributes, added in 8.0, are the language’s own metadata syntax: parsed by the engine, retrievable through reflection, and consumable by any library. The two coexist because they solve different problems — docblocks are comments that a tool reads, attributes are data in the AST.

<?php

declare(strict_types=1);

// Attributes: first-class syntax, reflection-readable, no engine behaviour.
#[Attribute(Attribute::TARGET_CLASS | Attribute::IS_REPEATABLE)]
final class Route extends Attribute
{
    public function __construct(
        public readonly string $method,
        public readonly string $path,
    ) {}
}

#[Route('GET', '/health')]
#[Route('GET', '/ready')]
final class HealthController
{
    #[Route('GET', '/health/live')]
    public function live(): string { return 'ok'; }

    // Docblock metadata for the analyser only. The engine ignores all of it,
    // which is exactly why array shapes and generics live here.
    /**
     * @param array<string, array{id: int, name: non-empty-string}> $rows
     * @return list<int>
     * @phpstan-pure
     * @throws InvalidArgumentException when a row is malformed
     */
    public function ids(array $rows): array { return array_column($rows, 'id'); }
}

// Reading attributes back requires reflection and consumes the arguments
// as their declared types.
$routes = array_map(
    static fn(ReflectionAttribute $a): Route => $a->newInstance(),
    (new ReflectionClass(HealthController::class))->getAttributes(Route::class),
);

// A docblock-only tag such as @deprecated has no runtime representation at all;
// an attribute with no reader is equally inert. Neither is enforced by PHP.

An attribute class is instantiated only when newInstance() is called on the reflected attribute, and the class must not be required for the file to parse. Attributes cannot contain arbitrary expressions: the arguments are limited to constant expressions, so a new in an attribute argument is a compile error.

Applies to: attributes are 8.0. #[\Override] is 8.3 and is an engine-enforced attribute, not a docblock: the engine raises a compile error when a method marked #[\Override] overrides nothing. Caveats: because attributes are inert, a missing reader is indistinguishable from a missing attribute. Any attribute-based framework therefore needs a cache-warming or compile step, and a typo in an attribute name fails silently.

Use docblocks for everything the analyser must enforce — array shapes, generics, refined scalars, purity, pre-conditions — because that is what PHPStan and Psalm read. Use attributes for everything a library will read at run time — routing, validation, dependency-injection bindings, serialisation. Mixing the two for the same fact guarantees that one of the two consumers is out of date.

Class declaration, visibility and typed properties

3.1 Property Types

The class declaration grammar, the three visibilities, typed and readonly properties, and readonly classes.

A class declaration names a type and its members. Members may be properties, methods or constants, and each carries an optional visibility modifier, an optional static modifier and an optional abstract or final modifier. Visibility defaults to public; a property without a modifier is public and untyped, which is the single most common source of accidental public state in legacy PHP.

Typed properties arrived in 7.4 and cover every type the parameter grammar accepts except callable and void. A typed property is checked on assignment and on read, and a typed property that is never initialised is in an uninitialised state that is distinct from null: reading it throws an Error.

<?php

declare(strict_types=1);

class Account
{
    // Constants may be typed as of PHP 8.3. Before that they are untyped.
    public const string CURRENCY_DEFAULT = 'EUR';

    public function __construct(
        // Promoted properties: public, typed, and assigned by the constructor.
        public readonly string $id,
        private array $lines = [],
    ) {
        // $id is already assigned and cannot be written again, from
        // anywhere, including from inside this class.
    }

    // A typed property with no default is uninitialised until written. Reading
    // it before that throws Error: "must not be accessed before initialization".
    private int $version = 0;

    // A nullable typed property is initialised to null by default, so it is
    // readable immediately. Nullable and uninitialised are different states.
    protected ?string $label = null;

    public function rename(string $label): void
    {
        $this->label = $label;
        $this->version++;
    }

    public function version(): int { return $this->version; }
    public function label(): ?string { return $this->label; }
}

// A readonly class (8.2) applies readonly to every property and forbids
// dynamic properties. It cannot be extended by a non-readonly class, and
// it cannot have untyped or static properties.
readonly class Money
{
    // readonly is inherited by every property: no modifier is needed here.
    public function __construct(
        public int $amount,
        public string $currency,
    ) {}
}

$price = new Money(1000, 'EUR');
// $price->amount = 5;    // Error: cannot modify readonly property
// $price->extra  = 1;    // Error: readonly class has no dynamic properties

$a = new Account('ACC-1');
$a->rename('primary');

echo Account::CURRENCY_DEFAULT;      // EUR

private is not inherited-visibility: a private property or method of a parent is invisible to the child, so a child that declares a same-named member is a different member rather than an override. Caveats: a readonly property can be initialised only from the scope that declares it, which means a parent cannot initialise a readonly property declared in a child. A readonly property holding an object gives immutability of the reference only, not of the object: readonly Money $price still permits $price->setAmount(1) if that method exists.

Prefer promoted constructor properties over declaring a property and then assigning it in the constructor. It removes a class of omission bugs, it makes the parameter name the property name so named arguments and the promoted property agree, and it makes the mutability of each field visible on one line.

Constructors, promotion and new in initialisers

3.2 Constructor Promotion

The construction protocol, what the constructor is actually for, and the initialiser forms added since 8.1.

__construct is called after the object exists and after promoted properties are assigned. It is not a factory, and it is not where validation belongs if a static named constructor can express the rule. A constructor that can fail should throw; an object that is constructed and then immediately invalid is a state the type system will not protect you from.

PHP has no destructors that run deterministically. __destruct is called at script shutdown or when the refcount reaches zero, which under a cycle collector is not a predictable moment. Resource ownership belongs to an explicit close() or is delegated to an object with its own lifetime.

<?php

declare(strict_types=1);

final class Cart
{
    private array $lines = [];

    // Constructor promotion with default values and validation.
    public function __construct(
        public readonly string $currency = 'EUR',
        /** @var list<array{sku: string, qty: int}> $initial */
        private array $initial = [],
    ) {
        foreach ($initial as $line) {
            $this->add($line['sku'], $line['qty']);
        }
    }

    // A named constructor: the type is guaranteed valid because construction
    // either returns a Cart or throws. No half-built object exists.
    public static function fromRequestData(array $data): self
    {
        if (!isset($data['currency']) || !is_string($data['currency'])) {
            throw new InvalidArgumentException('currency is required');
        }

        return new self(currency: strtoupper($data['currency']));
    }

    public function add(string $sku, int $qty = 1): self
    {
        if ($qty < 1) {
            throw new OutOfRangeException('quantity must be at least 1');
        }

        $this->lines[$sku] = ($this->lines[$sku] ?? 0) + $qty;

        return $this;                            // fluent: $cart->add(..)->add(..)
    }

    public function total(): int { return array_sum($this->lines); }
}

// new in initialisers (8.1) and in constant expressions. Three places:
// parameter defaults, static variable initialisers, global constants.
function cache(): array
{
    static $store = new ArrayObject();   // one shared instance
    $store['k'] = 1;

    return $store->getArrayCopy();
}

const BOOTED_AT = new DateTimeImmutable('2026-01-01', new DateTimeZone('UTC'));

// 8.4 allows new without parentheses around the method call on the result,
// so this is valid where 8.3 required the extra parentheses:
// $query->getConnection()->prepare($sql);

A static variable initialised with new is created once and shared by every subsequent call, exactly as a scalar static local would be. This makes it a convenient one-shot cache and an equally convenient cross-request state leak in a long-running worker. Prefer an explicit object passed in by the caller.

Returning $this from a mutator makes an object chainable and, if the mutator is also a getter, makes it ambiguous: $cart->add('A')->add('B')->total() works, but so does $cart->add('A')>lines if the property were public. Keep mutators returning static and accessors returning values, and never expose the internal collection by reference.

Named constructors such as fromX() and tryFromX() are the PHP idiom for "the object is valid or it does not exist". They give static analysers a precise return type of self instead of ?self, and they keep a partially-initialised object from ever being observable.

Methods, statics, this, final and class-relative names

3.3 Methods

Instance state versus shared state, the three class-relative keywords, and when final is a design tool rather than a restriction.

A non-static method has a $this, the instance the method was invoked on. A static method has none and is bound to the class; it may not read $this, and a static method may not be called on an instance. A static property is shared by every instance and by the class itself, and it is declared with static and may be initialised with a constant expression.

Three class-relative keywords appear in signatures and bodies, and they are not interchangeable. self resolves at compile time to the declaring class. static resolves at run time to the class of the current object, which is what makes covariance work. parent resolves to the direct parent.

<?php

declare(strict_types=1);

class Repository
{
    // A static property is shared by every instance. It is the closest thing
    // PHP has to a global, and carries all of the global's drawbacks.
    private static int $queryCount = 0;

    // static:: is late-bound: inside a subclass it refers to the subclass,
    // which is what allows this factory to return the right type.
    public static function make(PDO $pdo): static
    {
        return new static($pdo);                    // not `new self`
    }

    public function __construct(protected PDO $pdo) {}

    public function query(string $sql): PDOStatement
    {
        self::$queryCount++;

        return $this->pdo->query($sql);          // self:: for the shared counter
    }

    public static function queryCount(): int { return self::$queryCount; }

    // final prevents overriding. It is a design decision: it says the
    // behaviour of this method is part of the contract, not an extension point.
    final public function transaction(callable $work): mixed
    {
        $this->pdo->beginTransaction();

        try {
            $result = $work($this);
            $this->pdo->commit();

            return $result;
        } catch (Throwable $e) {
            $this->pdo->rollBack();

            throw $e;
        }
    }
}

final class SqlRepository extends Repository {}

$r = SqlRepository::make(/* PDO */ $pdo);
var_dump($r instanceof SqlRepository);   // true: static:: resolved late

// $r->queryCount();    // Error: calling a static method on an instance
// $r::queryCount();     // Error: calling a non-static method statically
KeywordResolvesConsequence
selfCompile time, to the declaring classCannot be narrowed by a subclass; use for shared state
staticRun time, to the class of the objectEnables covariant returns and self-returning factories
parentCompile time, to the direct parentCannot skip a level; use for explicit super calls

Caveats: a static method is not overridable in the late-bound sense unless it is called through static:: or self:: from an instance context; calling it as self::method() from an instance method is fine, calling it as ClassName::method() where ClassName is a variable is not. Static properties are not inherited as separate storage: a subclass writing to self::$count writes to the parent’s property, because self is the declaring class. A redeclaration in the subclass creates a second, distinct property.

Mark a class or method final when the ecosystem is expected to extend it without understanding it — value objects, DTOs, exceptions. Leave it open when extension is a design goal. final on a class is also a performance property: the engine can devirtualise calls to final methods, which is measurable in hot loops.

Property hooks and the magic-method fallback

3.4 Magic Methods

The 8.4 property hook system, the set shorthand, and the case for keeping __get and __set out of ordinary code.

PHP 8.4 replaced a property that is really a pair of accessor methods with a declaration that keeps the property syntax. A hooked property still behaves as a property to callers — $obj->name — while the class decides how the value is computed and validated. This removes the most common argument against accessors, which is that they change the call syntax and break every existing caller.

A property may declare a get hook, a set hook, both, or neither. A property with neither is an ordinary property. A property with only a get hook is read-only: assigning to it is a compile error. The set shorthand takes a single parameter, which is the incoming value, and a get shorthand takes none and returns the value directly.

<?php

declare(strict_types=1);

final class Temperature
{
    // Backed storage. It is private, so only this class can touch it, and it
    // is not part of the public surface the hooks present.
    private float $celsius;

    // Full hooks: a computed property. Reading validates and derives;
    // the get hook runs on every read, so keep it cheap.
    public float $kelvin {
        get => $this->celsius + 273.15;
    }

    // Shorthand hooks: `get => expression` with no braces for a direct
    // derivation, `set => expression` for a bare assignment to other state.
    public float $fahrenheit {
        get => $this->celsius * 9 / 5 + 32;
        set => $this->celsius = (float $value - 32) * 5 / 9;
    }

    // A write-only property: valid in PHP as a set hook with no get hook,
    // and reading it is a compile error.
    public string $label {
        set => $this->label = trim($value);
    }

    // A virtual property with no storage at all.
    public int $freezerAlert {
        get => $this->celsius <= -18 ? 1 : 0;
    }

    public function __construct(float $celsius) { $this->celsius = $celsius; }
    public function celsius(): float { return $this->celsius; }
}

$t = new Temperature(-20.0);
echo $t->kelvin;                    // 253.14999999999998: float arithmetic
$t->fahrenheit = 32.0;
echo $t->celsius();                 // 0.0: the setter converted back
echo $t->freezerAlert;              // 0

// Asymmetric visibility (8.4) is the narrow case: a public getter with a
// private setter, without a hook on either side.
final class Settings
{
    public private(set) string $locale = 'en';
    public protected(set) int $retries = 3;
}

A set hook receives the value as its single parameter, named $value by convention. The shorthand set => $this->label = trim($value) is a full body: it does not declare the type, so the declared property type is still enforced on assignment. The engine checks the type before the hook runs and the result of the hook after.

Property hooks change performance characteristics in both directions. A hooked property read is a method call, not a memory load, so a hook inside a hot loop is a measurable cost; conversely, a hook that caches its result can be faster than a property that is re-read from a cold cache. More importantly, get hooks may run more than once for a single expression in some engine versions, so a hook with a side effect is a defect. Hooks must be pure.

The magic methods remain, and remain necessary where hooks are not applicable. __get and __set are the older mechanism for the same problem and should be the last resort: they are invisible to every analyser, they are triggered by inaccessibility rather than by absence, and they interact with isset() and unset() in ways that are easy to get wrong. __call and __callStatic remain the only way to expose a method dynamically, which is also how most RPC and ORM clients are implemented.

The magic methods are a compatibility surface for existing libraries, not a design vocabulary.

Inheritance, abstract classes and interfaces

3.5 Interfaces

Single inheritance, when an abstract class is the right contract, and why interface hierarchies are preferable to class hierarchies.

PHP classes extend at most one parent. An abstract class exists to be extended: it may declare abstract methods with no body, and it may hold shared state and shared implementation. An interface declares only method signatures and constants; it holds no state, cannot be instantiated, and any number may be implemented by one class.

The distinction is a design one. A class hierarchy encodes is-a; an interface encodes can-do. A hierarchy of six or more classes is fragile for reasons that are structural rather than stylistic: every added level couples every subclass to every ancestor, overriding becomes a source of surprises, and a change at the top of the tree requires reading the whole tree.

<?php

declare(strict_types=1);

// An interface is a contract. It carries no state, and PHP 8.1 removed
// the ability to declare properties in one, so an interface can never leak
// storage obligations onto its implementors.
interface Identifiable
{
    public function id(): string;
    public const int PREFIX = 'id_';   // typed constants: 8.3
}

interface Clock { public function now(): DateTimeImmutable; }
interface Serialisable { public function toArray(): array; }

// Multiple interfaces, one parent class. This combination is the reason
// PHP has single class inheritance and no problem: the capability axes
// are orthogonal, so they belong in interfaces.
final class Invoice extends Model implements Identifiable, Clock, Serialisable
{
    public function __construct(
        public readonly string $number,
        private array $lines = [],
    ) {}

    public function id(): string { return self::PREFIX . $this->number; }
    public function now(): DateTimeImmutable { return new DateTimeImmutable('now', new DateTimeZone('UTC')); }
    public function toArray(): array { return ['id' => $this->id(), 'lines' => $this->lines]; }
}

// An abstract class carries the implementation that every subclass shares.
abstract class Model
{
    abstract public function id(): string;   // no body
    abstract protected function table(): string;

    public function toArray(): array
    {
        // Shared behaviour, defined once, using the subclass's answers.
        return ['id' => $this->id(), 'table' => $this->table()];
    }

    protected function label(): string { return $this->table() . '#' . $this->id(); }
}

// instanceof answers against the whole hierarchy, interfaces included,
// and it is the check to use before a type-specific call.
$i = new Invoice('2026-0001');
var_dump($i instanceof Invoice, $i instanceof Model, $i instanceof Clock);

// A class may also be named as a string, which is what class_exists checks.
var_dump(is_a($i, Serialisable::class));

An interface may declare constants, and a class implementing several interfaces that declare the same constant name is a fatal error unless the class resolves the conflict explicitly. Interface methods have no visibility in the signature — they are implicitly public, and an implementation cannot reduce visibility.

Deep hierarchies fail in three specific ways. Constructor coupling: a subclass must call parent::__construct() with arguments it does not control, so a change to the parent’s signature breaks every descendant. Override drift: a child overriding a method that calls an overridden method produces behaviour that neither class documents. Inverted dependencies: the deepest subclass is coupled to the base, so a runtime type check becomes the only escape hatch. The fix is composition: inject a collaborator rather than extend a base to reach its behaviour.

A useful test: if a proposed subclass overrides no method and adds no state, it should be a type alias or a docblock generic, not a class. If it overrides one or two methods and reuses the rest, an abstract class is right. If it shares no implementation at all, it is an interface. Two levels of class inheritance is a reasonable ceiling; beyond that, prefer composition.

Traits, generic docblocks and enums

3.6 Traits

Code reuse without inheritance, the static-analyser substitute for generics, and the enum type added in 8.1.

A trait is a bundle of methods and properties copied into the using class at compile time. It is not a type: a class using a trait is not an instance of the trait, and a parameter typed as the trait accepts nothing. What a trait provides is code reuse across an unrelated class hierarchy, and what it costs is that the origin of each method is invisible at the use site.

Because a trait copy is a flat merge, two traits that define the same method is a fatal error unless the conflict is resolved explicitly. insteadof selects one implementation and as aliases the other under a new name, so both remain callable.

<?php

declare(strict_types=1);

trait Timestamped
{
    private DateTimeImmutable $createdAt;

    public function createdAt(): DateTimeImmutable { return $this->createdAt; }
    public function describe(): string { return $this->createdAt->format('c'); }
}

trait SoftDeletable
{
    private ?DateTimeImmutable $deletedAt = null;

    public function delete(): void { $this->deletedAt ??= new DateTimeImmutable(); }
    public function isDeleted(): bool { return $this->deletedAt !== null; }

    // Conflicts with the trait's own describe().
    public function describe(): string { return 'deleted'; }
}

class Post
{
    use Timestamped, SoftDeletable {
        // insteadof discards SoftDeletable::describe(); as keeps it callable
        // under a second name. Both halves are required together.
        SoftDeletable::describe insteadof Timestamped;
        Timestamped::describe as createdDescription;
    }

    public function __construct() { $this->createdAt = new DateTimeImmutable(); }
    public function createdDescription(): string { return $this->createdDescription(); }
}

// Traits have no runtime identity. These are all false:
// $p instanceof Timestamped;   // false
// $p instanceof SoftDeletable; // false
// in_array(Timestamped::class, class_uses($p)); // true: reflection only

// A trait may also alter visibility and add abstract requirements:
trait RequiresSlug
{
    abstract public function slug(): string;
    private function cachedSlug(): string { return $this->slug(); }
}

A conflict is reported as a fatal error at compile time, not as a warning, which is a useful property: a trait combination that is ambiguous never runs. The insteadof and as clauses are resolved in the use statement of the class, and they affect only that class.

A trait can override a method the class itself defines, and a method defined in the class always wins over a trait method — without any diagnostic. A trait property with the same name as a class property is a fatal error only when the initialisers differ. The practical rule: keep traits small, single-purpose, and free of private state that the class also needs, because the collision surface grows with every member.

PHP has no generic types. A docblock is the substitute, and it is a real contract under PHPStan or Psalm even though the engine ignores it. Generic annotations on a class, an interface or a function tell the analyser what the type parameter must be at each use site, and violations are reported at the call rather than discovered later.

<?php

declare(strict_types=1);

/**
 * A generic interface. TKey and TValue are the type parameters, and every
 * implementation must bind both to concrete types.
 *
 * @template TKey of array-key
 * @template TValue
 */
interface Repository
{
    /**
     * @param TKey $id
     * @return TValue|null   null when absent, so absence is not an exception
     */
    public function find(int|string $id): mixed;

    /** @return array<TKey, TValue> */
    public function all(): array;
}

/**
 * @implements Repository<int, User>
 */
final class UserRepository implements Repository
{
    /** @var array<int, User> */
    private array $rows = [];

    /** @return User|null */
     */
    public function find(int|string $id): mixed { return $this->rows[$id] ?? null; }

    /** @return array<int, User> */
     */
    public function all(): array { return $this->rows; }
}

// Backed enums (8.1): a closed set of named values with a scalar backing type.
enum Status: string
{
    case Draft     = 'draft';
    case Published = 'published';
    case Archived  = 'archived';

    // Enums may have constants and methods, but no properties.
    public const DEFAULT = 'draft';

    public function isVisible(): bool { return $this !== self::Archived; }
    public function label(): string { return ucfirst($this->value); }
}

// Pure enums have no backing type and cannot be serialised to a scalar.
enum Unit { case Metric; case Imperial; }

$s = Status::from('published');          // throws ValueError if absent
$s = Status::tryFrom('nope') ?? Status::Draft;  // null if absent

// cases() enumerates, in declaration order. match is exhaustive over an enum.
foreach (Status::cases() as $case) { echo $case->name, '=', $case->value, ' '; }

echo match ($s) {
    Status::Draft     => 'editable',
    Status::Published => 'live',
    Status::Archived  => 'hidden',
};                                                     // no default: exhaustive

A backed enum is a singleton per case, so identity comparison (===) and match are exact; there is no way to construct a second instance of a case. An enum is also final, cannot be extended, and cannot hold state — if a value needs to carry data, use a backed enum plus a value object rather than adding properties to the enum.

OperationBacked enumPure enum

Enumerating an enum with match and no default is statically exhaustive: the analyser reports a missing arm as soon as a case is added, which makes match the correct exhaustive dispatch for an enum and a bug source when a default is added. Because an enum instance is not serialisable to a scalar by default, a pure enum crossing a process boundary needs a name-based adapter on both sides.

Prefer an enum to a class of string constants whenever the value set is closed and known at compile time. The gain is not brevity: it is that the analyser treats a parameter typed as the enum as exhaustive at every match, and a missing case becomes a build failure instead of a fall-through.

PHP has no built-in module system. Namespaces provide logical grouping, an autoloader provides physical discovery, and Composer ties the two together with a declarative manifest. Together they determine how code is found, how dependencies are resolved, and whether a codebase can be reasoned about at scale.

4.1 Namespaces and the fully-qualified name

4.1 Use Statements

A namespace maps a class, function or constant name onto a hierarchical, slash-separated identifier. It is declared once per file and applies to every unqualified name in that file. The fully-qualified name, prefixed with a single backslash, is the absolute name the engine resolves to.

// src/Billing/Invoice.php
<?php

declare(strict_types=1);

namespace App\Billing;   // applies to the whole file

final class Invoice
{
    // Unqualified:      Invoice
    // Qualified:        Billing\Invoice        (relative to current namespace)
    // Fully-qualified:  \App\Billing\Invoice   (absolute)

    public function self::label(): string { return 'invoice'; }
    public function qualified(): string { return Billing\Invoice::label(); }
    public function absolute(): string { return \App\Billing\Invoice::label(); }
}

Three ways to name the same class from inside its own namespace. Only the fully-qualified form is absolute, which is why it is the form used in generated code and strings.

Applies to: all supported versions. Note: a namespace declaration must be the first statement in the file, preceded only by a declare. Code before it is a parse error.

4.2 Imports, aliasing and the backslash rule

4.2 Aliasing

The use statement binds a local alias to a fully-qualified name. It is a compile-time alias, not a runtime import: no file is loaded and no class is instantiated. Aliasing with as keeps call sites short when two dependencies expose colliding short names.

<?php

declare(strict_types=1);

namespace App\Service;

use App\Billing\Invoice;                     // alias Invoice   -> \App\Billing\Invoice
use App\Billing\Invoice as BillingInvoice;   // alias BillingInvoice
use App\Support\Collection;                // no conflict, imported plainly
use App\Support\Collection as Bag;
use function App\Support\money;            // importing a function
use const App\Support\DEFAULT_CURRENCY;    // importing a constant

function total(Bag $items): string
{
    return money(DEFAULT_CURRENCY, $items->sum());
}

// THE RULE: an unqualified name inside a namespaced file resolves to the
// current namespace first, then the global namespace. A leading
// backslash forces the global namespace.
echo strlen('abc');      // App\Service\strlen  -> not found, falls back to \strlen
echo \strlen('abc');     // \strlen            -> guaranteed global
echo \Exception::class;   // the one global name worth memorising

use creates aliases at compile time. The backslash rule is the classic source of "class not found" errors: a bare name in a namespaced file is looked up in that namespace first.

Never define a function or class named the same as a global one and rely on the fallback. A namespaced count() will silently take precedence over the global count() for unqualified calls in that file, producing results that are difficult to trace.

4.3 PSR-4 autoloading

4.3 Autoload Configuration

PSR-4 defines a single mapping rule: a namespace prefix maps to a base directory, and the remaining namespace segments become path segments with a .php suffix. The engine has no built-in loader, so something must register one.

// psr4.php — a minimal, correct PSR-4 autoloader
<?php

declare(strict_types=1);

spl_autoload_register(static function (string $class): void {
    // Strip the vendor namespace; only our own code is handled here.
    $prefix = 'App\\';
    $baseDir = __DIR__ . '/src/';

    if (!str_starts_with($class, $prefix)) {
        return;
    }

    // App\Billing\Invoice -> src/Billing/Invoice.php
    $relative = substr($class, strlen($prefix));
    $file = $baseDir . str_replace(\\, '/', $relative) . '.php';

    if (is_file($file)) {
        require $file;
    }
});

The mapping is mechanical: strip the prefix, turn backslashes into directory separators, append .php. Composer generates an optimised equivalent from composer.json.

4.6 Composer scripts and environment configuration

4.6 Scripts

Composer scripts are the conventional place for project tasks, so that a contributor needs one tool rather than a written list of shell commands. Environment configuration is a separate concern and must never be committed.

// .env.example — committed, contains no real values
APP_ENV=dev
APP_DEBUG=1
DB_DSN="mysql:host=127.0.0.1;dbname=app;charset=utf8mb4"
DB_USER=app
DB_PASSWORD=
// .env is gitignored. Never commit real credentials or a filled .env.

// config/env.php
<?php

declare(strict_types=1);

use Dotenv\Dotenv;

require_once __DIR__ . '/../vendor/autoload.php';

Dotenv::createImmutable(dirname(__DIR__))->safeLoad();

    'dsn'      => $_ENV['DB_DSN'],
    'user'     => $_ENV['DB_USER'],
    'password' => getenv('DB_PASSWORD'),   // prefer the real environment in production

// PUBLISH when
//   - two or more projects will use the code
//   - the code has a stable public surface (classes, functions, exceptions)
//   - you want a versioned, checksummed, immutable artefact
//   - you want it installable with one line and no manual setup
//
// DO NOT PUBLISH when
//   - it is application code. an internal service is not a library.

//   - the API is still changing weekly. a published version is a promise
//     and you cannot take it back without breaking someone
//   - you are publishing to make a private dependency "look" available.
//     a path repository or a private registry does that honestly.

// THE COMMITMENT
//   Packagist is a public registry with a global cache. A published
//   version is permanent. You can yank a release, but every project
//   that installed it keeps it, and Packagist may already have served
//   the metadata to thousands of machines.

                works on 8.1 and 8.4 must say so, or someone will debug
                your library on 8.4
  autoload      how consumers find your classes. must be PSR-4 (below)

// THE CONSTRAINT RANGES, and this is where most packages go wrong

  "php": ">=8.2"                    fine, but permissive
  "php": "^8.2"                      means >=8.2 <9.0. preferred
  "php": "~8.2.0"                    >=8.2.0 <8.3.0. only for a patch series
  "psr/http-message": "^2.0"         the right form
  "psr/http-message": "^1.0|^2.0"    support both, correctly
  "monolog/monolog": "*"             NEVER. "*" means "any version ever",
                                      including a breaking 4.0 next year.
                                      use "^3.0" or a range you have tested
  "guzzlehttp/guzzle": "dev-main"     NEVER in a published package. you are
                                      telling every consumer to run your
                                      unreviewed branch

// the rule: your constraints must state the range you have actually
// tested. not the range you hope works.

The PSR-4 autoload rule for a library

PSR-4 is the single most important line in a publishable `composer.json`, and getting it wrong produces an error only your users will see.

// PSR-4: the namespace prefix maps to a directory
"autoload": { "psr-4": { "Amin360iT\\HttpClient\\": "src/" } }

// the rule, precisely
//   namespace Amin360iT\HttpClient;  in  src/Client.php
//   so:       src/ + Client.php
//   the namespace MINUS the prefix maps to the path relative to src/

Amin360iT\HttpClient\Client          ->  src/Client.php
Amin360iT\HttpClient\Retry\Policy   ->  src/Retry/Policy.php
Amin360iT\HttpClient\Exception\Failure -> src/Exception/Failure.php

// the three mistakes

// 1. a trailing backslash in the namespace
namespace Amin360iT\HttpClient;      // correct
namespace Amin360iT\HttpClient\;     // fatal error, and a confusing one

// 2. the directory does not match the case
// on Linux this fails. "src/client.php" does not satisfy
// "src/Client.php". macOS and Windows will not tell you.
src/
  Client.php        // capital C, matching the class

// 3. tests in src/
"autoload":       { "psr-4": { "Amin360iT\\HttpClient\\": "src/" } },
"autoload-dev":  { "psr-4": { "Amin360iT\\HttpClient\\Tests\\": "tests/" } }
// require-dev autoload is only loaded for the root project, so your
// test namespace never ships to consumers. That is the point.

// VERIFY IT, from a clean directory. This is the check that catches all three.
mkdir /tmp/consumer && cd /tmp/consumer
composer init --name=me/test --no-interaction
composer config repositories.local path /path/to/your/lib
composer require amin360it/http-client:@dev
php -r "require 'vendor/autoload.php'; var_dump(class_exists(Amin360iT\HttpClient\Client::class));"

Test your package by installing it into a throwaway project from a path repository before you publish. It takes two minutes and it catches every autoload mistake, every missing dev dependency, and every "works on my machine" file-path assumption. A published package that fails to load cannot be fixed retroactively for anyone who already tried it.

Git tags, branch aliases and versions

Packagist reads versions from your VCS. The mapping is not obvious the first time, and getting it wrong publishes the wrong version numbers.

// THE STABILITY FLAGS, which are Composer 2's default and a common surprise
//   dev-main        ->  1.5.x-dev   (minimum-stability dev by default)
//   dev-feature-x   ->  dev-feature-x
//   alpha, beta, RC ->  1.5.0-beta1, 1.5.0-RC1

Versioning and the stability flags

// semantic versioning, as Composer interprets it
//   MAJOR.MINOR.PATCH
//   1.4.0  ->  ^1.4 allows >=1.4.0 <2.0.0
//   1.4.3  ->  ~1.4 allows >=1.4.3 <1.5.0
//   *      ->  any version, including a future 2.0

// what forces a MAJOR bump
//   removing or renaming a public class, interface, method or function
//   changing a method signature
//   changing a parameter type
//   removing a public constant
//   changing a documented exception type
//   making an abstract class concrete (or the reverse)
//   CHANGING THE BEHAVIOUR of an existing method
//
// what is a MINOR
//   adding a new class, method or function
//   adding a new optional parameter with a default
//   widening an accepted type
//   relaxing a validation rule
//   adding a new feature behind a default-off flag
//
// what is a PATCH
//   bug fixes that do not change the contract
//   documentation, internal refactoring, performance
//   dependency constraint widening that stays compatible

// THE RULE THAT PREVENTS MOST MISTAKES
//   if a consumer following your documented upgrade path has to change
//   their code, it is a MAJOR change. if they can upgrade by changing
//   one number in composer.json and running an update, it is MINOR.

// pre-release

// and it is why you can ship betas safely to people who opt in.

5.1 Connecting with PDO

PDO is the portable database layer built into PHP. It presents one interface over MySQL, PostgreSQL, SQLite, SQL Server and others. The DSN carries the driver, host, database and character set; credentials are passed separately so they never appear in a connection string that might be logged.

<?php

declare(strict_types=1);

final class Database
{
    public function __construct(private readonly PDO $pdo) {}

    public static function connect(string $dsn, string $user, string $password): self
    {
        // ERRMODE_EXCEPTION turns SQL errors into exceptions, so failures are
        // never silently ignored. This is not the default and must be set.
        $pdo = new PDO($dsn, $user, $password, [
            PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            PDO::ATTR_EMULATE_PREPARES   => false,  // real server-side prepares
        ]);
        return new self($pdo);
    }

    public function pdo(): PDO { return $this->pdo; }
}

// MySQL:    utf8mb4 is the only charset that stores all of Unicode.
$mysql = Database::connect(
    'mysql:host=127.0.0.1;dbname=shop;charset=utf8mb4', 'app', getenv('DB_PASSWORD') ?: ''
);

// PostgreSQL
$pgsql = Database::connect('pgsql:host=127.0.0.1;dbname=shop', 'app', getenv('DB_PASSWORD') ?: '');

// SQLite: a file, no server. Ideal for tests and local development.
$sqlite = Database::connect('sqlite:' . __DIR__ . '/app.sqlite', '', '');

Three DSNs, one interface. The two settings that are not defaults and change behaviour substantially are ERRMODE_EXCEPTION and EMULATE_PREPARES => false.

Caveat: with ATTR_EMULATE_PREPARES left at its default of true, PDO sanitises and interpolates the SQL in PHP rather than sending it to the server. Integer and string binding then relies on PHP’s own quoting, which has a long history of edge cases. Setting it to false makes the driver perform true server-side prepared statements.

5.2 Prepared statements and parameter binding

A prepared statement separates the SQL structure from the data. The SQL is sent once and parsed by the database engine; the values travel separately and can never alter the statement’s meaning. This is the mechanism that makes injection structurally impossible rather than merely unlikely.

<?php

declare(strict_types=1);

// Positional placeholders: ?
$stmt = $pdo->prepare('SELECT id, email FROM users WHERE status = ? AND country = ?');
$stmt->execute(['active', 'GB']);
$rows = $stmt->fetchAll();

// Named placeholders: :name. Readable, and order-independent.
$stmt = $pdo->prepare('SELECT id, email FROM users WHERE status = :status AND country = :country');
$stmt->execute(['status' => 'active', 'country' => 'GB']);

// Explicit binding when the driver needs the type. Crucially,
// PDO::PARAM_INT prevents '1 OR 1=1' being compared as an integer.
$stmt = $pdo->prepare('SELECT * FROM users WHERE id = :id');
$stmt->bindValue(':id', $_GET['id'], PDO::PARAM_INT);
$stmt->execute();

// Writing: named parameters, never string concatenation.
$stmt = $pdo->prepare(
    'INSERT INTO users (email, status, created_at) VALUES (:email, :status, :now)'
);
$stmt->execute([
    'email'  => $email,
    'status' => 'active',
    'now'    => gmdate('Y-m-d H:i:s'),
]);
$newId = $pdo->lastInsertId();   // string, cast deliberately

Positional for short fixed queries, named when the parameter list is long or the order might change, explicit binding wherever the value came from user input.

5.3 SQL injection and the parameterisation defence

Injection occurs when data is concatenated into SQL text and the data itself contains SQL syntax. The correct defence is structural: do not build SQL with concatenated input. Escaping functions are a second line of defence that is easy to apply incorrectly and should not be the primary mechanism.

<?php

declare(strict_types=1);

// VULNERABLE: an attacker sending ' OR '1'='1 retrieves every row,
// and a stacked statement may modify data depending on the driver.
$name = $_GET['name'] ?? '';
$rows = $pdo->query("SELECT * FROM users WHERE name = ' . $name . "'")->fetchAll();

// DEFENCE 1 (structural, preferred): the value never enters the SQL text.
$stmt = $pdo->prepare('SELECT * FROM users WHERE name = :name');
$stmt->execute(['name' => $name]);
$rows = $stmt->fetchAll();

// DEFENCE 2 (quoting): only when a statement cannot be prepared, and
// only with a correctly chosen quote character for the driver.
$quoted = $pdo->quote($name, PDO::PARAM_STR);
$rows = $pdo->query('SELECT * FROM users WHERE name = ' . $quoted)->fetchAll();

// IDENTIFIERS CANNOT be bound. Table and column names must be
// checked against an allowlist - this is the correct pattern.
$sortable = ['created_at' => 'created_at', 'email' => 'email'];
$column   = $sortable[$_GET['sort'] ?? ''] ?? 'created_at';
$order    = str_starts_with($_GET['dir'] ?? 'asc', 'd') ? 'DESC' : 'ASC';

$stmt = $pdo->prepare("SELECT id, email FROM users ORDER BY {$column} {$order} LIMIT 50");
$stmt->execute();

Values are bound; identifiers are allowlisted. The allowlist substitutes a known-good name, so the interpolated text can only ever be one of a fixed set.

Modern PHP has no reason to concatenate any value into SQL. If a query cannot be prepared, the cause is usually a dynamic identifier or an IN list of variable length. The first is solved by an allowlist; the second by generating a correctly sized placeholder list.

5.4 CRUD mechanics and result fetching

PDO exposes three execution methods and several result-fetching modes. Choosing the wrong one is a common source of confusion, particularly around rowCount(), which reports affected rows rather than returned rows.

<?php

declare(strict_types=1);

$db = $pdo;

// CREATE - returns the generated id
$stmt = $db->prepare('INSERT INTO orders (customer_id, total) VALUES (?, ?)');
$stmt->execute([$customerId, $total]);
$orderId = (int) $db->lastInsertId();

// READ - fetch styles
$stmt = $db->prepare('SELECT id, total FROM orders WHERE customer_id = ?');
$stmt->execute([$customerId]);

$all   = $stmt->fetchAll();                    // array of arrays
$first = $stmt->fetch();                      // one row or false
$total = $stmt->fetchColumn();               // first column, one row
$obj   = $stmt->fetchObject();               // stdClass, column names as properties

// UPDATE - rowCount() is meaningful here: it counts affected rows.
$stmt = $db->prepare('UPDATE orders SET status = ? WHERE id = ?');
$stmt->execute(['shipped', $orderId]);
$affected = $stmt->rowCount();

// An IN list of variable length: build placeholders, not values.
$ids = [3, 17, 42];
$placeholders = implode(',', array_fill(0, count($ids), '?'));
$stmt = $db->prepare("SELECT id FROM orders WHERE id IN ({$placeholders})");
$stmt->execute($ids);

// DELETE
$stmt = $db->prepare('DELETE FROM orders WHERE id = ?');
$stmt->execute([$orderId]);

Caveat: rowCount() returns the number of rows changed by an UPDATE or DELETE, and is not defined for SELECT on many drivers. To count a SELECT result, use COUNT(*) in the query itself.

5.5 Transactions and savepoints

A transaction guarantees that a group of statements either all apply or none do. The reliable pattern is to put the commit inside the try and the rollback in finally, so an exception can never leave a transaction open.

<?php

declare(strict_types=1);

function transfer(PDO $db, int $from, int $to, int $cents): void
{
    $db->beginTransaction();
    try {
        $debit = $db->prepare('UPDATE accounts SET balance = balance - ? WHERE id = ?');
        $debit->execute([$cents, $from]);

        $debit->rowCount() === 1 || throw new RuntimeException('no such account');

        $credit = $db->prepare('UPDATE accounts SET balance = balance + ? WHERE id = ?');
        $credit->execute([$cents, $to]);

        $db->commit();
    } catch (Throwable $e) {
        if ($db->inTransaction()) {
            $db->rollBack();
        }
        throw $e;   // never swallow; let the caller decide
    }
}

// Savepoints allow partial rollback within one transaction.
$db->beginTransaction();
$db->exec('INSERT INTO audit (action) VALUES (?)', ['start']);
$db->exec('SAVEPOINT sp1');

$db->exec('INSERT INTO audit (action) VALUES (?)', ['speculative']);
$db->exec('ROLLBACK TO SAVEPOINT sp1');   // undoes only the speculative row

$db->commit();

Checking the affected-row count for a debit is what stops a transfer to a non-existent account from silently crediting the other side.

5.6 ORMs, N+1 and when to write raw SQL

An ORM trades explicitness for convenience. It earns its place in domains with deep object graphs and simple persistence rules, and becomes a liability when queries need to be predictable, tunable, or reviewable by someone who does not know the ORM.

<?php

declare(strict_types=1);

final class OrderRepository
{
    public function __construct(private readonly PDO $db) {}

    // Lazy loading: each access to $order->customer issues a query.
    // Rendering 20 orders produces 21 queries. This is the N+1 problem.
    public function findLazy(int $id): array
    {
        $stmt = $this->db->prepare('SELECT * FROM orders WHERE id = ?');
        $stmt->execute([$id]);
        return $stmt->fetch() ?: throw new RuntimeException('not found');
    }

    // Eager loading with a join: 1 query regardless of row count.
    public function findWithCustomer(int $id): array
    {
        $stmt = $this->db->prepare(
            'SELECT o.id, o.total, c.name AS customer_name
            . ' FROM orders o JOIN customers c ON c.id = o.customer_id'
            . ' WHERE o.id = ?'
        );
        $stmt->execute([$id]);
        return $stmt->fetch() ?: throw new RuntimeException('not found');
    }

    // When to reach for raw SQL regardless of ORM: reporting, aggregates,
    // anything whose performance must be predictable and reviewable.
    public function revenueByMonth(): array
    {
        return $this->db->query(
            'SELECT DATE_FORMAT(created_at, \'%Y-%m\') AS month, SUM(total) AS revenue'
            . ' FROM orders WHERE status = ? GROUP BY month ORDER BY month',
            ['paid']
        )->fetchAll();
    }
}

A 20-row lazy loop costs 21 round trips. The same output costs 1 with a join. This is the single most common performance defect in PHP applications.

5.7 Schema migrations

A migration is a versioned, reversible description of a schema change. The discipline that matters is not the tool but the deployment ordering: an expand-then-contract sequence lets old and new application code run simultaneously against one database.

<?php

declare(strict_types=1);

final class AddOrdersTotalIndex
{
    public function up(PDO $db): void
    {
        $db->exec('CREATE INDEX idx_orders_total ON orders (total)');
    }

    public function down(PDO $db): void
    {
        $db->exec('DROP INDEX idx_orders_total ON orders');
    }
}

// Runner: applies everything above the recorded version, in order,
// recording each success so a partial run is resumable.
$db->exec('CREATE TABLE IF NOT EXISTS schema_migrations (version VARCHAR(255) PRIMARY KEY, applied_at DATETIME NOT NULL)');

$applied = $db->query('SELECT version FROM schema_migrations')->fetchAll(PDO::FETCH_COLUMN);
$done = array_flip($applied);

foreach (glob(__DIR__ . '/migrations/*.php') as $file) {
    $version = basename($file, '.php');
    if (isset($done[$version])) { continue; }

    $migration = require $file;
    $db->beginTransaction();
    try {
        $migration->up($db);
        $stmt = $db->prepare('INSERT INTO schema_migrations (version, applied_at) VALUES (?, ?)');
        $stmt->execute([$version, gmdate('Y-m-d H:i:s')]);
        $db->commit();
    } catch (Throwable $e) {
        $db->rollBack();
        throw $e;
    }
}

Requirements for a safe rename: never rename or drop a column in the same release that stops using it. First deploy code that reads both and writes both, then a migration that adds the new column, then code that reads only the new one, then finally a migration that drops the old column. Four deployments, no downtime.

PHP’s standard library is large and uneven in places, with functions that predate strict types and newer additions that are considerably safer. Knowing which is which prevents a class of bugs that is otherwise difficult to attribute.

6.1 Array functions and their callback traps

PHP 8 reworked several array functions so that callback arguments are passed by value rather than by reference, which removed a long-standing source of surprising side effects. The remaining trap is that callbacks and the search functions use loose or inconsistent comparison semantics.

<?php

declare(strict_types=1);

$prices = [100, 250, 75];

// map/filter/reduce: callbacks receive (value) or (value, key).
$withVat   = array_map(static fn(int $p): float => $p * 1.2, $prices);
$expensive = array_filter($prices, static fn(int $p): bool => $p > 100);
$total     = array_reduce($prices, static fn(int $carry, int $p): int => $carry + $p, 0);

// array_filter preserves keys. Reindex when a list is required.
$reindexed = array_values($expensive);

// THE TRAP: array_search and in_array are loose by default, so
// 'abc' == 0 is true, and any string matches index 0.
var_dump(in_array('abc', [0, 1]));                    // true  -- string coerced to 0
var_dump(in_array('abc', [0, 1], true));         // false -- strict fixes it
var_dump(array_search('1', [1, 2]));                   // 0    -- loose
var_dump(array_search('1', [1, 2], true));            // false -- strict

// Sort with an explicit comparator. Without one, values are
// compared as strings, which is almost never what is intended.
$names = ['Zoe', 'Adam', 'Mary'];
usort($names, static fn(string $a, string $b): int => strcmp($a, $b));
usort($prices, static fn(int $a, int $b): int => $a <=> $b);   // <=> is the spaceship operator

Always pass the strict flag to in_array and array_search, and always pass a comparator to the sort family.

Without a comparator, sort() and usort() compare elements as strings. Sorting [1, 2, 10] as strings yields [1, 10, 2], which looks like a bug in the sort but is correct string ordering.

6.2 Closures, callables and the pipe operator

The pipe operator, new in 8.5, composes single-argument callables into a left-to-right chain. It does not change semantics; it changes reading order from nested and inside-out to sequential.

<?php

declare(strict_types=1);

// Before: nested calls read inside-out and the subject is buried.
$result = json_encode(array_slice(explode(',', strtoupper($raw)), 0, 10), JSON_THROW_ON_ERROR);

// With |> (8.5): the data flows left to right, one step per line.
$result = $raw
    |> strtoupper(...)
    |> explode(',', ...)
    |> array_slice(0, 10)
    |> json_encode(JSON_THROW_ON_ERROR);

// It is exactly equivalent to the nested form above, with the
// ... placeholder receiving the piped value as the first argument.
$result = json_encode(array_slice(explode(',', strtoupper($raw)), 0, 10), JSON_THROW_ON_ERROR);

// First-class callable syntax (8.1) turns any callable into a
// Closure without a lambda wrapper, preserving the name for stacks.
$upper = strtoupper(...);
array_map($upper, ['a', 'b']);

Applies to: 8.5 and later. Requirements: the left-hand side must be an expression, and the right-hand side must be a callable that accepts the piped value as its first parameter.

6.3 String functions

PHP 8.0 added three predicate functions that previously required regular expressions, and made them the recommended approach. The str_* family takes an offset and length; the mb_* family operates on characters rather than bytes.

<?php

declare(strict_types=1);

$url = 'https://example.com/docs/guide';

// 8.0: predicate functions replace preg_match for simple checks.
var_dump(str_contains($url, '/docs'));      // true
var_dump(str_starts_with($url, 'https'));  // true
var_dump(str_ends_with($url, '/guide'));   // true

// Case-insensitive needs a fold, not a regex.
var_dump(stripos($url, 'HTTPS') !== false);

// Slicing: str_* works on bytes, mb_* on characters.
$text = 'naive cafe';
echo mb_substr($text, 0, 5), "\n";    // character-safe
echo strlen('e' . mb_convert_encoding('e', 'UTF-8', 'UTF-8')), "\n";

// Always pass JSON_THROW_ON_ERROR so malformed input throws
// rather than returning false and being ignored.
try {
    $decoded = json_decode($raw, true, 512, JSON_THROW_ON_ERROR);
} catch (JsonException $e) {
    error_log('bad payload: ' . $e->getMessage());
}

6.4 Filesystem and the silent-failure trap

Most filesystem functions in PHP return false on failure rather than raising an error. A write that fails because of a permissions problem or a full disk is therefore invisible unless the return value is checked, which is why unreadable empty files appear in production logs.

<?php

declare(strict_types=1);

// The trap: returns int|false, and false is frequently ignored.
file_put_contents('/var/log/app.log', $line . "\n", FILE_APPEND);

// The correct form checks the result and the failure reason.
$bytes = file_put_contents('/var/log/app.log', $line . "\n", FILE_APPEND);
if ($bytes === false) {
    throw new RuntimeException(
        'log write failed: ' . error_get_last()['message'] ?? 'unknown'
    );
}

// Locking for concurrent writers. Without LOCK_EX, two processes can
// interleave and corrupt the line.
file_put_contents('/var/log/app.log', $line . "\n", FILE_APPEND | LOCK_EX);

// Reading a whole file can exhaust memory on a large input.
$handle = fopen('/var/log/app.log', 'r');
while (($line = fgets($handle)) !== false) {
    error_log(trim($line));
}
fclose($handle);

// Atomic replacement: write to a temp file, then rename.
file_put_contents($tmp = $path . '.tmp', $contents);
rename($tmp, $path);   // readers see old or new, never partial

Use the temp-file-plus-rename pattern for any file another process may read. rename is atomic within a filesystem, so readers never observe a half-written file.

6.5 Dates, time and timezones

PHP 8.0 deprecated the date() family in favour of DateTimeImmutable. Immutability removes an entire category of bug where a date object was modified by a callee that the caller did not expect to change.

<?php

declare(strict_types=1);

use DateTimeImmutable;
use DateTimeZone;
use DateInterval;

// Prefer immutable objects. modify() returns a new instance.
$now = new DateTimeImmutable('now', new DateTimeZone('UTC'));
$later = $now->modify('+1 day');        // $now is unchanged

// Explicit zone on construction. Never rely on the default zone.
$local = new DateTimeImmutable('now', new DateTimeZone('Europe/London'));

// Arithmetic with DateInterval. ISO 8601 durations also parse.
$in30days = $now->add(new DateInterval('P30D'));
$later2   = $now->add(new DateInterval('PT2H'));   // 2 hours

// Store UTC in the database; convert only for display.
$dbValue = $now->format('Y-m-d H:i:s');                 // '2026-09-27 12:00:00'
$iso     = $now->format(DATE_ATOM);                          // ISO 8601
$display = $now->setTimezone(new DateTimeZone('Europe/London'))
             ->format('j M Y, H:i');

// Comparisons work on the objects directly.
$isPast = $now < $local;

Caveat: the date_default_timezone_set() default is a global that a dependency may change. Passing an explicit DateTimeZone to every constructor removes the class of bug where a library changes a global that your code then reads.

6.6 JSON and round-trip limitations

JSON has no integer type distinct from float and no tuple type. Round-tripping through it is therefore lossy in specific, predictable ways that matter whenever a value is echoed to a client and read back.

<?php

declare(strict_types=1);

// Lossy conversions, all expected:
var_dump(json_decode('{"a": [1,2,3]}', true)['a']);   // array (not a list type)
var_dump(json_decode('{"a": 1}', true)['a']);      // int(1) - but 1.0 also decodes to float(1)
var_dump(json_decode('{"1": "a"}', true)[1]);       // 'a' - integer keys become strings
var_dump(json_decode('{"a": 12345678901234567890}', true)['a']); // float - exceeds int range

// Use flags to control the shape of the output.
$json = json_encode(
    $data,
    JSON_THROW_ON_ERROR | JSON_PRETTY_PRINT | JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE
);

// Decoding objects as objects rather than arrays.
$obj = json_decode($json, false);          // stdClass instances
$arr = json_decode($json, true, 512, JSON_THROW_ON_ERROR);  // nested arrays

// Objects implementing JsonSerializable control their own encoding.
final class Money implements JsonSerializable
{
    public function __construct(public readonly int $cents) {}

    public function jsonSerialize(): array
    {
        return ['amount' => $this->cents / 100, 'currency' => 'GBP'];
    }
}

6.7 Sessions and CSRF

Session configuration must be set before the session starts, and the cookie flags are the security-relevant part. Regenerating the session identifier on privilege change is what prevents session fixation.

<?php

declare(strict_types=1);

// Configure before session_start(). Values shown are the hardened set.
ini_set('session.use_strict_mode', '1');      // reject attacker-supplied ids
ini_set('session.cookie_httponly', '1');     // not readable from JavaScript
ini_set('session.cookie_samesite', 'Lax');
ini_set('session.cookie_secure', '1');       // HTTPS only; disable locally
ini_set('session.use_trans_sid', '0');       // no id in URLs

session_start([
    'cookie_lifetime' => 0,            // session cookie
    'gc_maxlifetime'  => 1800,         // 30 minutes
]);

// CSRF: a per-session token, compared with hash_equals.
session_regenerate_id(true);   // on login, to defeat fixation
$_SESSION['csrf'] ??= bin2hex(random_bytes(32));

function csrfToken(): string { return $_SESSION['csrf']; }

function csrfValid(string $candidate): bool
{
    return hash_equals($_SESSION['csrf'], $candidate);
    // hash_equals is constant-time; == leaks timing information.
}

Caveat: session_regenerate_id(true) must be called on every privilege transition, not only login. A token that survives a role change is a token the previous user could reuse.

6.8 Input validation and filtering

Validation decides whether input is acceptable; escaping decides how to render it. Conflating the two produces either rejected input that was harmless, or accepted input that was not escaped. They are separate operations.

<?php

declare(strict_types=1);

// filter_input reads from the request without trusting $_GET shape.
$email = filter_input(INPUT_POST, 'email', FILTER_VALIDATE_EMAIL);
$valid  = $email !== false && $email !== null;

// Integer with an explicit range. Never cast blindly: (int)'12abc'
// yields 12, silently accepting malformed input.
$page = filter_input(INPUT_GET, 'page', FILTER_VALIDATE_INT, [
    'options' => ['min_range' => 1, 'max_range' => 1000],
]);

// A validator function is clearer for domain rules than a filter.
function isValidSku(string $sku): bool
{
    return preg_match('/^[A-Z]{3}-\d{4}$/', $sku) === 1;
}

// Output escaping is separate and happens at render time.
$name = $_POST['name'] ?? '';
if (!isValidSku($name)) {
    throw new InvalidArgumentException('malformed sku');
}
echo htmlspecialchars($name, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');

// For SQL, do not escape - bind. See chapter 5.
$stmt = $pdo->prepare('SELECT * FROM items WHERE sku = :sku');
$stmt->execute(['sku' => $name]);

6.9 Iterators and generators

A generator is a function that yields values lazily. For large or unbounded result sets it converts peak memory from O(n) to O(1), because only one value is materialised at a time.

<?php

declare(strict_types=1);

// Loading a million rows into an array: every row is in memory.
$rows = $db->query('SELECT * FROM events')->fetchAll();   // O(n) memory

// A generator streams instead. PDO is unbuffered by default for this
// driver combination, so memory stays flat.
function streamRows(PDO $db): Generator
{
    $stmt = $db->query('SELECT id, payload FROM events ORDER BY id', PDO::FETCH_ASSOC);

    while ($row = $stmt->fetch()) {
        yield $row;   // nothing is retained between iterations
    }
}

foreach (streamRows($db) as $row) {
    // $row is one array; memory does not grow with the row count.
    process($row);
}

// IteratorAggregate lets a class expose iteration without implementing
// all four Iterator methods.
final class ResultSet implements IteratorAggregate
{
    public function __construct(private readonly iterable $items) {}

    public function getIterator(): Traversable
    {
        foreach ($this->items as $item) { yield $item; }
    }
}

// A generator is single-use. Iterating it twice raises an exception,
// which surprises code that stores one for later.

Caveat: a generator cannot be iterated twice, and cannot be rewound. If a value is stored and consumed in two places, the second use throws "Cannot traverse an already closed generator". Materialise with iterator_to_array() if reuse is needed.

7 · HTTP, PSR-7 and Web Development

7.1 Request objects and server globals7.2 PSR-7 messages and PSR-15 handlers7.3 Routing and middleware7.4 Responses, status codes and content negotiation7.5 Input validation at the boundary7.6 File uploads and static assets

PHP was designed as a template language for web pages, and its superglobals remain the lowest-level access to the request. PSR-7 and PSR-15 replace those globals with injectable message objects, which is what makes a codebase testable without a web server.

7.1 Request objects and server globals

The superglobal family exposes the request without an object graph. It is fast and universally available, but it is untyped, untestable, and easy to reach for from a class that has no business knowing about HTTP.

<?php

declare(strict_types=1);

// Superglobals: available everywhere, but not injectable.
$method = $_SERVER['REQUEST_METHOD'] ?? 'GET';
$path   = parse_url($_SERVER['REQUEST_URI'] ?? '/', PHP_URL_PATH);

// Never trust the shape of $_GET or $_POST. Values may be arrays,
// and an attacker controls both entirely.
$page = filter_input(INPUT_GET, 'page', FILTER_VALIDATE_INT, [
    'options' => ['min_range' => 1, 'max_range' => 1000],
]);

// JSON request bodies are NOT parsed for you.
$raw = file_get_contents('php://input') ?: '';
$payload = json_decode($raw, true, 512, JSON_THROW_ON_ERROR);

// Client IP: trust the proxy only when you control it, because
// X-Forwarded-For is a client-supplied header.
$ip = $_SERVER['REMOTE_ADDR'] ?? '0.0.0.0';
if (isset($_SERVER['HTTP_X_FORWARDED_FOR']) && TRUST_PROXY) {
    $ip = explode(',', $_SERVER['HTTP_X_FORWARDED_FOR'])[0];
}

Caveat: X-Forwarded-For is set by the client and is trivially spoofed. Read it only when a reverse proxy you control overwrites it, and only after establishing a trusted-proxy list. Otherwise an attacker can choose their own apparent IP and defeat rate limiting.

7.2 PSR-7 messages and PSR-15 handlers

PSR-7 models an HTTP message as an immutable value object with fluent with* methods that return a new instance. PSR-15 defines a server request handler and middleware. Together they let an application be driven in a test without binding a socket.

<?php

declare(strict_types=1);

use Nyholm\Psr7\Factory\Psr17Factory;
use Psr\Http\Message\ServerRequestInterface;
use Psr\Http\Message\ResponseInterface;
use Psr\Http\Server\RequestHandlerInterface;
use Psr\Http\Server\MiddlewareInterface;
use Psr\Http\Server\RequestHandlerInterface as Handler;

// A middleware runs before the handler and may short-circuit it.
final class RequestIdMiddleware implements MiddlewareInterface
{
    public function process(ServerRequestInterface $request, Handler $handler): ResponseInterface
    {
        $id = $request->getHeaderLine('X-Request-Id') ?: bin2hex(random_bytes(8));

        // withHeader() returns a NEW request; the original is untouched.
        $request = $request->withAttribute('request_id', $id);

        return $handler->handle($request)->withHeader('X-Request-Id', $id);
    }
}

final class CreateOrderHandler implements RequestHandlerInterface
{
    public function __construct(private readonly PlaceOrder $useCase) {}

    public function handle(ServerRequestInterface $request): ResponseInterface
    {
        $factory = new Psr17Factory();
        $dto = $factory->createResponse()->withStatus(201);

        return $dto;
    }
}

// In a test, no server, no socket, no superglobals.
$request = $factory->createServerRequest('POST', '/orders')
    ->withParsedBody(['total' => 100]);

$response = (new CreateOrderHandler($useCase))->handle($request);
assert($response->getStatusCode() === 201);

The handler receives a request and returns a response. Nothing about it is tied to a running server, which is the whole point of the abstraction.

7.3 Routing and middleware

Routing maps a method and path to a handler. Middleware wraps each handler in a chain, so cross-cutting concerns are expressed once rather than repeated in every endpoint. Order is significant and is the usual source of routing bugs.

<?php

declare(strict_types=1);

use FastRoute\Dispatcher;
use FastRoute\RouteCollector;

$dispatcher = new Dispatcher(new RouteCollector());
$dispatcher->addRoute(['GET'],  '/orders',          'listOrders');
$dispatcher->addRoute(['GET'],  '/orders/{id:\d+}', 'getOrder');      // constraint in the pattern
$dispatcher->addRoute(['POST'], '/orders',          'createOrder');

[$handlerName, $vars] = $dispatcher->dispatch(
    $request->getMethod(), $request->getUri()->getPath()
);

$handler = $handlers[$handlerName];
return $handler($request, $vars);

// Middleware order: outermost first. Each may delegate inward.
$chain = $stack
    ->append(new ErrorMiddleware())       // outermost: catches everything below
    ->append(new RequestIdMiddleware())
    ->append(new SessionMiddleware())
    ->append(new AuthMiddleware())          // must run before the handler
    ->append(new RouterMiddleware());       // innermost: terminates the chain

$response = $chain->handle($request);

Put error handling outermost and authentication innermost-but-one. A middleware that runs after the router has already dispatched the request, so an auth check placed there is skipped for unmatched routes — which is exactly when you still want it enforced.

7.5 Input validation at the boundary

Validation belongs at the boundary, converting untrusted input into a typed value object. Passing raw arrays deeper into an application is how unvalidated data reaches the database layer.

<?php

declare(strict_types=1);

final class CreateOrder
{
    public function __construct(
        public readonly int $customerId,
        public readonly int $totalCents,
        public readonly string $currency,
    ) {}

    // Parse from raw input and throw a domain error on anything invalid.
    public static function fromArray(array $input): self
    {
        $customerId = filter_var($input['customer_id'] ?? null, FILTER_VALIDATE_INT, [
            'options' => ['min_range' => 1],
        ]);
        if ($customerId === false) {
            throw new InvalidArgumentException('customer_id must be a positive integer');
        }

        $total = filter_var($input['total'] ?? null, FILTER_VALIDATE_INT, [
            'options' => ['min_range' => 1],
        ]);
        if ($total === false) {
            throw new InvalidArgumentException('total must be positive');
        }

        $currency = strtoupper((string) ($input['currency'] ?? ''));
        if (!in_array($currency, ['GBP', 'EUR', 'USD'], true)) {
            throw new InvalidArgumentException('unsupported currency');
        }

        return new self($customerId, $total, $currency);
    }
}

Once inside the application the value is a CreateOrder object with typed, validated properties. No downstream layer re-checks it.

7.6 File uploads and static assets

File uploads are a common vulnerability source because validation is frequently limited to trusting the client-supplied MIME type and filename. The checks that matter are size, extension allowlist, and a content signature read from the file itself.

<?php

declare(strict_types=1);

final class UploadValidator
{
    private const MAX_BYTES = 5 * 1024 * 1024;
    private const ALLOWED_EXT = ['jpg', 'jpeg', 'png', 'webp', 'pdf'];

    public function validate(array $file): string
    {
        if ((int) ($file['error'] ?? UPLOAD_ERR_NO_FILE) !== UPLOAD_ERR_OK) {
            throw new RuntimeException('upload failed with code ' . $file['error']);
        }
        if ((int) $file['size'] > self::MAX_BYTES) {
            throw new RuntimeException('file too large');
        }

        // Extension comes from the filename, which the client controls.
        $ext = strtolower(pathinfo($file['name'], PATHINFO_EXTENSION));
        if (!in_array($ext, self::ALLOWED_EXT, true)) {
            throw new RuntimeException('extension not allowed');
        }

        // Verify the real content type from the file itself. finfo reads
        // magic bytes; the client-supplied type is not evidence.
        $finfo = new finfo(FILEINFO_MIME_TYPE);
        $mime  = $finfo->file($file['tmp_name']);
        $expected = match ($ext) {
            'pdf' => 'application/pdf',
            'png' => 'image/png',
            default  => str_starts_with($mime, 'image/') ? $mime : throw new RuntimeException('not an image'),
        };
        if ($mime !== $expected) {
            throw new RuntimeException('content does not match extension');
        }

        // Store under a generated name. Never under the client's name.
        $stored = bin2hex(random_bytes(16)) . '.' . $ext;
        if (!move_uploaded_file($file['tmp_name'], '/var/uploads/' . $stored)) {
            throw new RuntimeException('could not store file');
        }
        return $stored;
    }
}

Caveat: move_uploaded_file verifies the file arrived through an HTTP upload. A path reaching the same code from elsewhere is not a valid upload and must be rejected earlier. Also ensure the upload directory is served by a web server configured not to execute PHP, so a disguised file cannot run.

PHP has a mature testing ecosystem. The hard part is not the framework but the boundaries: a test that requires a live database or a web server is slow, and a slow suite is a suite that gets skipped.

8.1 Unit tests and the arrange-act-assert shape

PHPUnit is the dominant test framework. A unit test exercises one behaviour, states its intent in the name, and asserts a single observable outcome. When a test needs three arrangements it is usually testing two things.

<?php

declare(strict_types=1);

use PHPUnit\Framework\TestCase;

final class PlaceOrderTest extends TestCase
{
    public function test_it_rejects_a_non_positive_total(): void
    {
        // arrange
        $orders = new InMemoryOrderRepository();
        $subject = new PlaceOrder($orders, new NullMailer());

        // act
        try {
            $subject->execute(new CreateOrder(1, 0, 'GBP'));
            self::fail('expected InvalidArgumentException');
        } catch (InvalidArgumentException $e) {
            // assert
            self::assertSame('total must be positive', $e->getMessage());
        }

        self::assertSame(0, $orders->count());   // and nothing was persisted
    }

    // A successful path with no exception reads more directly.
    public function test_it_persists_a_valid_order(): void
    {
        $orders = new InMemoryOrderRepository();
        $mailer = new SpyMailer();
        $subject = new PlaceOrder($orders, $mailer);

        $id = $subject->execute(new CreateOrder(42, 2599, 'GBP'));

        self::assertSame(1, $orders->count());
        self::assertTrue($mailer->wasSent());
        self::assertNotNull($id);
    }
}

8.2 Test doubles and where to mock

PHPUnit provides four kinds of double. The useful rule is that a test double should stand in for something you do not own or cannot easily run, and never for the code under test.

<?php

declare(strict_types=1);

// Injecting an interface is what makes this possible. See ch4, PSR interfaces.
interface MailerInterface { public function send(string $to, string $subject, string $body): void; }

final class FakeMailer implements MailerInterface
{
    public array $sent = [];

{
    $mailer = new FakeMailer();          // a fake, not a mock: real behaviour, no SMTP
    $subject = new PlaceOrder(new InMemoryOrderRepository(), $mailer);

    $subject->execute(new CreateOrder(7, 500, 'GBP'));

    self::assertCount(1, $mailer->sent);
    self::assertSame('Order confirmed', $mailer->sent[0]['subject']);
}

// A mock is right when the CALL is the behaviour, e.g. an audit log.
$logger = $this->createMock(LoggerInterface::class);
$logger->expects(self::once())
       ->method('warning')
       ->with('payment gateway timeout');

Prefer a hand-written fake for an interface you own. Mocks assert coupling to the current implementation; a fake asserts only behaviour, so refactoring internals does not break a suite full of brittle expectations.

8.3 Database tests and the transaction rollback pattern

The fastest database test is one that runs against an in-memory database, because creating and dropping a schema per test costs more than the test itself. When a real engine is required, wrapping each test in a transaction that is rolled back keeps the suite isolated and fast.

<?php

declare(strict_types=1);

abstract class DatabaseTestCase extends TestCase
{
    protected PDO $db;

    protected function setUp(): void
    {
        if ($this->db === null) {
            // Built once per process, not once per test.
            static $shared = null;
            $shared ??= new PDO('sqlite::memory:');
            $this->db = $shared;
            $this->migrate($this->db);
        }

        // Every test runs inside a transaction that is never committed.
        $this->db->beginTransaction();
    }

    protected function tearDown(): void
    {
        if ($this->db->inTransaction()) {
            $this->db->rollBack();
        }
    }
}

Rollback-based isolation gives each test a clean database without a truncate between tests, and costs almost nothing.

Caveat: this pattern does not work for tests that themselves open and commit transactions, nor on MySQL where DDL implicitly commits. Those tests need an explicit truncate strategy instead.

8.4 HTTP integration tests

An integration test boots the application kernel and issues a real request through the full middleware stack. It proves that routing, middleware, controller and persistence are wired correctly together, which unit tests cannot show.

<?php

declare(strict_types=1);

final class CreateOrderApiTest extends DatabaseTestCase
{
    public function test_it_rejects_an_order_with_a_zero_total(): void
    {
        $response = $this->request('POST', '/api/orders', [
            'customer_id' => 1,
            'total'     => 0,
            'currency'  => 'GBP',
        ]);

        self::assertSame(422, $response->getStatusCode());

        $body = json_decode((string) $response->getBody(), true);
        self::assertArrayHasKey('errors', $body);
        self::assertArrayHasKey('total', $body['errors']);
    }

    public function test_it_creates_an_order_and_returns_201_with_a_location(): void
    {
        $response = $this->request('POST', '/api/orders', [
            'customer_id' => 1,
            'total'     => 2599,
            'currency'  => 'GBP',

        self::assertNotNull($response->getHeaderLine('Location'));
    }
}

Assert on the status code, the headers that form the contract, and the error shape. Asserting on incidental body text makes the suite fail on harmless edits.

Example-based tests verify the cases you thought of. Property-based tests verify an invariant over inputs you did not, by generating many cases and shrinking any failure to a minimal reproducer. Mutation testing measures whether your assertions are strong enough to detect a defect.

<?php

declare(strict_types=1);

use Eris\TestTrait;

Every control in this chapter exists because a corresponding mistake is common and exploitable. The organising principle is that untrusted data is neutralised according to the context in which it lands, not globally and once.

9.1 Input handling and output encoding

Validation decides whether input is acceptable. Escaping decides how it is rendered. They are separate operations, and conflating them produces either over-rejection of harmless input or under-escaping of dangerous output.

<?php

declare(strict_types=1);

// Validation: accept or reject, with a specific message.
$email = filter_var($input['email'] ?? null, FILTER_VALIDATE_EMAIL);
if ($email === false) {
    throw new ValidationException(['email' => ['must be a valid address']]);
}

// Encoding: applied at render time, in the context of the output.
$name = $_POST['name'] ?? '';

// HTML text context
echo htmlspecialchars($name, ENT_QUOTES | ENT_SUBSTITUTE | ENT_HTML5, 'UTF-8');

// JavaScript context: JSON encoding, with the flag that stops </script>
// from terminating an inline script block.
echo json_encode($data, JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT | JSON_THROW_ON_ERROR);

// URL context: validate the scheme, or javascript: becomes an XSS vector.
if (!preg_match('/^https?:\/\//', $url)) {
    throw new ValidationException(['url' => ['must be http or https']]);
}

// Attribute context: ENT_QUOTES is required, not optional.
printf('<a href="%s">%s</a>',
    htmlspecialchars($url, ENT_QUOTES, 'UTF-8'),
    htmlspecialchars($name, ENT_QUOTES, 'UTF-8'));

Caveat: htmlspecialchars() without ENT_QUOTES does not escape single quotes, so a value placed in a single-quoted attribute can still break out. Always pass the flags explicitly; do not rely on default_charset for the encoding.

9.2 Cross-site scripting and context-specific escaping

XSS occurs when attacker-controlled data reaches an executable context. The defence is to choose the escaping function for the context the value lands in, which is why a single global "escape everything" helper is a source of bugs rather than a solution.

9.3 CSRF and request forgery

Cross-site request forgery exploits the browser’s automatic credential attachment. Any state-changing endpoint reachable by a cookie-authenticated session needs either a token check or a defence based on the Origin header.

<?php

declare(strict_types=1);

final class CsrfGuard
{
    public function __construct(private readonly SessionInterface $session) {}

    public function token(): string
    {
        $this->session->start();
        return $this->session->get('csrf') ??= bin2hex(random_bytes(32));
    }

    public function validate(ServerRequestInterface $request): bool
    {
        $this->session->start();
        $expected = $this->session->get('csrf');
        if (!is_string($expected)) { return false; }

        $supplied = $request->getHeaderLine('X-CSRF-Token')
            ?: (string) ($request->getParsedBody()['_token'] ?? '');

        // Constant-time comparison. A == check leaks timing information.
        return hash_equals($expected, $supplied);
    }

    public function originAllowed(ServerRequestInterface $request): bool
    {
        $origin = $request->getHeaderLine('Origin');
        if ($origin === '') { return true; }   // same-origin form posts may omit it
        return in_array($origin, $this->allowedOrigins, true);
    }
}

9.4 Session and cookie hardening

Session configuration is the largest single lever on account takeover risk, and its defaults are not the hardened values. Four settings must be changed explicitly.

<?php

declare(strict_types=1);

// Set before session_start(). These are not the defaults.
ini_set('session.use_strict_mode',  '1');    // reject client-supplied session ids
ini_set('session.cookie_httponly', '1');    // not readable by JavaScript, so XSS cannot steal it
ini_set('session.cookie_secure',   '1');    // HTTPS only
ini_set('session.cookie_samesite', 'Lax');   // blocks cross-site POSTs
ini_set('session.use_trans_sid',  '0');    // never put the id in a URL
ini_set('session.sid_length',     48);       // longer ids resist brute force
ini_set('session.sid_bits_per_character', 6);

session_start(['cookie_lifetime' => 0, 'gc_maxlifetime' => 900]);

// Regenerate on EVERY privilege transition: login, logout, role change,
// password change. This is what defeats session fixation.
function regenerate(): void
{
    session_regenerate_id(true);
    session_regenerate_id(true);   // twice removes the pre-auth entry server-side too
}

// Absolute and idle timeouts are separate controls.
$_SESSION['last_seen'] ??= time();
if (time() - $_SESSION['last_seen'] > 900) {
    session_destroy();
}
$_SESSION['last_seen'] = time();

Caveat: session_regenerate_id(true) issues a new id and deletes the old session file, but the old data may persist until garbage collection runs. Calling it twice, or calling session_destroy() for the previous id first, removes the window.

9.5 Password hashing

Password hashing must be deliberately slow and must use a salt the algorithm generates internally. Both requirements are met by a modern memory-hard hash; a bare SHA-256 of a password, however iterated by hand, is inadequate.

<?php

declare(strict_types=1);

// RECOMMENDED: Argon2id, memory-hard, with parameters tuned to your host.
$hash = password_hash($password, PASSWORD_ARGON2ID, [
    'memory_cost' => 65536,   // 64 MB
    'time_cost'   => 4,
    'threads'      => 2,
]);

// Acceptable: bcrypt. Capped at 72 bytes, so pre-hash long passwords.
$hash = password_hash($password, PASSWORD_BCRYPT, ['cost' => 12]);

// WRONG: a hand-rolled hash. No salt, no work factor, not memory-hard.
//   $hash = hash('sha256', $password);

// Verify. password_verify is constant-time and understands the
// algorithm and parameters stored in the hash string.
if (password_verify($submitted, $hash)) {
    // Rehash transparently if the cost parameters have been raised.
    if (password_needs_rehash($hash, PASSWORD_ARGON2ID, ['memory_cost' => 65536])) {
        $users->updateHash($userId, password_hash($submitted, PASSWORD_ARGON2ID));
    }
    session_regenerate_id(true);
}

// Long inputs exceed bcrypt's 72-byte limit. Pre-hash with a
// domain-separated HMAC so the pre-image is fixed-length.
//   $bcryptInput = base64_encode(hash_hmac('sha384', $password, $pepper, true));

// Never: md5(), sha1(), or an unsalted fast hash.

Raise the cost parameters periodically and rely on password_needs_rehash to migrate users lazily at their next login. That is simpler and safer than a bulk rehashing migration.

9.6 Secrets and cryptography

Cryptographic choices in application code are limited: hashing passwords, generating random values, and encrypting data at rest. Everything else belongs to a well-reviewed library, and bespoke cryptography should be treated as a defect.

<?php

declare(strict_types=1);

// Randomness: never rand(), mt_rand(), uniqid(). Use random_bytes.
$token  = bin2hex(random_bytes(32));      // 256 bits, CSPRNG
$userId = random_int(1, 1000000);          // unbiased integer

// Comparison: hash_equals is constant-time; == is not.
if (hash_equals($storedSignature, $provided)) { /* ok */ }

// Symmetric encryption: a standard AEAD, with a fresh nonce per message.
$key   = random_bytes(32);                       // 256-bit key, stored in a KMS
$nonce = random_bytes(SODIUM_CRYPTO_SECRETBOX_NONCEBYTES);
$ciphertext = sodium_crypto_secretbox(json_encode($data, JSON_THROW_ON_ERROR), $nonce, $key);
$stored = $nonce . $ciphertext;                            // store nonce with the data

$plaintext = sodium_crypto_secretbox_open(
    substr($stored, SODIUM_CRYPTO_SECRETBOX_NONCEBYTES),
    substr($stored, 0, SODIUM_CRYPTO_SECRETBOX_NONCEBYTES),
    $key
);

// WRONG: a nonce derived from a counter stored beside the ciphertext,
// or a mode without authentication, silently loses confidentiality.

// Secrets come from the environment, never from source control.
$apiKey = getenv('STRIPE_SECRET_KEY') ?: throw new RuntimeException('STRIPE_SECRET_KEY not set');

9.7 Filesystem, path traversal and deserialisation

Three classes of bug share a shape: a value from an untrusted source is used to locate or reconstruct something. Path traversal, unsafe deserialisation and command injection all follow from a string being trusted as a path, a format, or a command.

<?php

declare(strict_types=1);

// PATH TRAVERSAL: canonicalise, then verify the result is inside the base.
$base = realpath('/var/www/uploads');
$requested = $base . '/' . ($_GET['file'] ?? '');
$resolved = realpath($requested);

if ($resolved === false || !str_starts_with($resolved, $base . DIRECTORY_SEPARATOR)) {
    throw new RuntimeException('path outside base directory');
}
readfile($resolved);

// DESERIALISATION: unserialize() executes code embedded in the payload.
//   NEVER on user input. Prefer JSON, which has no object graph.
$safe = json_decode($input, true, 512, JSON_THROW_ON_ERROR);

// If a library forces unserialize, restrict the allowed classes.
$obj = unserialize($input, ['allowed_classes' => [DTO::class]]);

// COMMAND INJECTION: shell=True passes the string to a shell.
//   WRONG:  shell_exec('convert ' . $file . ' out.png');
//   RIGHT: pass an argument vector, with no shell involved.
$command = ['convert', $file, -strip', $out];   // note: no leading dash in the arg
proc_open(
    $command,
    ['1' => ['file', '/dev/stdout', 'w'], '2' => ['pipe', 'w']],
    $pipes
);

9.9 Dependency and supply-chain risk

A PHP application inherits the security posture of its entire dependency tree, including transitive packages. Most reported PHP vulnerabilities arrive through a package nobody chose deliberately.

<?php

declare(strict_types=1);

// 1. Audit the locked set, not the manifest. composer.lock is the truth.
//    composer audit --locked

// 2. Fail the build on a known advisory.
//    GitHub Actions step:
//    - run: composer audit --locked --format=summary
//      exit-code: 1

$composer = json_decode(file_get_contents('composer.lock'), true);

Almost every performance and architecture decision in PHP follows from one fact: a request is compiled, executed and destroyed, and nothing about the program survives it. This chapter establishes that model, then works outward to memory, bytecode caching, measurement, concurrency and the cache layers that sit above all of it.

10.1 The execution model

PHP does not interpret source text and it does not execute machine code. It compiles each file to a compact instruction set — opcodes — and executes those on the Zend Engine, a virtual machine written in C that maintains its own value stack, its own symbol tables and its own memory manager. Understanding the three-stage pipeline is what makes the rest of this chapter predictable rather than folklore.

/**
 * ch10-request-lifecycle.php
 *
 * Run it twice:
 *
 *     php ch10-request-lifecycle.php

);

{

}

10.2 Memory, measurement and copy-on-write

PHP does not use the operating system allocator for ordinary values. It carves each request’s memory out of arenas it manages itself, which is fast and which makes the accounting model different from every other language you may know: memory_limit bounds one request’s arena, not one process’s resident set.

{
    return sprintf('%6.2f MiB', $bytes / 1048576);

{
    printf(
        "%-22s current %s  peak %s\n",
        $label,
        mib(memory_get_usage()),
        mib(memory_get_peak_usage())
    );
}

function readOnly(array $rows): int
{
    return count($rows);
}

function writeInto(array& $rows): int
{
    $rows['marker'] = true;

    return count($rows);
}

report('start');

    $big[] = ['id' => $i, 'sku' => 'SKU-' . $i, 'qty' => 1];
}

// Assignment is copy-on-write. The reference count is incremented and not
// one byte is moved.
$alias = $big;
report('after alias');

// A read-only pass never triggers the duplication, because nothing writes.
readOnly($big);
report('after read pass');

// Writing through the alias separates the two arrays. This is the moment
// the 20 MB of buckets is duplicated.
$alias[0]['qty'] = 99;
report('after write');

// A by-reference parameter never duplicates at all, and never allocates
// a second copy of the hash table.
unset($alias);
$before = memory_get_usage();
writeInto($big);

// the pool did not set it with php_admin_value[memory_limit], which is not
// writable at runtime. See 10.2 and the Enterprise Appendix.
printf("ini_set(memory_limit, -1) => %s\n", ini_set('memory_limit', '-1') === false ? 'refused by the pool' : 'granted');

The readOnly and writeInto pair is the whole copy-on-write rule in two functions. A parameter declared array $rows duplicates the moment the callee writes; a parameter declared array &$rows never duplicates and never receives a copy — at the cost of exporting aliasing to the caller, and making the parameter unusable with a function-call result or an array literal.

  • $b = $a; increments a reference count. No bytes move.
  • Reading through either name does not separate them.
  • $b[] = 1;, $b['k'] = 1; or any nested write separates them and duplicates the buckets.
  • unset($a) decrements the count. It does not copy, and it does not free while $b holds the value.
  • $b =& $a; creates a real reference. There is no count and no separation; both names address one value forever.
  • Objects are handles, not values. $b = $a on an object never copies it; clone is required, and a shallow clone shares the object’s own properties. See 3.1.
  • foreach ($a as &$v) leaves dangling references in $a after the loop, which is why the loop variable is unset immediately afterwards. See 1.3.

Caveat: removing a memory_limit does not remove the risk, it only makes the failure mode unpredictable. With a limit, a runaway allocation becomes a catchable fatal error inside one request and one 500. Without one, the allocation competes with every other worker for host memory and the kernel OOM killer terminates a process chosen by a heuristic that has no knowledge of which one is leaking. ini_set('memory_limit', -1) belongs in a CLI script you are debugging, never in a request path. When a limit is genuinely too low for a legitimate endpoint, raise it for that pool or that route, do not remove it globally.

The limit is per request, and N workers may each consume the whole limit simultaneously, so the worst-case footprint of a pool is roughly N × memory_limit plus per-worker overhead. This arithmetic is the basis of the pool sizing in the Enterprise Appendix.

Streaming instead of materialising

The other half of the memory story is not freeing but never allocating. Section 6.9 covers the generator mechanics; the memory consequence is the reason to reach for them.

<?php

declare(strict_types=1);

/**
 * ch10-streaming.php -- run with: php -d memory_limit=32M ch10-streaming.php
 *
 * Peak memory for materialising 250,000 rows is O(n). Peak memory for a
 * generator over the same rows is O(1), because one row exists at a time.
 */

function seed(PDO $pdo, int $rows): void
{
    $pdo->exec('CREATE TABLE items (id INTEGER PRIMARY KEY, sku TEXT NOT NULL, qty INTEGER NOT NULL)');
    $insert = $pdo->prepare('INSERT INTO items (sku, qty) VALUES (:sku, :qty)');
    $pdo->beginTransaction();
    for ($i = 0; $i < $rows; $i++) {
        $insert->execute([':sku' => 'SKU-' . $i, ':qty' => 1]);
    }
    $pdo->commit();
}

/** @return Generator<int, array<string, mixed>> */
function streamItems(PDO $pdo, int $afterId, int $limit): Generator
{
    $stmt = $pdo->prepare('SELECT id, sku, qty FROM items WHERE id > :id ORDER BY id LIMIT :n');
    $stmt->bindValue(':id', $afterId, PDO::PARAM_INT);
    $stmt->bindValue(':n', $limit, PDO::PARAM_INT);
    $stmt->execute();

    while (($row = $stmt->fetch(PDO::FETCH_ASSOC)) !== false) {
        yield $row;
    }
}

    memory_get_usage() / 1048576, $baseline / 1048576);

printf("fetchAll()               current %6.2f MiB  peak %6.2f MiB  rows %d\n",
    memory_get_usage() / 1048576, memory_get_peak_usage() / 1048576, count($all));
unset($all);

// A keyset page at a time. Peak is already at its high-water mark from the
// previous phase, so current usage is the number that shows the difference.
$afterId = 0;
$total   = 0;
$pages   = 0;
do {
    $seen = 0;
    foreach (streamItems($pdo, $afterId, 5000) as $row) {
        $total += $row['qty'];
        $afterId = $row['id'];
        $seen++;
    }
    $pages++;
} while ($seen === 5000);

printf("paged generator         current %6.2f MiB  peak %6.2f MiB  sum %d in %d pages\n",
    memory_get_usage() / 1048576, memory_get_peak_usage() / 1048576, $total, $pages);

// Caveats:
//  - A generator holds its statement open for its whole lifetime. Two live
//    iterators on ONE connection interleave on the wire protocol and corrupt
//    each other's cursor. Use a second connection, or page by keyset as above.
//  - A generator is single-use. Traversing it twice raises
//    "Cannot traverse an already closed generator"; call iterator_to_array()
//    once if reuse is required.
//  - back() and count() are undefined on a plain generator. Implement
//    Countable, or accept that the count is not knowable without draining it.

memory_get_peak_usage() never decreases, so the third line’s peak still reflects fetchAll(). That is precisely why the peak function exists and why it is the wrong function for an incremental test: memory_get_usage() is the current-usage signal, memory_get_peak_usage() is the budget signal.

10.3 OPcache, preloading and the JIT

OPcache holds compiled opcodes in shared memory so that the compile stage happens once per file per host rather than once per request. It is the highest-value performance configuration in a PHP deployment and, empirically, the one most often left at its shipped defaults.

; ch10-opcache.ini -- the settings worth changing in production
; Requirements: the Zend OPcache extension, loaded with zend_extension=opcache.so
; and opcache.enable=1. Applies to PHP 8.4 and 8.5.

opcache.enable=1
opcache.enable_cli=0

; 0 = never stat a file on include. Correct in production only because the
; release process resets the cache; see 10.3 and chapter 12.
opcache.validate_timestamps=0

; Prevents a burst of concurrent requests from all compiling the same file
; and each blocking on the shared lock.

; rather than allowing a silent full-cache reset, which is catastrophic for
; latency: every request recompiles the entire application at once.
opcache.memory_consumption=192

; Megabytes of string interning arena. 0 disables interning entirely.

; Size this against the number of declared symbols, not the file count.
; Symptom of a value that is too low: a warning at startup and functions
; that are "not cached", which presents as random, unreproducible slowness.
opcache.max_accelerated_files=30000

; Fraction of the memory budget that may be wasted before eviction begins.
opcache.max_wasted_percentage=10

; restart, which makes it a cheap and effective warm-up target.
opcache.file_cache=/var/cache/php/opcache

; The JIT. As of PHP 8.5 the tracing JIT is correct and production-ready, and the
; consensus measurement on request/response PHP is a single-digit-percent gain
; at best, frequently zero, against a real memory cost. See 10.4.
opcache.jit=disable
opcache.jit_buffer_size=0

What OPcache caches is the compiled form of each file: its op_array, the instruction list, the literal table and the constant expressions. What it does not cache is anything about a request — not a database result, not a computed value, not a serialised object. A cache hit therefore removes compilation cost and nothing else. On a framework request that spends 80% of its time in the database, OPcache still roughly halves total CPU because compilation is usually 30—50% of a first-request cost, but it does not make the database faster.

validate_timestamps, and resetting the cache at deploy time

With opcache.validate_timestamps=1 (the shipped default) the engine calls stat() on every include, and recompiles when the modification time differs. The cost is one syscall per include per request, which on a large autoloaded codebase with a few hundred includes is a measurable and entirely avoidable tax. Setting it to 0 removes the tax and makes the cache the single source of truth for which code is running, which means an explicit invalidation is now mandatory.

  • opcache_reset() called from a CLI script resets the CLI SAPI’s own cache and nothing else. It does not touch the FPM segment. This is the most commonly believed false fix in PHP operations.
  • Reloading the FPM pool is effective: the master re-creates the shared segment, so every worker recompiles once. kill -USR2 on the master performs a graceful reload that starts new workers and lets the old ones drain (12.6).
  • Deleting the opcache.file_cache directory is effective and survives a pool reload, because that directory is shared by every SAPI on the host.
  • opcache.file_cache_only=1 makes the SAPI read compiled files from file_cache without ever writing to shared memory. This is the cheapest reliable warm-up: a CLI process populates the directory, and every FPM worker then starts on a warm cache.

Warm-up: run composer dump-autoload --optimize --classmap-authoritative, then read the generated classmap and call opcache_compile_file() on each path, then opcache_reset(). The chapter 12 release script performs exactly this sequence as part of the deploy.

Caveat: disabling validate_timestamps and swapping a current symlink is not sufficient on its own. A worker that has not yet compiled a file will compile whichever version of that file it resolves at that moment, into a cache that the old workers are also reading. The release must either reset the cache as part of the swap or reload the pool, and the order matters: drain the old workers first, then swap, then reload. Chapter 12.6 gives the working sequence.

Preloading

opcache.preload names a script that runs once in the FPM master before workers are forked. Classes, functions and constants defined there land in shared memory and are inherited copy-on-write by every worker, so no worker ever parses the framework’s class table. On a large framework the measurable gain is a real reduction in per-request CPU and a genuine reduction in first-request latency after a deploy.

  • Preload-time code must not depend on request state. Reading $_SERVER, the environment or a request-scoped service there produces a value frozen at master start that every worker then shares.
  • A database or HTTP connection opened during preload is inherited by every forked worker. Several processes then write to one socket, which corrupts the protocol. Open connections after the fork, in the worker.
  • Preloading is incompatible with pools that are restarted per request, and it requires preload_user to be set to a non-root user or the preload script runs as the wrong user and cannot read the application.
  • It is a compatibility risk for libraries that expect to be discovered or configured at runtime. Enable it per application, measure, and be prepared to remove it.

The JIT

As of PHP 8.5 the tracing JIT is a supported, production-ready feature selected by opcache.jit with a strategy of tracing, function or disable, and a budget in opcache.jit_buffer_size in megabytes. A buffer size of 0 disables it entirely, which is the shipped default. The tracing JIT compiles hot loops to machine code and specialises on the actual types observed, so it rewards monomorphic, CPU-bound, userland-heavy code: numeric transforms over large arrays, image-manipulation inner loops, cryptographic bulk work. It does not reward a request handler dominated by extension calls, because an internal function call is not something the JIT can inline past.

Applies to: PHP 8.4 and 8.5 with the bundled OPcache; the JIT is part of the extension, not a separate package. Requirement: the buffer is allocated from the same process memory as everything else, so opcache.jit_buffer_size is additional to opcache.memory_consumption. Caveat: do not enable a JIT strategy and assume a win. Benchmark opcache.jit=disable against opcache.jit=tracing on your own workload with everything else held constant, and keep it only if the difference survives a realistic concurrency test. opcache.jit_debug accepts a bitmask and will dump the generated machine code to the error log, which is the only way to confirm the JIT is engaging on your code paths at all.

<?php

declare(strict_types=1);

/**
 * ch10-fork-pool.php -- run with: php ch10-fork-pool.php 4
 *
 * Requirements: ext-pcntl, which is POSIX-only and is not present in the
 * official Windows builds. pcntl_fork() is deliberately unavailable inside a
 * PHP-FPM or mod_php process, so this runs under the CLI SAPI only.
 *
 * This is parallelism, not concurrency: separate processes, separate address
 * spaces, genuine multi-core execution. Forks are cheap because the child
 * shares the parent's pages copy-on-write until it writes.
 */

final class Pool
{
    public function __construct(private readonly int $workers) {}

    /**
     * @param list<string> $jobs
     * @return list<string>
     */
    public function run(array $jobs): array
    {
        if ($this->workers < 1 || $this->workers > 32) {
            throw new InvalidArgumentException('workers must be between 1 and 32');
        }
        if ($jobs === []) {
            return [];
        }

        $size = max(1, (int) ceil(count($jobs) / $this->workers));
        $buckets = array_fill(0, $this->workers, []);
        foreach (array_chunk($jobs, $size) as $i => $slice) {
            $buckets[$i % $this->workers] = array_merge($buckets[$i % $this->workers], $slice);
        }

        $children = [];
        foreach ($buckets as $i => $bucket) {
            $pid = pcntl_fork();
            if ($pid === -1) {
                throw new RuntimeException('pcntl_fork failed: ' . pcntl_strerror(pcntl_errno()));
            }
            if ($pid === 0) {
                // Child. exit() rather than return: falling through would
                // run the parent's shutdown functions and write its output.
                $out = [];
                foreach ($bucket as $job) {
                    $out[] = $this->handle($job);
                }
                file_put_contents($path = $this->path($i), json_encode($out, JSON_THROW_ON_ERROR));
                exit(0);
            }
            $children[$i] = ['pid' => $pid, 'path' => $this->path($i)];
        }

        $result = [];
        foreach ($children as $child) {
            pcntl_waitpid($child['pid'], $status);
            if (pcntl_wifexited($status) && pcntl_wexitstatus($status) === 0) {
                $decoded = json_decode((string) @file_get_contents($child['path']), true);
                $result = array_merge($result, is_array($decoded) ? $decoded : []);
            } else {
                // Fail loudly. The classic pcntl defect is a parent that reports
                // success for a bucket that was never processed.
                @unlink($child['path']);
                throw new RuntimeException(
                    sprintf('worker pid %d failed, status %d', $child['pid'], $status)
                );
            }
            @unlink($child['path']);
        }

        return $result;
    }

    private function path(int $i): string
    {
        return sys_get_temp_dir() . '/php-pool-' . getmypid() . '-' . $i . '.json';
    }

    private function handle(string $job): string
    {
        // Replace with the real unit of work. Whatever it is, it must be safe
        // to abandon: the parent kills nothing, so a half-written side
        // effect on a child's death stays made.
        return strtoupper($job) . '@' . getmypid();
    }
}

$jobs = array_map(static fn (int $i): string => 'job-' . $i, range(1, 12));

$pool    = new Pool(max(1, (int ($argv[1] ?? 2)));
$started = hrtime(true);
$result  = $pool->run($jobs);

printf("%d jobs across %d workers in %.2f ms\n",
    count($jobs), 2, (hrtime(true) - $started) / 1e6);
printf("%-10s %-8s %s\n", 'job', 'pid', 'result');
foreach ($result as $line) {
    printf("%-10s %-8s %s\n", ...explode('@', $line, 2));
}

Passing results back through a temporary file is a simplification that keeps the sample short. The alternatives are a stream_socket_pair per child, a shared msgpack pipe, or having each child write its own result set. What matters in every design is the last paragraph of the run body: a child that dies must fail the parent, never be skipped.

<?php

declare(strict_types=1);

/**
 * ch10-fibers.php -- run with: php ch10-fibers.php
 *
 * Requirements: PHP 8.1 or later. A Fiber is a cooperative execution context.
 * Control moves between fibers only where the code explicitly says so, at a
 * call to Fiber::suspend(). There is no preemption, no data race, no shared
 * mutable state and no parallelism on a single core.
 */

final class Scheduler
{
    /** @var list<Fiber> */
    private array $queue = [];

    /** @var array<int, true> */
    private array $fresh = [];

    /** @var list<string> */
    private array $log = [];

    public function add(string $name, callable $task): void
    {
        $fiber = new Fiber(static function () use ($name, $task): void {
            $task();
        });

        $this->queue[] = $fiber;
        $this->fresh[spl_object_id($fiber)] = true;
    }

    /** @return list<string> */
    public function run(): array
    {
        $this->log = [];

        while ($this->queue !== []) {
            $fiber = array_shift($this->queue);
            $id    = spl_object_id($fiber);

            // start() runs to the first suspend and returns what was passed
            // to it; resume() does the same from the next suspend point.
            $label = isset($this->fresh[$id]) ? $fiber->start() : $fiber->resume();
            unset($this->fresh[$id]);

            $this->log[] = sprintf('%-18s %s', (string) ($label ?? '(no yield)'),
                $fiber->isTerminated() ? 'terminated' : 'suspended');

            if (!$fiber->isTerminated()) {
                $this->queue[] = $fiber;
            }
        }

        return $this->log;
    }
}

$scheduler = new Scheduler();
$names     = ['alpha', 'beta', 'gamma'];

foreach ($names as $name) {
    $scheduler->add($name, static function () use ($name): void {
        echo sprintf("%-8s start\n", $name);
        Fiber::suspend("$name waiting");
        echo sprintf("%-8s end\n", $name);
    });
}

$started = hrtime(true);
foreach ($scheduler->run() as $line) {
    echo $line, "\n";
}
printf("three suspending tasks in %.2f ms\n", (hrtime(true) - $started) / 1e6);

// Limitations that decide whether a Fiber is worth anything in your code:
//  - A fiber cannot be suspended from inside a blocking internal call.
//    sleep(), a synchronous cURL call, file_get_contents() on a socket and
//    most PDO calls will block the whole request, not just that fiber.
//  - A Fiber is not a thread: it buys concurrency, never parallelism, and it
//    cannot be used from pcntl_fork()-created processes in any useful way.
//  - A fiber that is never resumed is a leak with an unusual name. Always
//    resume or throw it away.
//  - To gain anything from a fiber, every dependency on the path must be able
//    to yield: ext-curl does not, so the realistic use is a library with an
//    async interface such as an event loop or a non-blocking stream.

Applies to: Fibers 8.1 and later; pcntl POSIX only, CLI only. Requirements: none for Fibers beyond the version; pcntl_fork requires ext-pcntl. Caveat: PHP has no global interpreter lock in the CPython sense because core PHP has no userland threads. The equivalent constraint is that the vast majority of extensions are not thread-safe, which is the reason parallel and every other threaded approach sit at the extension layer rather than the language layer. Any threaded extension invoked from several threads can corrupt interpreter state; a crash that appears only under load and only in a worker is the usual symptom.

The pragmatic rule for concurrency in PHP: if a request spends more than a few tens of milliseconds waiting on a third party, that wait does not belong in the request. Return 202 Accepted, enqueue a job, and let a supervised worker (12.6) do the work with retries and backoff. This removes the wait from the user-visible latency, removes the thundering herd from the third party, and makes the work observable and replayable. It also converts a synchronous failure into a retryable one, which is almost always the behaviour you wanted.

<?php

declare(strict_types=1);

/**
 * ch10-cache-layers.php
 *
 * Requirements: ext-redis (or ext-memcached; the interface below is the same
 * shape either way). Run with: php ch10-cache-layers.php
 *
 * The interesting part is invalidateTag(), not remember(). A cache is only as
 * correct as the event that removes its entry, and the event is where the
 * races are.
 */

final class TaggedCache
{
    public function __construct(
        private readonly Redis $redis,
        private readonly string $prefix = 'app:',
    ) {}

    public function remember(string $key, int $ttl, callable $producer): mixed
    {
        $full = $this->prefix . $key;
        $hit  = $this->redis->get($full);

        if ($hit !== false) {
            return json_decode($hit, true, 512, JSON_THROW_ON_ERROR);
        }

        // Stampede protection. The lock is short, and a waiter re-reads the
        // key after every wait: a bare "sleep then compute" merely moves the
        // stampede to the lock's own expiry.
        $lock = $full . ':lock';

        if ($this->redis->set($lock, '1', ['NX', 'EX' => 5])) {
            try {
                $value = $producer();
                $this->redis->setex($full, $ttl, json_encode($value, JSON_THROW_ON_ERROR));

                return $value;
            } finally {
                $this->redis->del($lock);
            }
        }

        for ($i = 0; $i < 50; $i++) {
            usleep(20000);
            $hit = $this->redis->get($full);
            if ($hit !== false) {
                return json_decode($hit, true, 512, JSON_THROW_ON_ERROR);
            }
        }

        // The holder is slower than the whole wait window. Serve uncached
        // rather than failing the request: a stale-or-slow cache is a
        // performance problem, a 500 is an availability one.
        return $producer();
    }

    // Tag invalidation: the index write and the member delete are NOT atomic, so
    // a concurrent reader can repopulate a key that this call is about to
    // delete. Two mitigations are required, not optional: a short TTL as the
    // backstop, and a version token checked on read.
    public function invalidateTag(string $tag): int
    {
        $index   = $this->prefix . 'tag:' . $tag;
        $members = $this->redis->smembers($index);

        if ($members === []) {
            return 0;
        }

        // Remove the index first, so a concurrent tag() cannot re-add a key to a
        // set that is about to be deleted wholesale.
        $this->redis->del($index);
        $deleted = $this->redis->del(...$members);

        // Bump the generation so a key written during the window is known stale
        // on its next read even if it still exists.
        $this->redis->incr($this->prefix . 'gen:' . $tag);

        return $deleted;
    }

    public function tag(string $key, string $tag, int $ttl, mixed $value): void
    {
        $full = $this->prefix . $key;

        $this->redis->setex($full, $ttl, json_encode($value, JSON_THROW_ON_ERROR));
        $this->redis->sadd($this->prefix . 'tag:' . $tag, $full);
        $this->redis->expire($this->prefix . 'tag:' . $tag, $ttl);
    }
}

final class UserRepository
{
    public function __construct(private readonly TaggedCache $cache) {}

    public function find(string $id): array
    {
        return $this->cache->remember('user:' . $id, 300, function () use ($id): array {
            // One query, not a lookup per field. The N+1 pattern is documented
            // in 5.6 and in the Enterprise Appendix.
            return ['id' => $id, 'status' => 'active'];
        });
    }

    public function rename(string $id, string $name): void
    {
        // 1. Commit the write on the PRIMARY.
        // 2. Invalidate on the same connection or after the same commit. Invalidation
        //    on a replica can run before replication has applied the write, and a
        //    reader then repopulates the pre-write value.
        $this->cache->invalidateTag('user');
    }
}

11.1 Why static analysis carries more weight in PHP

In a statically typed language the compiler proves a large class of defect absent, and a test suite only has to cover behaviour. PHP hands that class back to you: the compiler proves almost nothing, and a test suite that covers the happy path will not find a wrong return type on a branch nobody exercised.

The dynamic surface is wide and each item defeats a different kind of checking:

  • Superglobals are untyped array, and a value read from one is mixed for the rest of the request. See 7.1.
  • mixed propagates silently through an unannotated parameter, and every arithmetic operation on it is legal until the moment it is not.
  • Everything arrives from a request, a database row or a JSON document as a string, and a type error is the first thing that notices — at runtime, in production, on the one path that was not tested. See 6.6.
  • call_user_func, a variable function name and an invokable object all erase the signature, so a call cannot be resolved at compile time.
  • __call, __get and __callStatic make any method or property access syntactically valid. A method that does not exist is only a failure when it is called.
  • Reflection bypasses visibility entirely, and the analyser cannot follow a name computed at runtime.
  • Docblocks are the only place a container’s element type can be stated at all, and the engine does not read them. See 3.6 and 11.4.

PHPStan closes most of that surface by inferring types through the whole call graph, from annotations, from reflection-visible signatures, and from the shape of the values that actually flow. The result is that a level-8 codebase on PHP 8.4 or 8.5 has most of the guarantees a statically typed language provides, minus the compiler’s speed, which is irrelevant because the analysis is not run per request.

function baseline_size(): int
{
    $file = __DIR__ . '/phpstan-baseline.neon';

    if (!is_file($file)) {
        return 0;
    }

    // Each entry is a "- message: ..." line inside a parameters/ignoreErrors
    // block. Counting message lines is exact and needs no parser.
    $count = preg_match_all('/^\s*-\s+message:/m', (string) file_get_contents($file));

    return $count === false ? 0 : $count;
}

Caveat: a baseline is a suppression list that nobody reads. Every entry is technical debt with no expiry, and reportUnmatchedIgnoredErrors does not help, because a baseline entry that matches a different error at the same location still counts as matched. Two practices keep a baseline honest: enforce the ratchet above, and put a comment on the one hand-written suppression that says why. If the baseline has no budget, the team will raise the level only after the debt has become unpayable.

bleedingEdge

PHPStan ships a large test suite and a set of unreleased behaviours behind bleedingEdge: true in parameters. Enabling it changes inference, adds new rules and, on a mature codebase, produces a diff comparable to a two-level jump. Treat it as a version upgrade of the analyser: do it on its own branch, with the level unchanged, and triage the entire diff in one sitting. Combining it with a level increase makes it impossible to attribute a new finding to a cause, and a finding nobody can attribute is a finding nobody will fix.

It is a type checker with an unusually good type system. Everything outside types remains the territory of tests, migrations, review and monitoring.

Enforcing declare(strict_types=1)

The declaration is per file, so it is a per-file opt-in, which makes it a migration rather than a switch. Its effect is at the boundary it appears on, and the boundary that governs is the calling file: a strict callee called from a non-strict caller still coerces, and a non-strict callee called from a strict caller does not. See 1.4.

  • Enable it in every new file from day one. The declare_strict_types fixer above does this automatically, and phpstan at level 6 will then report any untyped boundary in it.
  • For an existing codebase, enable it directory by directory and let the test suite find the boundaries. Every new TypeError is either a genuine defect at a boundary that relied on coercion, or a signature that is wrong.
  • Never enable it in a file in the same commit as a behavioural change. The two failures are indistinguishable at the call site and only one of them is a code review item.
  • It does not apply to an internal function called from a file without the declaration, and it does not make an untyped mixed safe. It removes silent coercion, nothing more.

PHPMD and mess detection

PHPMD ships six rulesets — cleancode, codesize, controversial, design, naming and unusedcode — and its value is concentrated in a few rules: ElseExpression, StaticAccess, BooleanArgumentFlag, TooManyArguments, TooManyMethods, CouplingBetweenObjects, LongVariable and ShortVariable. Most of the rest is noise that a team will suppress file by file. Configure a small rule set you have agreed to obey, gate on that, and report the remainder. A smell detector that fails every build trains the team to add a @SuppressWarnings annotation instead of fixing anything, which is strictly worse than not running it.

11.4 Docblock generics as the analyser contract

PHP has no native generics. list<T>, array<K, V>, class-string<T>, int<0, 100> and non-empty-string are not language features; they are a contract read by PHPStan and Psalm and ignored entirely by the engine. Section 3.6 introduced the syntax. This is what it is for.

The contract is worth writing precisely because the engine cannot check it. A function declared function all(): array communicates nothing; declared function all(): list<Invoice>, it becomes a contract the analyser enforces at every call site, and every consumer that assumes something else — a string key, a nullable element, a Money — is a build failure. The cost is one line and the payoff is that the error moves from a production TypeError to a pull request.

<?php

declare(strict_types=1);

namespace App\Invoice;

/**
 * @template T of Invoice
 */
interface Repository
{
    /** @return T|null */
    public function find(string $id): ?Invoice;

    /**
     * * @return non-empty-list<T>
     * */
    public function all(): array;

    /**
     * * @param  T $invoice
     * * @return T
     * */
    public function save(Invoice $invoice): object;
}

/**
 * The concrete repository supplies the type argument, and every consumer
 * inherits it. Without the @implements line the analyser treats all()
 * as a bare list and the whole chain downstream is untyped.
 *
 * @implements Repository<Invoice>
 */
final class PdoRepository implements Repository
{
    public function __construct(private readonly \PDO $pdo) {}

    public function find(string $id): ?Invoice
    {
        $stmt = $this->pdo->prepare('SELECT id, total_minor, currency FROM invoices WHERE id = :id');
        $stmt->execute([':id' => $id]);
        $row = $stmt->fetch(\PDO::FETCH_ASSOC);

        return $row === false ? null : Invoice::fromRow($row);
    }

    public function all(): array
    {
        $stmt = $this->pdo->query('SELECT id, total_minor, currency FROM invoices ORDER BY id', \PDO::FETCH_ASSOC);
        $out  = [];
        while (($row = $stmt->fetch()) !== false) {
            $out[] = Invoice::fromRow($row);
        }

        return $out;
    }

    public function save(Invoice $invoice): Invoice
    {
        // A prepared statement, parameterised. See 5.2 and 5.3.
        $stmt = $this->pdo->prepare(
            'INSERT INTO invoices (id, total_minor, currency) VALUES (:id, :total, :currency)'
        );
        $stmt->execute([
            ':id'       => $invoice->id,
            ':total'    => $invoice->total->minorUnits,
            ':currency' => $invoice->total->currency->value(),
        ]);

        return $invoice;
    }
}

final class Invoice
{
    public function __construct(
        public readonly string $id,
        public readonly Money $total,
    ) {}

    public static function fromRow(array $row): self
    {
        return new self($row['id'], new Money((int) $row['total_minor'], $row['currency']));
    }
}

Caveat: a docblock type is a promise, not a check. The engine will not stop a caller passing a stdClass into a parameter documented as Invoice; it will produce a TypeError at the first method call inside. The promise is enforced by the analyser on every file in the project and by review at the boundary where the value enters the system — which is why a repository constructor should take a typed input object from a single hydrator rather than a raw array from twenty places. See 6.6 for the round-trip failure modes that produce the wrong shape in the first place.

11.5 Mutation testing

Line coverage answers a question nobody asked: which lines executed. A line that executed and asserted nothing contributes nothing to confidence while adding to the number, which is why a high coverage figure is routinely consistent with an untested suite. Mutation testing asks the question that matters: if the code were wrong, would the suite notice?

A mutation tool makes small semantic changes to the source — > becomes >=, + becomes -, a return value is negated, a method call is removed, a condition is inverted, a literal is replaced with a boundary value — then runs the suite. A mutant that no test fails is a surviving mutant, and each one is a specific, located claim that a test is asserting less than it appears to.

// One assertion closes every mutant in the class except the ones that
// happen to produce the same number.

final class DiscountTest extends PHPUnit\Framework\TestCase
{
    public function test_it_waives_the_fee_above_a_threshold(): void
    {
        $subject = new App\Pricing\Discount(2500);

        self::assertSame(0, $subject->apply(3000));
        self::assertSame(500, $subject->apply(2999));   // the boundary, which is the mutation
        self::assertSame(2500, $subject->apply(2500));  // and the no-op case
    }
}

A boundary assertion is almost always the assertion that kills a comparison mutant. > versus >=, < versus <=, and === versus == are all distinguished by exactly one value, and that value is the one an example-based suite omits.

Reading the result: msi is the mutation score index, the percentage of generated mutants killed; coveredMsi is the same restricted to mutants on covered lines. Require the covered score, not the total. A 100% covered MSI with a low total MSI means the uncovered code is untested, which you already knew; a high total MSI with a low covered MSI means your covered code is weakly asserted, which is the finding that matters.

When a mutant survives, read the diff before writing anything. Roughly a fifth of survivors are equivalent mutants — changes that are not observable given the types involved, such as replacing === with == between two distinct literal types, or reordering two independent assignments. Mark those with @infection-ignore-all and a one-line reason so the next reader does not re-investigate it. The rest are real gaps, and the fix is one assertion.

Caveat: mutation testing multiplies suite runtime by the number of generated mutants, which is commonly a factor of twenty to a hundred. Running it on every commit makes the pipeline unusable and the suite ignored. Run it nightly on a schedule, and in a pull request only for the files the diff touches. --threads and --filter both exist for exactly this split, and Infection’s Stryker report format makes a nightly result reviewable as a coverage delta rather than a wall of text.

12.1 Configuration and secrets

The third factor of the twelve-factor methodology is that configuration — everything that varies between deploys — belongs in the environment, and that means the environment and nothing else. The corollary is the rule worth stating at the top of this section: configuration varies per environment, code does not. A branch on the environment inside application code is a defect, because it means the artefact that was tested is not the artefact that runs.

<?php

declare(strict_types=1);

namespace App\Config;

/**
 * Configuration is read once, at the edge, into an immutable value object.
 * Application code never calls getenv() and never receives a string where a
 * typed value is required, so a missing or malformed variable is a startup
 * failure rather than a TypeError on the first checkout at 3 a.m.
 */
final class readonly class Config
{
    private function __construct(
        public string $env,
        public bool $debug,
        public string $dsn,
        public string $redisDsn,
        public int $httpTimeoutMs,
        public string $logLevel,
    ) {}

    public static function fromEnvironment(): self
    {
        return new self(
            env: self::string('APP_ENV', 'production'),
            debug: self::bool('APP_DEBUG', false),
            dsn: self::string('DATABASE_URL'),          // required
            redisDsn: self::string('REDIS_URL', 'redis://127.0.0.1:6379'),
            httpTimeoutMs: self::int('HTTP_TIMEOUT_MS', 2000),
            logLevel: self::string('LOG_LEVEL', 'info'),
        );
    }

    /** getenv() returns false when the variable is unset, so a bare
    //  getenv('X') passed to a string parameter is a TypeError, not a
    //  configuration error. That is the whole reason this class exists.
    private static function string(string $key, ?string $default = null): string
    {
        $value = getenv($key);

        if ($value === false || $value === '') {
            if ($default !== null) {
                return $default;
            }

            throw new RuntimeException(sprintf('required environment variable %s is not set', $key));
        }

        return $value;
    }

    private static function bool(string $key, bool $default): bool
    {
        $value = getenv($key);
        if ($value === false) {
            return $default;
        }

        return in_array(strtolower($value), ['1', 'true', 'yes', 'on'], true);
    }

    private static function int(string $key, int $default): int
    {
        $value = getenv($key);
        if ($value === false) {
            return $default;
        }
        if (filter_var($value, FILTER_VALIDATE_INT) === false) {
            throw new RuntimeException(sprintf('%s must be an integer, got %s', $key, var_export($value, true)));
        }

        return (int) $value;
    }
}

12.2 Structured logging with PSR-3 and Monolog

PSR-3 is an interface, not a library: eight levels, a LoggerInterface, and psr/log version 3 adds a void return type to every method and requires PHP 8.0. Any logger can be swapped in, and the value of the abstraction is not the logger but the discipline it makes possible: a record is a level, a message and an arbitrary context array, and a context array is where the searchable facts belong.

<?php

declare(strict_types=1);

namespace App\Log;

use Monolog\Formatter\JsonFormatter;
use Monolog\Handler\FingersCrossedHandler;
use Monolog\Handler\StreamHandler;
use Monolog\Level;
use Monolog\LogRecord;
use Monolog\Logger;
use Monolog\Processor\MemoryUsageProcessor;
use Monolog\Processor\ProcessIdProcessor;
use Monolog\Processor\PsrLogMessageProcessor;
use Monolog\Processor\UidProcessor;
use Monolog\Processor\ProcessorInterface;
use Psr\Log\LoggerInterface;

/**
 * Redaction is not optional. A request body or an exception trace reaches the
 * log sooner or later, and a shared log store is a wider blast radius than the
 * database it was written from.
 */
final class Redactor implements ProcessorInterface
{
    public function __construct(
        private readonly array $keys = ['password', 'token', 'authorization', 'cookie', 'secret', 'card_number', 'cvv'],
    ) {}

    public function __invoke(LogRecord $record): LogRecord
    {
        return $record
            ->with(context: $this->scrub($record->context))
            ->with(extra: $this->scrub($record->extra));
    }

    private function scrub(array $data): array
    {
        foreach ($data as $key => $value) {
            $data[$key] = is_array($value)
                ? $this->scrub($value)
                : (in_array(strtolower((string) $key), $this->keys, true) ? '[redacted]' : $value);
        }

        return $data;
    }
}

/**
 * The container rule: log to stderr and let the runtime collect it. A file
 * written inside a container is lost when the container is replaced, is not
 * rotated by the platform, and needs a sidecar to be read at all.
 */
// ch12-logging.php -- the factory, called from the bootstrapping file.
function buildLogger(string $level = 'info', ?string $path = null): LoggerInterface
{
    // ndjson: one self-contained JSON object per line, which is the format
    // every log collector parses without a grok pattern.
    $format = new JsonFormatter(JsonFormatter::BATCH_MODE_NEWLINES);

    // A VM with systemd: php://stdout, collected by journald. A container:
    // php://stderr, collected by the container runtime. A bare VM with a
    // logrotate policy: RotatingFileHandler, which is the one case where a
    // file handler is the correct answer.
    $stream = $path ?? 'php://stderr';

    // Sink 1: every record at or above the configured level, immediately.
    $live = new StreamHandler($stream, Level::fromName($level), true, null, true);
    $live->setFormatter($format);

    // Sink 2: buffered at Debug, flushed only if the request errors. This is
    // how you get the whole request's context onto the failure without
    // paying for it on the 99.9% of requests that succeed.
    $deferred = new StreamHandler($stream, Level::Debug, true, null, true);
    $deferred->setFormatter($format);
    $onError = new FingersCrossedHandler($deferred, Level::Error, 0, true, true);

    $logger = new Logger('billing');

    // pushHandler() prepends, so the deferred handler is consulted first
    // and the live sink is the fallback.
    $logger->pushHandler($live);
    $logger->pushHandler($onError);

    // PsrLogMessageProcessor interpolates {placeholders} from the context and
    // then empties it, so the structured fields survive as real fields.
    $logger->pushProcessor(new PsrLogMessageProcessor());
    $logger->pushProcessor(new ProcessIdProcessor());      // essential: many workers
    $logger->pushProcessor(new MemoryUsageProcessor(true, true));
    $logger->pushProcessor(new UidProcessor());
    $logger->pushProcessor(new WebProcessor());
    $logger->pushProcessor(new Redactor());

    return $logger;
}

$logger->info('invoice.finalised', [

A record at error or above is written twice: once by the live sink, which is what you alert on, and once at the head of the flushed block, which carries the request’s preceding records as context. If you would rather have exactly one line, push only the FingersCrossedHandler and accept that successful requests produce no output at all.

  • Propagate a request_id through the context of every record, generate it in the outermost middleware, and pass it into the queue payload so the worker’s records join the same trace. Without it, a log aggregator cannot reconstruct a request that crossed a process boundary.
  • Record the duration of every external boundary in milliseconds, with a stable message name. That single discipline localises most production incidents without a profiler (10.4).
  • Build the logger once. Constructing one per call allocates a handler stack and a processor chain on every invocation.
  • In a hot loop, guard with $logger->isHandling(LogLevel::DEBUG) before assembling a large context array. The handler may be a NullHandler, but the array is still built.

<?php

declare(strict_types=1);

/**
 * ch12-error-handler.php
 * Requirements: psr/log. Everything else is core.
 * Applies to: a PSR-15 application under PHP-FPM. See 7.2 and 7.4.
 */

final class HttpProblem extends RuntimeException
{
    public function __construct(
        string $message,
        private readonly array $errors = [],
        private readonly int $status = 422,
    ) {
        parent::__construct($message);
    }

    public function status(): int { return $this->status; }
    public function errors(): array { return $this->errors; }
}

final class NotFound extends RuntimeException {}
final class Forbidden extends RuntimeException {}
final class Conflict extends RuntimeException {}

/**
 * A single, explicit registry. A chain of instanceof in the handler is the
 * same mapping, less visible, and impossible to review.
 */
final class ProblemMap
{
    private const MAP = [
        HttpProblem::class => ['validation-failed', 'The request payload is invalid', 422],
        NotFound::class     => ['not-found', 'The requested resource does not exist', 404],
        Forbidden::class    => ['forbidden', 'The caller is not permitted to perform this action', 403],
        Conflict::class     => ['conflict', 'The request conflicts with the current state', 409],
    ];

    /** @return array{0: int, 1: string, 2: string} status, slug, title */
    public static function resolve(Throwable $e): array
    {
        foreach (self::MAP as $class => [$slug, $title, $status]) {
            if ($e instanceof $class) {
                return [$status, $slug, $title];
            }
        }

        // A TypeError from a strict_types boundary (1.4) is a server-side
        // defect, not a client error. It is a 500.
        return [500, 'internal-error', 'The request could not be completed'];
    }
}

function installHandlers(Psr\Log\LoggerInterface $logger, bool $debug): void
{
    set_exception_handler(static function (Throwable $e) use ($logger, $debug): void {
        [$status, $slug, $title] = ProblemMap::resolve($e);
        $requestId = (string) ($_SERVER['HTTP_X_REQUEST_ID'] ?? bin2hex(random_bytes(8)));

        // One error record per failed request, with the full chain in the
        // context. Not one record per frame.
        $logger->error($e->getMessage(), [
            'exception'  => $e::class,
            'origin'     => $e->getFile() . ':' . $e->getLine(),
            'request_id' => $requestId,
            'status'     => $status,
            'uri'        => $_SERVER['REQUEST_URI'] ?? null,
            'trace'      => explode("\n", $e->getTraceAsString()),
        ]);

        // RFC 9457 problem details. The body carries a type, a title, a
        // status and a correlation id. It does not carry internals.
        $body = [
            'type'     => 'https://errors.acme.test/' . $slug,
            'title'    => $title,
            'status'   => $status,
            'instance' => $requestId,
            'detail'   => $debug || $e instanceof HttpProblem
                ? $e->getMessage()
                : 'An internal error occurred. Quote the instance id when reporting this.',
        ];

        if ($e instanceof HttpProblem && $e->errors() !== []) {
            $body['errors'] = $e->errors();
        }

        if (!headers_sent()) {
            http_response_code($status);
            header('content-type: application/problem+json');
            header('x-request-id: ' . $requestId);
        }

        echo json_encode($body, JSON_UNESCAPED_SLASHES | JSON_PRETTY_PRINT), PHP_EOL;
    });

    // set_exception_handler() never sees a fatal error, a memory exhaustion
    // kill or a max_execution_time abort. Only a shutdown function does.
    register_shutdown_function(static function () use ($logger): void {
        $last = error_get_last();

        if ($last === null || !in_array(
            $last['type'],
            [E_ERROR, E_PARSE, E_CORE_ERROR, E_COMPILE_ERROR, E_USER_ERROR],
            true
        )) {
            return;
        }

        $logger->critical($last['message'], [
            'origin' => $last['file'] . ':' . $last['line'],
            'type'   => $last['type'],
        ]);

        if (!headers_sent()) {
            http_response_code(500);
            header('content-type: application/problem+json');
            echo '{"title":"The request was terminated","status":500}', PHP_EOL;
        }
    });
}

Requirements: the global handler must be installed before anything that can throw — which means before the container is built and before the error handler itself, because an exception during bootstrap happens before the application handler exists. Register it in the file the SAPI includes first. Caveat: a memory exhaustion kill and a max_execution_time abort both end the request without running the exception handler, and the shutdown function that does observe them cannot rely on much memory being available. Keep it small, log one line, and do not attempt to render a page from it.

  • On Linux FPM, max_execution_time is enforced by the pool watchdog, not by a tick, so it does not interrupt a blocking syscall. A request stuck in a socket read runs until the upstream times out. Set request_terminate_timeout in the pool and a timeout on every client (12.4).
  • ignore_user_abort defaults to false, which means the engine aborts the request when the client disconnects and the worker is freed. If you do work after the response, set it deliberately, because the default will kill the process mid-cleanup.
  • assert() is compiled out entirely when zend.assertions=-1, which is the production default. Never use assert() for a control-flow decision; throw.
  • A 4xx storm is a client or an attack, not an application fault. Count it, rate-limit it, and do not page on it. A 5xx storm is an application fault and is the only one that should page.

#!/usr/bin/env bash
# ch12-release.sh -- zero-downtime release for a PHP-FPM deployment.
#
# Requirements: bash 4+, GNU coreutils, a FPM master process, a shared
# releases directory, and write access to the OPcache file cache directory.
#
# Invoked as: ch12-release.sh <release-id>   with APP_ROOT already exported.

set -Eeuo pipefail

readonly RELEASE_ID="${1:?usage: ch12-release.sh <release-id>}"
readonly APP_ROOT="${APP_ROOT:-/srv/app}"
readonly RELEASES="$APP_ROOT/releases"
readonly CURRENT="$APP_ROOT/current"
readonly SHARED="$APP_ROOT/shared"
readonly FPM_MASTER_PID="${FPM_MASTER_PID:-/run/php-fpm.pid}"

readonly release_dir="$RELEASES/$RELEASE_ID"
readonly previous="$(readlink -f "$CURRENT" 2>/dev/null || true)"

log() { printf '%s [release] %s\n' "$(date -u +%FT%TZ)" "$*" >&2; }

rollback() {
  log "failed; rolling back to $previous"
  [[ -n "$previous" && -d "$previous" ]] && ln -sfn "$previous" "$CURRENT"
  kill -USR2 "$(cat "$FPM_MASTER_PID")" 2>/dev/null || true
  exit 1
}
trap rollback ERR

# 1. Materialise the release. Never build inside the directory that is live.
mkdir -p "$release_dir" "$SHARED/log" "$SHARED/storage"
cp -a "$APP_ROOT/artifacts/$RELEASE_ID/." "$release_dir/"

# 2. Production dependency install. The lock file decides the versions,
#    never a fresh resolve. --classmap-authoritative removes the PSR-4
#    filesystem fallback, which is what makes validate_timestamps=0 safe:
#    a file that is not in the classmap cannot be silently found.
composer install \
  --working-dir="$release_dir" \
  --no-dev --no-scripts --no-autoloader --no-interaction --prefer-dist

cp "$release_dir/composer.json" "$release_dir/composer.lock" "$release_dir/"
composer dump-autoload \
  --working-dir="$release_dir" \
  --no-dev --optimize --classmap-authoritative

# 3. Writable paths are links into shared/, never copies, so a release
#    directory stays immutable and the cache is not lost on every deploy.
ln -sfn "$SHARED/storage" "$release_dir/storage"
ln -sfn "$SHARED/log" "$release_dir/var/log"

# 4. Bytecode cache. Reset the on-disk tier for every SAPI on the host, then
#    warm it from the new classmap so no request pays for compilation.
rm -rf /var/cache/php/opcache
php -d opcache.enable_cli=1 \
    -d opcache.file_cache=/var/cache/php/opcache \
    -d opcache.file_cache_only=1 \
    "$release_dir/bin/warm-opcache.php"

# 5. Migrations, before the new code receives traffic. Every migration in
#    this release MUST be backward compatible with the release that is
#    currently running. See 5.7 and the expand/contract table in 12.6.
php "$release_dir/bin/console" migrate --no-interaction --allow-no-migration

# 6. Switch. ln -sfn is atomic on the same filesystem: it is a rename, so
#    a concurrent read sees either the old target or the new one, never a
#    missing symlink.
ln -sfn "$release_dir" "$CURRENT"

# 7. Reload the pool. USR2 on the master starts new workers and lets the
#  old ones drain their in-flight requests first. This is also what
#  discards the old opcode cache: the master re-creates the shared
#  segment, so every new worker compiles from the new files.
kill -USR2 "$(cat "$FPM_MASTER_PID")"

# 8. Restart the long-running workers so they pick up the new code. They
#  are separate processes with their own opcode cache and their own
#  in-memory state. A graceful signal, never a kill.
systemctl try-reload-or-restart billing-worker.service || true

# 9. Verify against the release, not against the process: the probe must pass
#  through the same symlink the load balancer resolves.
for attempt in {1..30}; do
  if curl -fsS --max-time 2 http://127.0.0.1/healthz | grep -q "$RELEASE_ID"; then
    log "release $RELEASE_ID is live after ${attempt}s"
    trap - ERR
    # Keep the last five releases for an instant rollback.
    ls -1dt "$RELEASES"/*/ | tail -n +6 | xargs -r rm -rf
    exit 0
  fi
  sleep 1
done

log "release $RELEASE_ID did not become healthy in 30s"
false   # the ERR trap rolls back

Step 7 reloads the pool after the symlink swap rather than before it, and the order is deliberate. A worker that starts before the swap resolves current to the old release and would compile old files into a shared cache that new workers then read. Reloading last means every new worker resolves the new release, and the old workers finish their in-flight requests against code that is still on disk. See 10.3 for why opcache_reset() from a CLI script does not achieve this.

declare(strict_types=1);

/**
 * ch12-health.php -- GET /healthz and GET /readyz
 *
 * Requirements: a load balancer or orchestrator that speaks HTTP probes.
 * Route both paths to this handler from public/index.php. They must be
 * reachable without authentication and without a session.
 */

final class HealthCheck
{
    public function __construct(
        private readonly \PDO $pdo,
        private readonly \Redis $redis,
        private readonly object $config,
        private readonly float $bootedAt,
        private readonly string $releaseId,
    ) {}

    /** Liveness. Depends on nothing outside this process, on purpose. */
    public function liveness(): array
    {
        return [
            'status'   => 'ok',
            'release'  => $this->releaseId,
            'uptime_s' => round(microtime(true) - $this->bootedAt, 1),
            'pid'      => getmypid(),
        ];
    }

    /**
     * Readiness. Every dependency the request path needs, each with a
     * bounded deadline. A probe that can hang is worse than no probe,
     * because the orchestrator's own timeout then fires and the report
     * tells you nothing about which check failed.
     */
    public function readiness(): array
    {
        $checks = [];

        try {
            $this->pdo->query('SELECT 1')->fetchColumn();
            $checks['database'] = 'ok';
        } catch (Throwable $e) {
            $checks['database'] = 'failed';
        }

        try {
            $this->redis->ping();
            $checks['cache'] = 'ok';
        } catch (Throwable $e) {
            $checks['cache'] = 'failed';
        }

        // Validating the configuration object here is what turns a missing
        // environment variable into a red readiness light at deploy
        // time, rather than a 500 on the first customer checkout.
        $checks['configuration'] = isset($this->config->dsn) ? 'ok' : 'failed';

        // Report the names of the failures, never their causes. The probe
        // endpoint is unauthenticated and therefore public.
        $healthy = !in_array('failed', $checks, true);

        return [
            'status' => $healthy ? 'ok' : 'degraded',
            'checks' => $checks,
        ];
    }
}

function emit(array $body, int $status): never
{
    http_response_code($status);
    header('content-type: application/json; charset=utf-8');
    header('cache-control: no-store');
    echo json_encode($body, JSON_UNESCAPED_SLASHES), PHP_EOL;
    exit($status < 400 ? 0 : 1);
}

// ---------- FastCGI graceful completion ----------
//
// The client receives the full response, the connection is closed, and the
// worker then finishes work the user is not waiting for: analytics, a
// cache warm, a non-critical write. Everything after this call is invisible
// to the client, including any header() or setcookie(), which is silently
// discarded. It is the only supported way to respond fast and clean up slowly.

$response = $handler($request);

while (ob_get_level() > 0) {
    ob_end_clean();
}

http_response_code($response->getStatusCode());
foreach ($response->getHeaders() as $name => $value) {
    header($name . ': ' . implode(', ', $value));
}
echo $response->getBody();

    fastcgi_finish_request();   // the client now has every byte it will ever get
}

// Everything below is invisible to the client and must not be able to fail
// the request, which is already complete. Wrap it, and time-box it.
try {
    $analytics->track('page_view', $request->getUri()->getPath());
    $warmer->warmPopularRoutes(max: 3);

    $response->getBody()->close();
} catch (Throwable $e) {
    $logger->warning('post-response cleanup failed', ['error' => $e->getMessage()]);
}

The HealthCheck class and the emit() helper are the whole of the two probe routes in public/index.php. The section beginning at the request completion path belongs to any PSR-15 front controller, and it is shown here only because fastcgi_finish_request() has to sit between the two; $handler, $request, $analytics, $warmer and $logger are the usual pipeline. See 7.2 and 7.4.

Shutdown order in PHP is not the order you wrote it: register_shutdown_function callbacks run last-registered-first, then object destructors, then the SAPI flushes its buffers. A destructor that performs I/O is therefore on the critical path of a response that is already complete, and under FPM with output buffering it can add hundreds of milliseconds to a request the client gave up on. If the cleanup is optional, put it after fastcgi_finish_request(). If it is mandatory, do it before the response and accept the latency.

12.6 Zero-downtime releases, workers and rollback

A release is a sequence of ordered steps, and the order is the design. Two invariants carry the whole chapter: an in-flight request must be served entirely by one version, and a schema change must be readable by both the version running now and the version you might roll back to.

2 BackfillA separate, resumable, idempotent job in batches, outside any request✓ yes✓ yes

The rule is absolute: never contract in the release that stops using the thing, and never contract in a release you might roll back to. Queue workers

A long-running worker differs from a request in three ways that each cause a specific failure: it holds memory that is never released, max_execution_time does not apply to the CLI, and it must be stopped by a signal. A worker that ignores SIGTERM is a worker whose supervisor escalates to SIGKILL mid-transaction, which is the mechanism by which a routine deploy loses work.

<?php

declare(strict_types=1);

namespace App\Worker;

use App\Log\LoggerInterface as AppLogger;

final class class JobTimeout extends RuntimeException {}

/**
 * A database-backed queue worker.
 *
 * Requirements: ext-pcntl (POSIX), and a supervisor unit or a Supervisor
 * program to restart it. Run with: php bin/worker.php
 *
 * Three properties matter and each one has a specific failure behind it:
 *   - it stops on SIGTERM between jobs, not mid-job;
 *   - it is safe to kill, because every job is idempotent;
 *   - it recycles itself, because memory is never returned to the OS.
 */
final class Worker
{
    private bool $shouldStop = false;

    public function __construct(
        private readonly \PDO $pdo,
        private readonly JobHandler $handler,
        private readonly AppLogger $logger,
        private readonly float $bootedAt,
        private readonly int $maxJobs = 1000,
        private readonly int $maxSeconds = 3600,
        private readonly int $jobTimeoutSeconds = 60,
    ) {}

    public function run(): int
    {
        // Without this, a signal is only delivered at the next tick. A
        // while(true) loop with no ticks never reaches one, so SIGTERM is
        // ignored and the supervisor escalates to SIGKILL.
        pcntl_async_signals(true);

        pcntl_signal(SIGTERM, function (): void { $this->shouldStop = true; });
        pcntl_signal(SIGINT,  function (): void { $this->shouldStop = true; });
        pcntl_signal(SIGALRM, function (int $signo): void {
            throw new JobTimeout('job exceeded its deadline');
        });

        $this->logger->info('worker.started', [
            'pid'      => getmypid(),
            'max_jobs' => $this->maxJobs,
            'max_seconds' => $this->maxSeconds,
        ]);

        $processed = 0;
        $failed    = 0;

        while (!$this->shouldStop) {
            // Deliberate recycling. A worker that runs for a month has
            // a month of accumulation in whatever the dependencies did
            // not free. Exiting cleanly is cheaper than an OOM.
            if ($processed >= $this->maxJobs
                || (time() - $this->bootedAt) >= $this->maxSeconds) {
                $this->logger->info('worker.recycling', [
                    'processed' => $processed, 'failed' => $failed,
                ]);
                break;
            }

            $job = $this->claim();

            if ($job === null) {
                usleep(250000);   // idle backoff; the loop still tests $shouldStop
                continue;
            }

            $this->withDeadline($job, function () use ($job, &$processed, &$failed): void {
                try {
                    $this->handler->handle($job);
                    $this->acknowledge($job);
                    $processed++;
                } catch (Throwable $e) {
                    $this->release($job, $e);
                    $failed++;
                }
            });
        }

        $this->logger->info('worker.stopped', [
            'processed' => $processed,
            'failed'    => $failed,
            'clean'     => $this->shouldStop,
        ]);

        // A clean stop exits 0; a crash exits non-zero. The supervisor's
        // restart policy keys on exactly this distinction.
        return $failed === 0 ? 0 : 1;
    }

    private function withDeadline(array $job, callable $fn): void
    {
        // max_execution_time does not apply to the CLI, so a hung syscall
        // hangs the worker forever and the job is never released.
        pcntl_alarm($this->jobTimeoutSeconds);

        try {
            $fn();
        } catch (JobTimeout $e) {
            $this->logger->error('job.timed_out', [
                'job_id'  => $job['id'],
                'type'    => $job['type'],
            ]);
            $this->release($job, $e);
        } finally {
            pcntl_alarm(0);
        }
    }

    /**
     * SKIP LOCKED lets N workers claim from one queue without blocking each
     * other and without a distributed lock. Requires PostgreSQL 9.5+ or
     * MySQL 8.0+; see 5.8.
     *
     * @return array{id: int, type: string, payload: array}|null
     */
    private function claim(): ?array
    {
        $stmt = $this->pdo->query(
            'SELECT id, type, payload FROM jobs'
            . ' WHERE run_at <= :now AND attempts < 5'
            . ' ORDER BY run_at LIMIT 1'
            . ' FOR UPDATE SKIP LOCKED'
        );
        $stmt->execute([':now' => gmdate('Y-m-d H:i:s')]);
        $row = $stmt->fetch(PDO::FETCH_ASSOC);

        if ($row === false) {
            return null;
        }

        return [
            'id'      => (int) $row['id'],
            'type'    => (string) $row['type'],
            'payload' => json_decode((string) $row['payload'], true, 512, JSON_THROW_ON_ERROR),
        ];
    }

    private function acknowledge(array $job): void
    {
        $this->pdo->prepare('DELETE FROM jobs WHERE id = :id')
            ->execute([':id' => $job['id']);
    }

    private function release(array $job, Throwable $e): void
    {
        // Exponential backoff, then a dead-letter table after the attempt cap.
        // The job is returned, not deleted: a worker that dies after the side
        // effect and before this statement will simply run it again, which
        // is why the handler MUST be idempotent. See 11.5.
        $this->pdo->prepare(
            'UPDATE jobs SET attempts = attempts + 1, run_at = :run_at, last_error = :err WHERE id = :id'
        )->execute([
            ':run_at' => gmdate('Y-m-d H:i:s', time() + (2 ** 3)),
            ':err'    => mb_substr($e->getMessage(), 0, 2000),
            ':id'     => $job['id'],
        ]);
    }
}

Idempotency is not optional for a queue, because at-least-once delivery is the only delivery guarantee a queue gives you. The pattern that works: record the message id in a processed_messages table with a unique constraint and insert it in the same transaction as the effect. A second run conflicts on the insert, rolls back, and reports success. INSERT ... ON CONFLICT DO NOTHING, a conditional state transition such as UPDATE ... Backup, rollback and the pre-production checklist

A database backup is not a rollback strategy for an application release. The rollback is the previous release directory plus a schema the previous release can still read, which is why the expand/contract sequence above exists. Take a snapshot immediately before any migration you have not proved reversible — a dropped column is not reversible, and no amount of backup frequency makes that acceptable. The number that matters is the elapsed time from decision to restored service, and the only way to know it is to have rehearsed it. A rollback that has never been executed is not a rollback.

<?php

declare(strict_types=1);

// The single most expensive defect in a PHP application, in both forms.
// Run it with php -d memory_limit=64M to see the first version fail.

// ---------- 1. The N+1: one query per row ----------
final class class NPlusOneReport
{
    public function __construct(private readonly \PDO $pdo) {}

    /**
     * BAD. 1 + N queries: one for the orders, then one per order for its
     * customer. With 200 orders that is 201 round trips, and the cost is
     * the SUM of the latencies, not the latency of the slowest.
     */
    public function broken(int $limit = 200): array
    {
        $orders = $this->pdo
            ->query('SELECT id, customer_id, total_minor FROM orders ORDER BY id LIMIT ' . $limit, \PDO::FETCH_ASSOC)
            ->fetchAll();

        foreach ($orders as &$order) {
            $customer = $this->pdo
                ->prepare('SELECT name FROM customers WHERE id = :id')
                ->execute([':id' => $order['customer_id']])
                ->fetchColumn();
            $order['customer_name'] = $customer;
        }

        return $orders;
    }

    /**
     * GOOD. One query, one round trip, and the join columns are named so a
     * rename in either table surfaces immediately rather than as a null.
     * The LIMIT is interpolated: it is a validated int from the type system,
     * never a request value. Everything from the request is bound. See 5.2.
     */
    public function fixed(int $limit = 200): array
    {
        $limit = max(1, min(1000, $limit));
        $stmt  = $this->pdo->prepare(
            'SELECT o.id, o.total_minor, c.name AS customer_name'
            . ' FROM orders o'
            . ' INNER JOIN customers c ON c.id = o.customer_id'
            . ' WHERE o.id > :cursor'
            . ' ORDER BY o.id LIMIT :limit'
        );
        $stmt->bindValue(':cursor', 0, \PDO::PARAM_INT);
        $stmt->bindValue(':limit', $limit, \PDO::PARAM_INT);
        $stmt->execute();

        // Keyset pagination rather than OFFSET: OFFSET re-scans and discards every
        // skipped row, so page 500 of 10,000 is far more expensive than page 1.
        return $stmt->fetchAll(\PDO::FETCH_ASSOC);
    }
}

<?php

declare(strict_types=1);

/**
 * bin/diagnose.php -- the first thirty seconds of an incident.
 *
 * Requirements: none beyond core extensions. Safe to run on production: it
 * reads configuration and status only, opens no transaction, and writes
 * nothing.
 *
 * Run with: php bin/diagnose.php
 */

require __DIR__ . '/../vendor/autoload.php';

$fail = 0;

function row(string $label, string $value, bool $ok = true): void
{
    global $fail;

    // TTY gets colour; a log collector gets a parseable prefix. No unicode:
    // this line is read by a person and by a grep, in that order.
    printf("%-34s %-4s %s\n", $label, $ok ? 'ok' : 'FAIL', $value);

    if (!$ok) {
        $fail++;
    }
}

// ---------- runtime ----------
row('php.version', PHP_VERSION);
row('php.sapi', PHP_SAPI);
row('php.zend_engine', zend_version());
row('php.memory_limit', ini_get('memory_limit'));
row('php.memory_peak', mb(memory_get_peak_usage(true)));
row('php.max_execution_time', ini_get('max_execution_time')));
row('php.display_errors', ini_get('display_errors'), ini_get('display_errors') === '0');
row('php.error_log', ini_get('error_log') ?: '(SAPI default)');

// ---------- extensions: the allowlist and the forbidden ----------
$forbidden = array_intersect(['xdebug', 'xhprof', 'tideways', 'blackfire'], get_loaded_extensions());
row('ext.profiling_agents', $forbidden === [] ? 'none' : implode(', ', $forbidden), $forbidden === []);

// ---------- opcache: the single most common production difference ----------
if (extension_loaded('Zend OPcache')) {
    $status = opcache_get_status(false) ?: [];
    row('opcache.enabled', ini_get('opcache.enable'), ini_get('opcache.enable') === '1');
    row('opcache.validate_timestamps', ini_get('opcache.validate_timestamps'));
    row('opcache.memory_consumption', ini_get('opcache.memory_consumption'));
    row('opcache.cached_scripts', (string) ($status['opcache_statistics']['num_cached_scripts'] ?? 0));
    row('opcache.jit_buffer_size', ini_get('opcache.jit_buffer_size')));
} else {
    row('opcache.enabled', 'extension not loaded', false);
}

// ---------- realpath cache ----------
row('realpath_cache_size', ini_get('realpath_cache_size')));
row('realpath_cache_ttl', ini_get('realpath_cache_ttl')));

// ---------- autoloading: classmap authoritative means no file fallback ----------
$composer = __DIR__ . '/../vendor/composer/autoload_classmap.php';
if (is_file($composer)) {
    $map = require $composer;
    row('autoload.classmap_entries', (string) count($map));
    // authoritative = true means the PSR-4 filesystem fallback is
    // disabled, so a class absent from the map is simply not found. A
    // false here is a warning, not a failure, for a development build.
    $authoritative = str_contains(
        (string) @file_get_contents('/vendor/composer/autoload_static.php'),
        "'classMapAuthoritative' => true"
    );

    row('autoload.classmap_authoritative', $authoritative ? 'true' : 'false (PSR-4 fallback active)', true);
}

// ---------- dependencies ----------
if (class_exists(Composer\Autoload\ClassLoader)) {
    try {
        $installed = json_decode((string) file_get_contents('/vendor/composer/installed.json'), true, 512, JSON_THROW_ON_ERROR);
        row('composer.installed_packages', (string) count($installed['packages'] ?? []));
        $names = array_column($installed['packages'] ?? [], 'name');
        row('composer.dev_packages_present', (string) count(array_intersect($names, ['phpunit/phpunit', 'phpstan/phpstan'])), !array_intersect($names, ['phpunit/phpunit']));
    } catch (Throwable $e) {
        row('composer.installed_json', $e->getMessage(), false);
    }
}

// ---------- services: reachability only, no credentials in the output ----------
if (extension_loaded('pdo_pgsql')) {
    try {
        $started = hrtime(true);
        new PDO(getenv('DATABASE_URL') ?: 'pgsql:host=127.0.0.1;dbname=postgres', null, null, [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION, PDO::ATTR_TIMEOUT => 3]);
        row('database.reachable', sprintf('yes (%.1f ms)', (hrtime(true) - $started) / 1e6));
    } catch (Throwable $e) {
        row('database.reachable', 'no', false);
    }
}

if (extension_loaded('redis')) {
    try {
        $redis = new Redis();
        $started = hrtime(true);
        $redis->connect(getenv('REDIS_HOST') ?: '127.0.0.1', (int) (getenv('REDIS_PORT') ?: 6379), 1.5);
        $redis->ping();
        row('redis.reachable', sprintf('yes (%.1f ms)', (hrtime(true) - $started) / 1e6));

        $stats = $redis->info();
        $hits   = (int) ($stats['keyspace_hits'] ?? 0);
        $misses = (int) ($stats['keyspace_misses'] ?? 0);
        $ratio  = ($hits + $misses) > 0 ? $hits / ($hits + $misses) * 100 : 0;
        row('redis.hit_rate_percent', sprintf('%.1f%%', $ratio), $ratio >= 50.0,);
    } catch (Throwable $e) {
        row('redis.reachable', 'no', false);
    }
}

// ---------- process ----------
row('process.pid', (string) getmypid());
row('process.rss_peak', mb(max(0, (int) (getrusage()['ru_maxrss'] ?? 0) * 1024)));
row('process.load_average', (string) sys_getloadavg()[0]);
row('release.identifier', getenv('RELEASE_ID') ?: '(not set)');

printf("\n%d check(s) failed.\n", $fail);
exit($fail === 0 ? 0 : 1);

function mb(int $bytes): string
{
    return sprintf('%.1f MiB', $bytes / 1048576);
}
