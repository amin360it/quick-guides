How this guide is organised

This guide covers web app development from static pages to full-stack applications. Every chapter follows the same rhythm: topic description, prose explanation, two code examples, and a callout flagging the most common mistake.

Structure of every section

Each h3 section is self-contained: intro, walkthrough, two examples, and a callout. Chapters 1–2 cover static vs dynamic. Chapters 3–5 go deep on APIs, databases, and auth. The remaining chapters cover deployment, performance, testing, and scaling.

The mindset: full stack means end to end

A full-stack developer can design a database schema, write a REST API, build a UI, and deploy the whole thing. You do not need to be an expert in every layer, but you should know how they fit together.

Follow the request lifecycle

User clicks → browser sends request → server runs code → server queries database → server returns HTML or JSON → browser renders. Every chapter in this guide maps to one step in that chain.

Tools you will use throughout

VS Code, Node.js, Python, .NET, and a local server are all you need. Git for version control, npm or pip for packages, and a browser with DevTools for debugging.

Start with the stack you already know. The architecture patterns — API design, database schema, deployment — are the same whether you use PHP, Node, or ASP.NET.

1.1 HTML, CSS & assets

A static site is HTML, CSS, and JavaScript served directly from files. No server-side processing happens per request.

A minimal static page

<!DOCTYPE html>
<html>
<head>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>Hello world</h1>
  <script src="app.js"></script>
</body>
</html>

1.2 Build steps & output

A static site can be handcrafted or generated by tools like Astro, Hugo, or Next.js in static mode. The output is always a folder of HTML, CSS, JS, and assets.

A typical build output

dist/
  index.html
  about.html
  assets/
    style.css
    logo.png
    script.js

1.3 Hosting and CDNs

Static sites can be hosted on GitHub Pages, Netlify, Vercel, or any S3-compatible store. A CDN edge cache ensures fast delivery worldwide.

2.1 APIs, databases & auth

A dynamic app serves data from a database via a REST or GraphQL API. Authentication protects write operations and private routes.

A minimal REST endpoint

app.get('/api/users', async (req, res) => {
  const rows = await db.query('SELECT id, name FROM users');
  res.json(rows);
});

app.post('/api/users', async (req, res) => {
  await db.query('INSERT INTO users (name) VALUES ($1)', [req.body.name]);
  res.status(201).send();
});

2.2 Server rendering & SPA

Server-side rendering sends a full HTML page to the browser. A SPA sends a shell and fetches data via AJAX. Both patterns are valid; the choice depends on the use case.

2.3 Deployment & CI

Modern deployment is automated: push code, run tests, build, and ship. A CI pipeline that fails on a red test saves hours of debugging.
