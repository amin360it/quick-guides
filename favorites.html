1.1 What appears here

Every guide page and every individual section you starred shows up in the list below, saved by this page from this browser.

The star lives in the header, to the right of the colour-mode control. Press it on any guide and the whole page is saved; press it while you are reading inside a chapter and the exact section is saved instead, anchor and all. Each row in the list shows the title you saved, whether it was a page or a section, and the date. The title is a normal link: one click returns you to the spot, with your theme, colour mode and scroll progress restored by the shared shell.

Favorites are stored per browser profile, not per account. There is no sign-in anywhere in this library, and nothing is sent over the network — the star, the list and the storage all run in this one page.

1.2 Removing a favorite

Every row carries its own Remove button; nothing needs a confirm dialog.

Press Remove and the row disappears immediately, the count above it updates, and the entry is gone from storage. If the entry pointed at a section, the star on that guide un-fills the next time you open the same spot — the star always reflects what is actually stored, so there is no separate "unsave" mode to learn. Removing one entry never touches the others, and there is no undo, which is the right trade for a list this cheap to rebuild: star the page again and it is back.

1.3 Clearing everything

The Clear all button empties the whole list in one press.

Use it when the list has grown past what you actually revisit, or before handing the machine to someone else. It writes an empty list back to storage in one step; individual Remove buttons become redundant the moment it is pressed, so the button disables itself when there is nothing left to clear.

Clearing is instant and has no confirmation step. If you only meant to drop one entry, use that row's Remove button instead.

2.1 Stored in this browser

One key in localStorage holds the whole list: amin360it-favs.

The value is a small JSON array of objects, each carrying the link, its title, the page it belongs to and the date it was saved. The shell reads it when a starred page loads and when this list renders, and writes it back the moment you toggle, remove or clear. Nothing else in the library touches the key, so browser extensions or other pages on the same origin cannot confuse the list without writing that exact key.

// Open the console on any page of this library:
var saved = JSON.parse(localStorage.getItem('amin360it-favs'));

saved.length        // how many favorites you have
saved[0].href       // "flutter.html#ch1" or "python.html"
saved[0].title      // the heading or guide title you saved

localStorage is per origin and per browser profile. Chrome and Firefox each keep their own list, and private windows usually drop theirs when the session ends.

2.2 Saving a section, not just a page

The star targets the heading you are currently reading, not blindly the top of the file.

When you press it, the shell walks the page's headings and picks the last one whose top edge has passed under the header — the section your eyes are in. That heading's anchor becomes part of the saved link, so reopening lands mid-guide with the chapter in view instead of at the band. If you are still at the very top, before the first heading has slid under the header, the star saves the page itself. The rule is deliberately visual rather than based on scroll percentages: it matches what you are reading at any viewport size, on any guide, without knowing anything about the page's length.

2.3 Works offline

The feature makes zero network requests — star, list, remove and restore are all local.

That is the whole design: favorites are a browser feature, not a service. The same holds for every other control in this library — the theme, the colour modes, the sidebar search and the progress markers all read and write localStorage on your machine, and the pages themselves are plain files with no backend. Open the folder on a laptop with the Wi-Fi off and everything on this page behaves exactly as it does now.

Favorites are only as durable as the browser data behind them. "Clear browsing data" or clearing site storage for this origin deletes the list with no way to recover it — export the JSON from the console first if the list matters.
