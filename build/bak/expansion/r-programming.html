0.1 Why R, and what it is for

R is a language designed for statistics and data analysis, and it is the tool of choice for data science, machine learning, and academic research.

1.1 Vectors: the most important data structure in R

1.1 Vectors: the most important data structure in R

In R every object is a vector, and almost every surprising behaviour follows from that one fact: there is no scalar type, arithmetic applies element-wise, and a vector's length is whatever the operation produced rather than what you asked for.

The four basic types and the coercion ladder

R has four atomic types: logical, integer, double and character. Composite types are factors, which are integers with a level set attached, and lists, which can hold anything. When a vector contains mixed types, R coerces along a fixed ladder: logical becomes integer, integer becomes double, double becomes character. The ladder is total, so c(TRUE, 1) gives you 1 1 rather than an error, and c(1, "a") gives you two strings rather than a warning.

x  <- c(1, 2, 3)                    # double
i  <- c(1L, 2L, 3L)                # integer
b  <- c(TRUE, FALSE)               # logical
s  <- c("a", "b")                  # character

typeof(x)                          # "double"
c(TRUE, 1)                         # 1 1          (logical -> integer)
c(TRUE, 1.5)                       # 1 1.5        (integer -> double)
c(1, "a")                          # "1" "a"      (double -> character)

# there is no scalar type. A "scalar" is a length-1 vector and
# every operation on it is still a vector operation.
length(42)                         # 1
is.vector(42, "double")            # TRUE

Element-wise arithmetic, and why a loop is usually wrong

Because arithmetic is element-wise and vectors recycle, x * 2 multiplies every element and a loop is almost never the right tool. The one thing to know is recycling: R will repeat a shorter operand to match a longer one, silently, and warns only when the length is not a whole multiple. A length-3 vector added to a length-2 vector produces a length-6 result and no complaint about the one that was probably a mistake.

a <- c(1, 2, 3)
b <- c(10, 20)

a + b          # 11 22 31 12 22 32  <- RECYCLED, and warned about
a * 2          # 2 4 6              <- length-1 recycles cleanly
a + 1          # 2 3 4

# a length-3 against a length-2 is almost always a bug, and R only
# warns. Use rep_len to make the mistake impossible to hide:
rep_len(b, length(a)) + a          # 11 22 31, no ambiguity

Lists are the one heterogenous container

A list holds elements of any type, including other lists, and is R's equivalent of a JSON object. The distinction between [] and [[]] on a list is the single most common source of confusion in the language: single brackets always return a list, double brackets return the element. For a list of exactly length one — which is what a function returning a list usually is — that difference is the difference between a list and the thing inside it.

config <- list(
  host  = "localhost",
  port  = 8080,
  flags = c(TRUE, TRUE, FALSE),
  db    = list(user = "app", name = "prod")
)

class(config)                      # "list"
length(config)                     # 4
config$port                       # 8080      ($ is shorthand for [[]])
config[["port"]]                  # 8080
config[[1]]                       # "localhost"

config["port"]                    # a LIST of length 1, not 8080
class(config["port"])             # "list"  <- the gotcha

config$db$name                    # "prod"    nested access works

Factors, and the trap that has bitten everyone once

A factor stores integers and a separate table of level names, which is efficient for grouping and efficient for forgetting: the levels are alphabetical unless you set them. Sorting a factor sorts by its integer codes, so a factor with default levels sorts as "high low medium" rather than "high low medium" alphabetically — and the plot axis inherits that. It also silently converts character vectors to factors in old data frames, so a postal code with a leading zero arrives as a number.

grade <- factor(c("medium", "low", "high"))
levels(grade)                      # "high" "low" "medium"  (alphabetical)
sort(grade)                        # high low medium  -- already sorted!
as.integer(sort(grade))            # 1 2 3              -- meaningless

# declare the order you mean:
grade <- factor(c("medium", "low", "high"),
                levels = c("low", "medium", "high"),
                ordered = TRUE)
sort(grade)                        # low medium high  <- correct
levels(grade)                      # "low" "medium" "high"

# the leading-zero trap:
zip <- factor(c("02134", "02135"))
nchar(as.character(zip[1]))        # 5, but as.numeric() gives 2134

The subsetting operator, and its three forms

x[i] selects and always returns a vector, which is why it can change length. x[i, j] on a data frame selects a cell and on a matrix selects a submatrix. Logical indexing filters and changes length; numeric indexing selects by position and also changes length; character indexing on a named vector selects by name. Knowing which one you have is what makes a surprising length change explicable rather than mysterious.

v <- c(alpha = 10, beta = 20, gamma = 30)

v[2]                  # beta 20        numeric: by position
v[c(1, 3)]            # alpha gamma    numeric: several
v[v > 15]           # beta gamma     logical: FILTERED, len 2
v[["beta"]]          # 20             [[ ]] on a vector: by name
v[c("alpha","beta")]  # alpha beta     character: by name

# the surprise, explained:
n <- c(1, 2, 3, 4, 5)
n[n > 3]             # 4 5  <- length 2, and that is correct
# ...using length(n) as an index into another vector after this is
# the classic off-by-N bug, because the length is no longer 5.

Four disciplines: always set levels = on a factor used for ordering or plotting, because the default is alphabetical and both sort and axis inherit it; use [[ when you want the element and [ when you want a list, because on a length-one list the two give different types and the difference surfaces three lines later; check the length after any logical subset, because it is not the length you expect when a filter drops rows; and use rep_len rather than relying on recycling, because recycling a length-2 against a length-3 warns but succeeds, and the resulting six-element vector is not an error anyone will notice.

2.1 ggplot2: the grammar of graphics

ggplot2 is not a function, it is a grammar. A plot is assembled from a dataset, a set of mappings from variables to visual properties, one or more layers that draw something, a scale specification, a theme and a title block — and because the pieces compose with +, the order you write them is irrelevant and a plot can be built up incrementally.

The six pieces and what each controls

ggplot(data, aes(...)) establishes the data and the aesthetic mappings: which column becomes which visual property. A geom_* layer draws something and inherits the mappings. scale_* functions transform or relabel an axis. facet_* splits the plot into a grid of small plots. theme_* controls everything that is not data: fonts, grid lines, background. labs() sets the title and axis labels.

library(ggplot2)

df <- data.frame(
  age    = c(25, 30, 35, 40, 28, 33, 45),
  height = c(165, 175, 180, 170, 162, 172, 185),
  weight = c(60, 78, 85, 72, 55, 74, 92),
  gender = c("F", "M", "M", "F", "F", "M", "M")
)

# the minimal scatter: one mapping, one layer
ggplot(df, aes(x = age, y = height)) +
  geom_point(size = 3) +
  theme_minimal() +
  labs(title = "Height vs Age", x = "Age", y = "Height (cm)")

# adding a colour mapping: one more aesthetic, no new layer
ggplot(df, aes(x = age, y = height, color = gender)) +
  geom_point(size = 3) +
  theme_minimal()

Layers, and the aesthetics each one uses

Every geometry has a different set of aesthetics it understands, and passing an aesthetic a geom does not support is one of the most common errors. geom_point uses x, y, colour, shape, size and alpha. geom_line uses x, y, colour, linetype and group, and requires a group or it draws one line across all the data. geom_bar uses x, y and fill, and defaults to counting rather than plotting a supplied y. geom_histogram uses only x, because it bins y for you.

# a bar chart COUNTS unless you say otherwise
ggplot(df, aes(x = gender)) +
  geom_bar(fill = "steelblue")

# to plot a supplied y you must say stat = "identity"
ggplot(summarise(df, g = gender, m = mean(height)), aes(x = g, y = m)) +
  geom_bar(stat = "identity", fill = "steelblue")

# a line needs a group: one line per gender
ggplot(df, aes(x = age, y = height, color = gender, group = gender)) +
  geom_line() +
  geom_point()
# ...colour alone is NOT enough for geom_line. This is the single
# most common reason a multi-series line chart comes out as a
# zigzag through every point.

Facets: one plot per group, and the difference between the two

facet_wrap arranges panels in a grid that wraps, treating the variable as unordered — useful when you have many levels. facet_grid arranges panels by two factors, one per axis, and shows every combination including empty ones. Both inherit every mapping and every layer, so a faceted plot is the same plot repeated rather than a separate construction. The fixed aspect control is the one that matters when comparing across panels: scales = "free_y" lets each panel scale independently, which stops one outlier from flattening every other panel.

# wrap: one panel per gender, arranged automatically
ggplot(df, aes(x = age, y = height)) +
  geom_point() +
  facet_wrap(~ gender) +
  theme_minimal()

# grid: row and column factors, every combination shown
df$smoker <- ifelse(df$age > 30, "over30", "under30")
ggplot(df, aes(x = age, y = height)) +
  geom_point() +
  facet_grid(gender ~ smoker) +
  theme_minimal()

# free scales: the difference between seeing a trend and not
ggplot(df, aes(x = age, y = weight)) +
  geom_point() +
  facet_wrap(~ gender, scales = "free_y") +
  theme_minimal()

Saving, and the two arguments that matter

ggsave() writes the current plot, and it infers the format from the filename extension — .png, .pdf, .svg. The width and height arguments are in inches and the default is the current device's size, which is why a plot produced in RStudio and one produced by a script come out different sizes. Set both explicitly for anything that will be published or version-controlled, and use bg = "white" for .png because a transparent background renders black in most viewers.

p <- ggplot(df, aes(x = age, y = height, color = gender)) +
  geom_point(size = 3) +
  theme_minimal() +
  labs(title = "Height vs Age", x = "Age", y = "Height (cm)")

# explicit size, white background, print-quality
ggsave("height-vs-age.png", p,
       width = 8, height = 5, dpi = 300, bg = "white")
ggsave("height-vs-age.pdf", p, width = 8, height = 5)   # vector
ggsave("height-vs-age.svg", p, width = 8, height = 5)   # vector

# and the two ways to get the data out for a caption or a report
library(ggplot2)
b <- ggplot_build(p)
b$data[[1]]        # the layer's computed coordinates
ggplot2::layer_data(p, 1)

Three disciplines: give geom_line a group mapping whenever the colour mapping is categorical, because colour alone produces one line through every point in the order they appear; state stat = "identity" on a bar chart when your y is already an aggregate, because the default re-counts and silently replaces your values with ones; and set width, height and bg explicitly in ggsave, because the defaults come from the current device and therefore differ between an IDE and a script.

2.2 Statistics: hypothesis testing, regression, and the four things to check

R has the deepest statistical ecosystem of any language: over 1,000 statistics packages on CRAN, and base R built-ins for the fundamental tests.

The four things you will reach for

Every shortcoming in this area comes from one of two places: the tool being used makes a promise it does not keep, or the surrounding process is not checking that promise at the boundary. Both are the same mistake in different clothes — treating a silent tool as an honest one. Fix the silence first, and the debugging gets much quieter.

Then the four functions, and what each answers. t.test() — is the mean of one or two samples what we expect? lm() — is there a linear relationship between a predictor and an outcome? cor.test() — are two variables related? chisq.test() — is the observed count of categories different from what theory predicts? Then the two things to check on every test's result. The p-value tells you the probability of seeing the data if the null is true, — it does NOT tell you the probability the null is true. And Effect size is the more honest number, — Cohen's d for t-tests, R-squared for regression, and they answer "how much difference does this make?" rather than "is it different?". Then the one discipline. Plot the data first. A statistical test assumes the data has a particular shape — independence, normality, equal variance — and the only way to check those assumptions is to look at a histogram, a scatterplot, and a residual plot.

# t-test: is the mean height different between groups?
group_a <- c(170, 175, 165, 180, 172)
group_b <- c(178, 182, 175, 185, 180)
t.test(group_a, group_b)
# Welch Two Sample t-test
# t = -3.4521, df = 7.8312, p-value = 0.0094

# Linear regression: height ~ age
df <- data.frame(age = 20:30, height = 165:175 + rnorm(11, 0, 2))
model <- lm(height ~ age, data = df)
summary(model)
# Coefficients, R-squared, F-statistic, p-values

# Correlation test
x <- rnorm(100); y <- x + rnorm(100, 0, 0.5)
cor.test(x, y)

# Chi-square test of independence
observed <- matrix(c(50, 30, 20, 40, 60, 10), nrow=2)
chisq.test(observed)

# THE TWO THINGS TO CHECK ON EVERY RESULT.
# 1. p-value is NOT the probability the null is true
#    It IS the probability of seeing data at least this extreme
#    IF the null hypothesis is true. A small p-value means the
#    data is unlikely under the null, NOT that the null is
#    unlikely given the data.

# 2. Effect size matters more than significance
#    p-value depends on sample size: a tiny difference on a huge
#    sample is "significant" but meaningless. Cohen's d, R-squared,
#    and the confidence interval are the honest numbers.

# THE DISCIPLINE: plot before you test
par(mfrow=c(2,2)); plot(model)   # residual vs fitted, normal Q-Q,
                                  # scale-location, residual vs leverage
# These diagnostic plots tell you whether the test's assumptions
# (linearity, normality of residuals, equal variance) are plausible.
